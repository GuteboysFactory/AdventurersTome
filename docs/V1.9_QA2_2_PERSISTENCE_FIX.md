# 1.9.0-qa.2.2 — Foundry persistence fix and interruption handling

Live failure: 20 Folder copies were saved, then the first Actor failed with `Cannot use 'in' operator to search for 'Item' in Actor.…`. Simulated creation in earlier tests accepted raw JSON and missed Foundry's dotted-key expansion.

Identity maps now use an array of `{sourceUuid, targetUuid}` entries; UUIDs are string values, not object keys. This avoids a root Actor mapping colliding with its embedded Item mappings when Foundry expands paths. Readers also support earlier flat object maps and their expanded nested form, including already-created Folder records.

On interruption, the toolkit shows the failed document, saved-copy count and remaining count at the top, emits a persistent error notification, and displays stopped status rather than Ready. A retry discovers saved copies and reuses their identities. No source deletion, automatic rollback or existing-world cleanup is performed. A missing document returned by creation is treated as failure.

Tests reproduce the previous persistence collision, create Actor/Item/Journal identities with dotted-key expansion, and simulate interruption after a Folder followed by a successful retry without duplicate folders. Browser tests additionally cover the error display, notification, and retry. These emulate the persistence boundary; the live destination remains the final check.
