# Adventurer's Tome v1.6.0-qa.16 — Exact Ownership Convergence

**Baseline:** v1.6.0-qa.15  
**Verified Foundry baseline:** V13.351

## Trigger

Live qa.15 diagnostics isolated the remaining permission mismatch to persisted Journal ownership.

For both Baran Dev and Testas Testasson:

- source Actor OBSERVER = true
- linked target Actor OBSERVER = false
- generated Contact Journal OBSERVER = true

A manual Contact Projection sync completed but the same two permission violations remained.

## Root cause

Foundry document updates merge nested `ownership` objects.

Writing only the desired ownership object does not necessarily remove stale per-user ownership keys that are absent from the new desired state.

Example:

Current:

```js
{
  default: 0,
  GM_USER: 3,
  DEV_PLAYER: 3
}
```

Desired:

```js
{
  default: 0,
  GM_USER: 3
}
```

A normal nested ownership update can leave `DEV_PLAYER: 3` behind.

## Fix

qa.16 adds exact ownership convergence for Tome-managed Semantic Contact projections.

The synchronizer now:

1. writes every desired ownership key through flattened `ownership.<key>` paths
2. explicitly removes stale current keys using Foundry's `ownership.-=<key>` deletion syntax
3. compares current vs desired ownership by normalized ownership signature
4. keeps the existing evidence-scoped viewer privacy gate unchanged

Scope is intentionally limited to Tome-managed Semantic Contact projections.

No ordinary Journals, Quests, Sessions, manual World entries, or unrelated Foundry documents are modified by this mechanism.
