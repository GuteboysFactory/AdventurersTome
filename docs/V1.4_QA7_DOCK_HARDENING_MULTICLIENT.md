# Adventurer's Tome v1.4.0-qa.7 — Dock Hardening & Multi-Client QA

**Foundry target:** V13.351  
**Tome QA build:** v1.4.0-qa.7  
**Host policy:** system-independent; any compatible `gbf-gm-dock-host` implementation may be used as a reference host.

## Goal

Harden the GM Dock against stale context, reloads, document deletion, host changes and multi-client use without binding Tome to any specific game system or host version.

## 1. Standalone/system-independent baseline

Test Tome in a world with no compatible external Dock Host.

- [ ] Tome renders its standalone GM Dock for a GM.
- [ ] Player clients see no GM Dock.
- [ ] Current Scene becomes a valid canonical context.
- [ ] Quick Capture to current context works.
- [ ] Private Vault to current context works.
- [ ] Reload preserves per-user Dock position and pinned context when the source still exists.
- [ ] No game-system-specific API is required for any core Dock action.

## 2. Compatible Host v1

With any host advertising:
- `contract === "gbf-gm-dock-host"`
- `version >= 1`
- `registerProvider()`

Verify:
- [ ] Tome enters `hosted-provider` mode.
- [ ] Tome suppresses its standalone Dock.
- [ ] Standard provider menu items work.
- [ ] No v2-only inline body/footer is required.
- [ ] Removing/replacing the host allows Tome to recover on the next refresh/reload.

## 3. Compatible Host v2+

With any compatible host version 2 or newer:

- [ ] Inline Quick Capture is available.
- [ ] Dedicated Open Tome footer is available.
- [ ] Quick Capture draft survives unrelated host/menu refreshes while expanded.
- [ ] Successful save resets/collapses the draft.
- [ ] Host version changes do not alter Tome campaign data ownership.

## 4. Context deletion / stale-pin recovery

For Actor, Item, Journal and Scene contexts:

- [ ] Pin the context.
- [ ] Delete the source document.
- [ ] Tome automatically clears the stale pin.
- [ ] Dock falls back to a valid current Scene/campaign context.
- [ ] A Quick Capture draft targeting the deleted UUID safely falls back to Inbox/current available context.
- [ ] No recurring console errors occur.

Reload with an already-stale pinned UUID:
- [ ] startup heals the stale pin automatically.
- [ ] no broken/blank Dock context remains.

## 5. Quick Capture context consistency

- [ ] Begin writing a Quick Capture on Context A.
- [ ] Trigger an unrelated Dock refresh or open another Foundry sheet.
- [ ] The draft text/type/target is preserved.
- [ ] Saving still writes to the explicitly selected canonical UUID, not silently to the newly active context.
- [ ] If that target is deleted before save, save is blocked safely with a warning.
- [ ] Inbox capture remains available.

## 6. Multi-client/privacy

With one GM and one player client:

- [ ] GM Dock/provider remains GM-only.
- [ ] Player never receives Private Vault content through Dock UI.
- [ ] GM context changes do not create player-side errors.
- [ ] Reveal Queue / Show to Players retains existing permission behavior.
- [ ] No duplicate writes from Quick Capture.

With two GM clients where practical:
- [ ] each client's Dock position/pin remains user-scoped.
- [ ] document changes refresh cleanly on both clients.
- [ ] no render/update loop appears.

## 7. Diagnostics

Run:

```js
game.modules.get("adventurers-tome")?.api?.gmDock?.compatibility?.()
```

Expected shape:

```js
{
  systemId: "...",
  mode: "standalone-fallback" | "hosted-provider",
  hostContract: "" | "gbf-gm-dock-host",
  hostVersion: 0 | 1 | 2 | ...,
  richMenu: true | false
}
```

This is diagnostic only. Tome behavior must remain capability-driven, not system-id-driven.

## 8. Regression

- [ ] Private Vault open/addNote APIs remain available.
- [ ] Reveal Queue unchanged.
- [ ] Next Session / GM Dashboard unchanged.
- [ ] Recent navigation unchanged.
- [ ] canonical UUID identity unchanged.
- [ ] v1.3 source-convergence behavior remains clean.
- [ ] no recurring console errors.

## PASS criteria

qa.7 passes when Tome remains fully functional with no external host, works against generic compatible Host v1/v2+ implementations, heals stale context safely, preserves capture intent across refreshes, and remains GM-private/multi-client safe.
