# Adventurer's Tome v1.6.0-qa.14 — Projection Permission Enforcement

**Baseline:** v1.6.0-qa.13  
**Verified Foundry baseline:** V13.351

## Trigger

Live qa.13 player testing proved that the previous hotfix was incomplete.

Observed as Dev Player:

- Baran Dev was absent from Character → Relations
- Baran Dev still appeared in World → Contacts
- Baran Dev still appeared in Campaign Explorer
- opening the Contact profile exposed name, portrait, relationship, status, location, origin, and the canonical Foundry Actor UUID
- therefore the generated Contact Journal itself remained player-readable

## Root cause

The generated Contact Journal can retain stale or permissive Foundry ownership while downstream Tome views trust the Journal's permission state.

A derived semantic Contact must not remain readable merely because its persisted Journal ownership is stale.

## Fix

qa.14 adds defense-in-depth permission enforcement.

### 1. Central Tome evidence gate

Every Tome surface that uses `canViewInTome()` now applies an additional live check for automatically managed semantic Contact projections.

For a non-GM viewer, an automatic semantic Contact is visible only when all Actor evidence recorded by the projection is currently OBSERVER-readable:

- semantic source Actor
- canonical linked Actor, when present
- recorded permission-source Actors

If a required Actor is missing or unreadable, the Contact is hidden even if the Journal itself still has stale OBSERVER ownership.

### 2. Viewer-scoped Contact Projection API

`contactProjections.list()` applies the same live Actor-evidence rule in addition to Journal readability.

### 3. Ownership refresh on Actor changes

A Foundry `updateActor` now schedules Contact Projection synchronization for the active GM.

This allows managed Contact Journal ownership to tighten after Actor ownership changes rather than waiting for unrelated campaign/discovery changes.

### 4. Technical-link redaction

If a GM deliberately broadens Contact Journal visibility while the canonical linked Actor remains unreadable, the Contact may remain visible by explicit override, but the generated `Foundry Link` UUID fact is removed from the player-facing profile.

The normal Open Actor control already requires the Actor itself to be readable.

## Hard lock

> Automatic semantic projections must be permission-safe twice: persisted document ownership where possible, and live viewer-scoped evidence validation at every Tome read surface.

This prevents stale document permissions from becoming a confidentiality leak.
