# 1.9.0-qa.2.5 — Standard folder reuse and synchronization boundary

The live destination contained three independent World trees: 48 Journals without migration provenance, one empty tree, and 59 Journals with import provenance. The importer cloned source folders while the destination already had a standard Tome hierarchy. Backend projection could also run after Actors/Items arrived but before their imported Journal representations arrived.

Import now reuses the canonical destination hierarchy returned by Tome's folder bootstrap: root, Sessions/Quests/World/Rules and typed World category folders. Matching uses the source hierarchy and semantic flags, not a blanket match of every folder named World. Custom folders, unrelated roots and compendium folders remain independent. Folder aliases are persisted as array entries without replacing existing folder metadata, so retry/reload retains their mappings.

Backend folder projection scheduling is paused and any current projection run is drained before import writes. Source-parity writes are deferred while migration is active. Synchronization resumes once the import writes settle. Concurrent standard-folder bootstrap requests share a pending operation. Managed projection Actor and Folder identifiers are remapped together with UUIDs; imported text/pages are retained.

Existing occupied duplicate trees are not automatically merged or deleted. This is a prevention fix for the next import. Use a new test destination, leave the destination's standard folders in place, and reuse the migration ZIP. After importing, standard folders should be reused rather than additional Tome roots created. The result reports reused folders/copies separately from new documents. Stable 1.8.0 is unchanged.

Automated coverage checks scoped folder matching, custom-folder preservation, source-page preservation, remapped managed markers, retry, pause/resume even on failure, and browser routing/persistence of folder aliases. Browser storage is simulated; a clean live destination remains the final check.
