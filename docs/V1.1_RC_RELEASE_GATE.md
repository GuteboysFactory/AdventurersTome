# Adventurer's Tome v1.1 Release Candidate Gate

## Purpose

This document defines the final release gate between `v1.1.0-rc.1` and stable `v1.1.0`.

The RC is a **feature freeze**. No new authoring features are permitted in the RC line. Only release-blocking regressions, compatibility fixes, packaging fixes, permission/security fixes, or data-safety fixes may change runtime behavior.

## Accepted beta baseline

`v1.1.0-beta.1` passed the complete manual beta regression matrix on 2026-09-03:

- GM Explorer navigation, filtering, expand/collapse and drag/drop
- GM folder create / rename / protected-root / empty-only delete behavior
- GM entry create / rename / open / move / delete behavior
- Journal Page create / rename / reorder / duplicate / move / delete / navigation behavior
- Section Editor delegated authoring with a GM online
- Entry Editor entry-scoped authoring without structure privileges
- normal Player read-only presentation with no authoring controls
- GM Notes / private GM workspace isolation
- persistence after reload and repeated Tome navigation

The RC must preserve that exact behavioral baseline.

## RC smoke test

Before promoting RC to stable, verify the following in the packaged RC build:

1. Install/update from the RC manifest URL, not a development checkout.
2. Open Tome as GM and navigate World -> Quests -> Sessions -> World.
3. In World, select folders and verify the rich catalog filters without rebuilding or destabilizing Explorer.
4. Move one disposable test entry between two folders and back.
5. Open one multi-page entry; verify inline editing/autosave, Page Navigator and Page Manager.
6. Log in as one delegated Section Editor and create one disposable entry through the GM broker.
7. Log in as one ordinary Player and confirm all structural/authoring controls are absent.
8. Confirm GM Notes/private GM workspace are not visible to that Player.
9. Reload Foundry and confirm the disposable Journal/folder/page changes persisted.
10. Check browser console for new repeating Tome errors or render loops.

## Automated release requirements

The release workflow must fail if any of the following is true:

- `module.json` is invalid or has an unexpected module id/version shape.
- manifest/runtime file references are duplicated or missing.
- language JSON is invalid.
- any retired Explorer prototype returns.
- any manifest-listed runtime file is absent from the release ZIP.
- development/release internals are included in the ZIP.
- RC/stable release URLs do not match the manifest version.
- the RC release-gate document is missing from the package.

## Stable promotion rule

Promote `v1.1.0-rc.1` to `v1.1.0` only when:

- automated release workflow is green,
- RC smoke test is green,
- no release-blocking regression is known,
- no runtime feature change has been added after the accepted beta baseline unless it specifically fixes a release blocker.

If an RC blocker requires runtime code changes, publish another RC (`rc.2`, etc.) and repeat the smoke test before stable promotion.
