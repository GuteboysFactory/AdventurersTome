# v1.7.0-qa.1 — Campaign Links / Semantic Mention Foundation

**Stable baseline:** v1.6.0  
**Foundry verified baseline:** V13.351  
**Architecture:** v14-first / v13-compatible  
**Scope:** resolver foundation only; no prose scanning or Campaign Link writes

## Goal

Start v1.7 by hardening the identity contract before Tome begins discovering campaign mentions from Session and Quest prose.

The build adds a read-only resolver that consumes a normalized MentionCandidate and resolves it against the current viewer-scoped Universal Campaign Discovery snapshot.

## Implemented

- new public `campaignMentions` API
- MentionCandidate normalization
- target families for Character, NPC, Location, Faction, Item, Lore, Quest and Session
- identity priority:
  1. canonical UUID
  2. semantic identity
  3. external/import identity
  4. corroborating context
  5. display name only as evidence
- same-name isolation
- multiple-context-signal requirement before contextual auto-link eligibility
- explicit review/ambiguous/unresolved outcomes
- read-only audit diagnostics
- text scanning deliberately disabled

Contract: `docs/CAMPAIGN_LINK_SEMANTIC_MENTION_CONTRACT.md`

## Explicit non-goals

qa.1 does **not**:

- scan Session/Quest prose
- persist discovered mentions
- create or delete Campaign Links
- replace manual links
- auto-merge same-name entities
- expose hidden evidence
- begin Migration Workspace

## QA A — Canonical UUID wins

Create a candidate for a visible Actor using its exact UUID:

```js
const api = game.modules.get("adventurers-tome").api.campaignMentions;
const actor = game.actors.contents[0];
api.resolve(api.createCandidate({
  text: actor.name,
  kindHint: "npc",
  explicit: { canonicalUuid: actor.uuid }
}));
```

Expected:

- decision = `resolved-canonical`
- confidence = 1
- selected target = the exact Actor
- autoLinkEligible = true

## QA B — Name alone does not auto-link

Create a candidate using only a visible Actor's display name.

Expected:

- `review`, `ambiguous`, or `unresolved`
- never `autoLinkEligible: true` from name alone

## QA C — SAME NAME ≠ SAME IDENTITY

Use two visible campaign entities with exactly the same display name but distinct identities.

Resolve a candidate containing only that name.

Expected:

- decision = `ambiguous`
- selectedTarget = null
- requiresReview = true
- both identities remain separate candidates

## QA D — Corroborating context

For a target with matching semantic attributes, supply at least two independent contextual attributes.

Expected for a unique result:

- decision = `resolved-corroborated`
- autoLinkEligible = true

If multiple candidates are still strongly supported, expected:

- `ambiguous` or `review`
- no silent merge

## QA E — Viewer-scoped privacy

Repeat relevant candidate tests as a real player.

Expected:

- hidden/unreadable target documents are absent from the Discovery snapshot
- resolver cannot select them
- no hidden identity appears in candidates or counts
- no indication that hidden evidence exists
