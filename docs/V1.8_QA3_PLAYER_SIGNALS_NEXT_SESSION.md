# 1.8.0-qa.3 — Player Signals in Next Session Prep

Local QA build continuing the Player Chronicle work. Not published or tagged.

## Included

- Next Session Dashboard adds a **Player Signals** section for the GM.
- It groups currently available, player-authored snapshots explicitly shared **with the GM** by signal type and visible canonical entity. The summary shows distinct players, signal count, original note titles and excerpts.
- A note linked to multiple visible entities can appear in each relevant entity group. Notes without currently visible links are grouped without exposing hidden identities.
- Each linked identity opens through its canonical Foundry UUID. The existing Player Signals page remains available for full review.
- Withdrawal removes signals from the active summary after its tombstone is imported.

## Privacy and authority

- Only the GM reads the aggregate, and the model API returns no data to players.
- Private notes, party-only snapshots and GM-authored Chronicle entries are excluded. Only explicit GM shares are included.
- Entity labels are permission-projected before rendering. Hidden or revoked links cannot leak through names, counts or group labels.
- Signal types are the player's selected labels. Tome does not infer intent, classify note text, rewrite it, or turn signals into campaign facts.
- This is an overview for prep, not a scheduled-session binding: notes do not have a target-session field yet.

## Verification

- Model tests check aggregation, distinct player counts, and exclusion of private, Party-only and GM-authored notes.
- Browser test checks the Next Session Dashboard container and renders an explicitly GM-shared signal group with its canonical entity link in Microsoft Edge.
- Full Node regression: **618 passed, 0 failed**. Manifest/workflow validation and syntax checks passed for 97 ES modules and the vendor script.
- Campaign Index exclusion and Chronicle privacy tests are included in the full passing suite. Live GM/second-player checks remain necessary before stable release.
- Live two-player Party delivery remains deferred until a second player can join. Test the Dashboard with at least one real GM-shared player signal in Foundry V13.351.

## Deferred

- No automatic relevance ranking or narrative synthesis.
- No session-target assignment, cross-session trend inference, or direct edits to a player's note from GM prep.
- Party-shared signals do not appear in the GM panel unless the player separately shares a version with the GM.
