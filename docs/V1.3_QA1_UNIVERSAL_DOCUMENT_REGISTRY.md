# Adventurer's Tome v1.3.0-qa.1 — Universal Document Registry Foundation

## Purpose

This is the first **v1.3 Foundry Source Parity II / Universal Document Takeover** QA build.

The registry is deliberately **shadow/read-only**. It does not take over any existing Tome workflow and does not rewrite Foundry documents.

Goal:

> Establish one generic UUID-indexed view of the Foundry documents Tome may later work against, before any new live authority is introduced.

## Supported document types

- Actor
- Item
- JournalEntry
- JournalEntryPage
- Scene
- Folder

## Architecture constraints

- Core remains RPG-system agnostic.
- No system-specific fields are read or written.
- UUID is the canonical registry key.
- JournalEntryPage retains explicit parent UUID.
- ordinary documents retain Folder UUID where present.
- Folder hierarchy is represented through parent Folder UUID.
- registry rebuilds are read-only.
- no rename/move/create/delete hook performs a Tome write.
- v14-first / v13-compatible platform policy remains active.
- v1.2 stable behavior remains live authority.

## QA 1 — Startup

1. Install `v1.3.0-qa.1` from TEST.
2. Start the world on Foundry V13.351.
3. Open console.
4. Expected log:

   `Adventurer's Tome | Universal Document Registry shadow foundation ready: <N> documents, healthy.`

5. No recurring Tome errors.

## QA 2 — Registry API

Run in console:

```js
game.modules.get("adventurers-tome").api.universalDocuments.audit()
```

Expected:

- `schema = "adventurers-tome.universal-document-registry"`
- `schemaVersion = 1`
- `mode = "shadow-read-only"`
- `healthy = true`
- `total > 0`
- `byType` contains Actor / Item / JournalEntry / JournalEntryPage / Scene / Folder counts
- `duplicateUuids = []`
- `invalidDocuments = []`
- `missingFolders = []`
- `badPageParents = []`

## QA 3 — UUID resolution

Pick one Actor and run:

```js
const a = game.actors.contents[0];
const r = game.modules.get("adventurers-tome").api.universalDocuments;
[r.get(a.uuid), r.resolve(a.uuid) === a]
```

Expected:

- registry record has the same UUID, id, name and `documentName: "Actor"`
- second result is `true`

Repeat for one Item, JournalEntry, Scene and Folder if available.

For a Journal page:

```js
const p = game.journal.contents.find(j => j.pages.size)?.pages.contents[0];
const r = game.modules.get("adventurers-tome").api.universalDocuments;
r.get(p.uuid)
```

Expected:

- `documentName: "JournalEntryPage"`
- `parentUuid` equals the owning JournalEntry UUID
- `embedded: true`

## QA 4 — Rename/move shadow refresh

1. Pick an Actor.
2. Rename it in Foundry.
3. Wait a moment.
4. Run:

```js
game.modules.get("adventurers-tome").api.universalDocuments.get(game.actors.getName("NEW NAME")?.uuid)
```

Expected: record contains the new name.

5. Move the Actor to another Folder.
6. Run `get(actor.uuid)` again.

Expected: `folderUuid` matches the new Folder UUID.

No Tome document should be rewritten by the registry itself.

## QA 5 — Create/delete shadow lifecycle

1. Create a disposable Actor.
2. Confirm `registry.has(actor.uuid) === true` after the hook settles.
3. Delete it.
4. Confirm `registry.has(oldUuid) === false`.
5. Run `audit()` again.

Expected: `healthy = true`.

Repeat with a disposable JournalEntryPage if convenient.

## QA 6 — v1.2 regression smoke

Registry must not change existing behavior. Verify briefly:

- Tome opens normally.
- World/NPC Known Information still works.
- Actor-backed rename live sync still works.
- Private Vault opens.
- Group opens.
- Search works.
- no new Tome console errors.

## PASS gate

`v1.3.0-qa.1` passes when:

- registry builds successfully on V13.351;
- audit is healthy;
- representative UUIDs resolve correctly;
- JournalEntryPage parent identity is correct;
- rename/move/create/delete are reflected in shadow state;
- no registry action writes canonical Foundry/Tome data;
- v1.2 workflows remain intact;
- no recurring Tome console errors appear.

Only after this foundation passes may v1.3 begin comparing existing Tome source links against the universal registry in shadow parity.
