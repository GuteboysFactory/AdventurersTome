# 1.8.0-qa.2 — Player Knowledge & Memory Views

Local QA build on the qa.1 Player Chronicle foundation. Superseded by qa.3; not published or tagged.

## Included

- **Known to Me** groups canonical entities linked by the current user's private Chronicle notes and explicit shared notes available to that user.
- Each Known to Me entry navigates through the canonical Foundry UUID and lists the note references behind the entry. The view describes note context; it does not assert that a player knows campaign truth.
- Players may add an optional calendar date for when a remembered moment happened. The timeline uses only that explicit date, sorts chronologically, and does not mistake note creation/edit times for story events.
- My Chronicle search now covers the user's private notes, received shared versions, signal labels, remembered-moment dates and currently visible linked entity names.
- Personal and shared snapshots remain separate from Campaign Memory, Campaign Index, campaign discovery and shared Search.

## Boundaries

- Locked encrypted notes do not disclose their hidden title, text, links or remembered date; they may appear only as a locked private note.
- Entity and note visibility still follows the current user's Foundry permissions. Inaccessible UUIDs and names are excluded before display.
- An entity listed in Known to Me means only that it appears in a private note or an explicit share the user can access. Tome does not infer character knowledge or confirm a campaign fact.
- Next Session signal aggregation is added in [qa.3](V1.8_QA3_PLAYER_SIGNALS_NEXT_SESSION.md); narrative synthesis and inference remain out of scope.
