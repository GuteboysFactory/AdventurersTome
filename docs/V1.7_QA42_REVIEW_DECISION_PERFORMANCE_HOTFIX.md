## Root cause and measurement boundaries

The guided Review handler forced `campaignMentionEvidence.sync({rescan:true})` without a source boundary after the authoritative decision. This ran Semantic Mention discovery and New Entity discovery over every Session/Quest, then resolved all campaign candidates again. It also called global relationship extraction. Memory sync rendered Tome itself, followed by the handler's second render. Link writes and learning signals additionally scheduled background scans through lifecycle hooks. Create awaited registry rebuild and discovery including compendiums before returning. These shared post-decision paths explain unnecessary work after the “linked” notification.

The foreground four-source fixture reproduced **two full narrative scans per click**, including Keep Unresolved, and duplicate foreground renders for Link/Keep. Create additionally requested a compendium-inclusive discovery scan. It did **not** reproduce the reported 12–13+ second live freeze or a six-build graph storm. Its transport is in memory and its render exercises real Memory/Review projection functions and Entity Intelligence, not Foundry's complete browser layout/paint. Native creation UI is replaced by a generic test provider. Background timer delays are excluded from timings; separate tests drain scheduled callbacks to verify convergence. Live latency and any remaining large-world context cost must be measured by Per with the new profile.

The same measurement helper runs against an archive of the immutable baseline and current code, with three fresh-world samples per action. Totals below are medians; phase times/counters come from the median sample. Nested phases overlap and must not be summed. CPU warmup and host load still affect this small sample.

## Incremental design and hook cascades

1. Validate the candidate and selected UUID through existing GM-authority APIs. Picker catalog text cannot authorize a link. Canonical UUID validation now runs once after the picker; confirm-to-handler/dialog-close timing is retained.
2. Save the canonical Campaign Link and learned decision using existing APIs. If learning persistence fails after a new link, roll that link back. A pre-existing link is preserved.
3. Update only the affected source's mention/evidence records. Semantic/New discovery replace that source's cached slice, preserving unrelated candidates, suppression records and diagnostics only for the same viewer. Memory merge preserves unrelated persistent records byte-for-byte. Keep reuses discovery rather than rerunning NLP. Scoped post-decision resolution disables automatic creation of other candidates; they remain in REVIEW for their own decision. Full analysis retains its existing creation policy.
4. Refresh relationship evidence only for that source, preserving unrelated historical/active rows and decision history. Full sync APIs remain available for manual reanalysis, startup/recovery and genuine global changes. Concurrent Memory syncs are serialized; a scoped relationship request waits rather than being silently replaced by a concurrent global sync.
5. Internal canonical flag writes carry an explicit Foundry operation option. Narrative discovery/relationship/render scheduling skips these derived flag-only writes; normal external edits retain their hooks. Internal learning/discovery scheduling is coalesced during the active decision. A silent scoped discovery pass avoids scheduling a new global scan from its own completion signal.
6. Registry lifecycle hooks update the affected document record during the decision. Create refreshes its canonical entity in the current GM Discovery snapshot without awaiting registry/world/compendium scans. Existing registry audit findings are retained; parity metadata is recomputed from current registry records, not by collecting the world again. Untagged external registry events are deferred, then replayed after the decision; they are not discarded. Newly created documents/pages belonging to this action are recognized before finalization.
7. Intermediate render requests are coalesced; the handler awaits one final render. The original render and hook-dispatch functions are restored in finalization. EI may receive several cheap invalidations (counts are logged), while the subsequent visible graph/index builds once in the fixture. The first-party Context/Memory/Review work is timed so Per can identify any remaining heavy phase.

## Transaction and duplicate-click safety

Review actions lock while an action is pending, including a second button/picker invocation. Simultaneous clicks produce one entity/link operation. Derived refresh occurs after authoritative persistence; a failed derived refresh does not discard the saved decision. Creation likewise remains successful if its incremental Discovery view refresh fails. Locks/render/hook wrappers restore after failure. Undo for Link restores the prior source choice/dismissal and removes only a newly added link. Undo for Create reverses the source decision/link while retaining the authored canonical entity; it does not delete campaign content. Reload and full manual reanalysis retain learned authority.

This uses ordered existing Foundry writes and rollback for a failed Link decision save; it does not claim an atomic multi-document database transaction. Native creation cancellation and provider failures retain their existing semantics.

## Privacy, adapters and startup

The profile contains fixed action/phase names, durations and numeric counters. No candidate/source/target names, UUIDs, source snippets, private notes or secrets enter telemetry. Unknown labels are normalized. Snapshots and console output are GM-only. Viewer stamps prevent merging another viewer's cached discovery slice. Existing player permission, hidden endpoint/source/page, canonical backlink and no-adapter suites remain green. No production campaign names, system IDs or Session numbers are hardcoded.

Startup migration and summary code are unchanged. The live-world startup improvement previously reported by Per is not remeasured here. The real-DOM startup fixture still gives **18 then 0 migrations**, **2 then 0 repairs**, and zero reload vault/document/page writes. The recorded fixture times were 19.4/3.4 ms total for vault+summary; these are synthetic timings, not Per's world. The new Review module registers read-only APIs/hooks and starts no startup scans or rebuilds. The complete startup/idempotency regression suite remains green.
