# v1.7.0-qa.25 — Suggested Mention Identity Reconciliation

**Baseline:** v1.7.0-qa.24  
**Foundry baseline:** V13.351  
**Scope:** reconcile projected/duplicate campaign identities before rendering Tome noticed and Campaign Analysis known-mention rows.

## Problem

qa.24 correctly separated authoritative Campaign Links from heuristic text mentions, but the advisory layer could still show one semantic person multiple times when that person had more than one Foundry representation.

Examples:

```text
Arne
├─ Contact Journal projection
└─ Actor

Baran Dev
├─ Contact Journal projection
└─ Actor
```

Those are not necessarily separate identities. A managed Contact projection may explicitly point to an Actor through `semanticProjection.linkedUuid` or Tome World profile metadata.

## Shared reconciliation layer

qa.25 adds a read-only Campaign Identity Reconciliation API.

Identity authority is resolved in this order:

1. Actor UUID when the source is an Actor.
2. Actor UUID referenced by a managed Contact / World projection.
3. Explicit Tome World profile Actor reference.
4. Journal UUID for an independent World entity.
5. Canonical UUID fallback.
6. Normalized display name only as a grouping key, never as identity authority.

The layer performs no writes.

## Projection collapse

If an Actor and Contact/World projection resolve to the same Actor UUID, they are rendered as one logical suggestion.

Example:

```text
Arne
Character / Contact
Reconciled
```

The projection remains a separate Foundry Document. qa.25 only reconciles its presentation identity.

## True ambiguity

If multiple unrelated canonical identities share the same normalized display name and do not converge on the same authority UUID, the result remains **Ambiguous**.

Example:

```text
Baran Dev
2 possible identities
AMBIGUOUS
```

No silent merge is performed.

## Consumers

### Tome noticed

Session/Quest Suggested Mentions now reconcile across:

- Actor suggestions
- Contact / World suggestions
- Quest suggestions
- Session suggestions

This allows Actor + Contact projections to collapse even though they originated in different suggestion categories.

### Campaign Analysis

Known mentions reuse the same reconciliation layer so the GM Review panel and Tome noticed no longer invent separate identity models.

Detection and identity confidence are aggregated conservatively across reconciled representations.

## QA

### Test A — Actor + Contact projection

Use a campaign person that exists as both:

- a Foundry Actor
- a managed Contact projection linked to that Actor

Mention the person in Session text without creating an explicit Campaign Link.

Expected:

- one Tome noticed row, not two
- label indicates Character / Contact when both representations exist
- row is marked Reconciled
- not marked Ambiguous

### Test B — unrelated duplicate name

Use two independent World/Actor identities with the same display name and no projection/canonical relationship.

Expected:

- one advisory display row may summarize the collision
- it is marked Ambiguous
- UI states multiple possible identities
- no canonical identity is selected automatically

### Test C — Campaign Analysis parity

Open Campaign Analysis for the same Session.

Expected:

- known mentions use the same identity interpretation as Tome noticed
- Actor + Contact projection does not appear as two unrelated known identities
- true duplicate identities remain Ambiguous

### Regression

- qa.24 canonical Campaign Link counters/lists remain authoritative only.
- qa.20–qa.23 Create & Link and Link Existing are unchanged.
- no auto-linking
- no auto-creation
- no confidence-driven graph writes
- system-agnostic startup remains unchanged.

## PASS gate

qa.25 passes when projected representations of one canonical Actor collapse into one advisory identity in both Tome noticed and Campaign Analysis, while genuinely unrelated same-name identities remain ambiguous.
