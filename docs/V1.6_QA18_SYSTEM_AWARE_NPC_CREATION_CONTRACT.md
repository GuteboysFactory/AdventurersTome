# Adventurer's Tome v1.6.0-qa.18 — System-aware NPC Creation Contract

**Baseline:** v1.6.0-qa.17 FULL PASS  
**Foundry target:** V13.351  
**Scope:** API / contract foundation only — no Quick NPC UI yet

## Goal

Establish a generic, system-aware NPC creation contract before Tome exposes creation UX.

The contract keeps system-specific field knowledge behind the Adapter API while Tome Core owns validation, duplicate prevention, planning, provenance and the explicit GM-only apply step.

## New public API

```js
game.modules.get("adventurers-tome").api.npcCreation
```

Methods:

- `schema(options)`
- `plan(options)`
- `apply(plan)`
- `audit()`

Adapter helper:

```js
game.modules.get("adventurers-tome").api.adapters.npcSchema(...)
```

## Architecture

```text
GM request
   ↓
active system adapter → npcSchema
   ↓
Core schema normalization / validation
   ↓
duplicate scan
   ├─ exact World Actor → reuse
   ├─ exact Compendium Actor → import candidate
   └─ no exact candidate → create-new plan
   ↓
read-only deterministic plan
   ↓
explicit GM apply(plan)
   ↓
canonical Actor UUID
```

## Safety locks

- planning and apply are GM-only
- no adapter schema = fail safely, no partial Actor
- only adapter-declared `system.*` paths may be written
- prototype-pollution paths are rejected
- unsupported fields are rejected
- plans are immutable and signature-checked before apply
- ambiguous exact World/Compendium duplicates block apply
- identity matching is exact-name + actor-type only; no fuzzy auto-merge
- apply is never automatic
- Quick NPC UI is intentionally deferred until this contract passes QA

## Realm Guard reference schema

Realm Guard is the first advanced reference implementation.

Actor type:

`npc`

Declared fields:

- concept
- rank
- homeland
- ancestry
- biography
- notes

Realm Guard remains optional. Tome Core has no runtime dependency on a particular Realm Guard version.

## QA protocol

### A. Adapter / schema

As GM:

```js
const at = game.modules.get("adventurers-tome").api;
const schema = await at.npcCreation.schema();
schema;
```

Expected:

- contract = `adventurers-tome-npc-schema`
- adapterId = `realm-guard-semantic-reference`
- systemId = `realm-guard`
- actorType = `npc`
- six normalized fields
- no mutation

### B. Create-new plan

Use a unique name:

```js
const plan = await at.npcCreation.plan({
  name:"Tome QA NPC 18",
  values:{
    concept:"Contract QA",
    rank:"Test",
    homeland:"Bree",
    ancestry:"Man",
    biography:"<p>qa.18</p>",
    notes:""
  }
});
plan;
```

Expected:

- `liveMutation:false`
- `resolution.action:"create-new"`
- `canApply:true`
- no Actor exists yet
- actorData contains only schema-authorized system paths

### C. Explicit apply

```js
const result = await at.npcCreation.apply(plan);
result;
```

Expected:

- Actor created once
- type = `npc`
- canonical Actor UUID returned
- provenance flag under `flags.adventurers-tome.npcCreation`

### D. Existing World duplicate prevention

Re-run the same plan with the same name.

Expected:

- `resolution.action:"reuse-world"`
- apply returns existing Actor
- no duplicate Actor created

### E. Unsupported field rejection

```js
await at.npcCreation.plan({
  name:"Should Not Exist",
  values:{ evilPath:"nope" }
});
```

Expected: throws safely and creates nothing.

### F. Non-GM safety

As player, call `plan()` or `apply()`.

Expected: blocked, no mutation.

### G. Audit / regression

```js
at.npcCreation.audit()
```

Expected: `healthy:true`.

Then run the v1.6 final regression audit from qa.17. All read/privacy/convergence checks must remain green.

## Promotion rule

qa.18 passes when:

- schema is normalized and inspectable
- create-new plan is mutation-free
- explicit apply creates exactly one valid Actor
- same-name retry reuses the World Actor
- unsupported fields and non-GM writes are blocked
- existing v1.6 read/privacy regression remains green

Only after this passes should Quick NPC creation UI be wired to the contract.
