# v1.7.0-qa.15 — Question & Alias Boundary Precision

**Baseline:** v1.7.0-qa.14  
**Foundry baseline:** V13.351  
**Scope:** fix the verified question-sentence boundary edge case where grammar words become part of an unknown entity candidate.

## Live qa.14 edge case

Session QA — The Broken Road to Hollowwatch was extended with:

```text
Is this really solved? Is Dev gonna be the hero he is destined to be?
```

The new-entity scanner produced:

```text
Is Dev
Unknown
1 mention
72%
Review
```

The candidate boundary was wrong. The intended semantic identity is the already-known alias `Dev` for `Dev Testsson`.

## Fix

qa.15 expands the existing leading-context trim step to include common question / auxiliary starters before known-name and known-alias filtering.

Examples:

```text
Is Dev ...
Was Gandalf ...
Did Arantor ...
Can Edrik ...
Could Elira ...
```

become:

```text
Dev
Gandalf
Arantor
Edrik
Elira
```

The remaining candidate then passes through the normal known canonical / known alias filters.

This is boundary precision only. It does not create fuzzy identity matches or persist aliases.
