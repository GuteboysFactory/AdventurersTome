# v1.7.0-qa.34 — Campaign Memory Search & Filters

**Baseline:** v1.7.0-qa.33  
**Foundry baseline:** V13.351

## Goal

Make persistent Campaign Memory / Mention evidence practically searchable, filterable and sortable without changing the canonical authority model.

qa.34 is GM-only because the current Mention ledger is GM-private/user-scoped.

## Search integration

The normal **Search the Tome** index remains unchanged for ordinary Tome entries.

GM users additionally receive a dedicated:

**Campaign Memory — Evidence Search**

section on the Search page.

This keeps campaign-memory evidence discoverable without mixing raw evidence rows into the normal entity/document index.

## Searchable evidence fields

Free-text search includes available:

- target/entity name
- detected mention text
- evidence snippet
- source Session/Quest name
- Journal page name
- entity type
- relation label
- source type
- lifecycle state

## Filters

qa.34 adds client-side filters for:

### Relation
- All relations
- Linked + Mentioned
- Mentioned
- Review
- Ambiguous / Unresolved

### Lifecycle
- Active + Historical
- Active
- Historical

### Source
- All sources
- Sessions
- Quests

### Entity type
Available target types are built dynamically from current evidence, for example:
- Character
- Faction
- Location
- Item
- Lore
- World

## Sorting

Evidence can be sorted:

- Newest
- Oldest
- First seen
- Last seen

The underlying Campaign Mention Evidence API also accepts:

```js
api.query({
  text,
  relationState,
  lifecycle,
  sourceKind,
  targetKind,
  sort
});
```

## Navigation

Each resolved evidence result supports:

### Target
Opens the resolved target inside Tome when possible.

- Actor-backed or Item-backed World projections open the Tome World profile.
- Actor targets without a World projection open the Tome actor profile.
- Journal targets route through the appropriate Tome view when available.
- unsupported but openable Foundry documents fall back to their native sheet.

### Source
Two source paths remain available:

- source Session/Quest button -> Tome source view
- **Source** -> authoritative Foundry Journal/Page

Unresolved / ambiguous evidence has no target navigation until identity resolution exists.

## Privacy lock

qa.34 must not expose the GM-private Mention ledger to players.

Expected:

- GM sees Campaign Memory Evidence Search
- non-GM users do not receive the evidence model in render context
- player Search remains the normal permission-safe Tome search

## Authority locks

qa.34 does not change:

- Deterministic Auto-Link rules
- canonical Campaign Link authority
- ambiguous identity handling
- auto-create policy
- Mention persistence semantics
- Foundry-as-backend/source-of-truth model

Search/filter operations are read-only.
