# 1.8.0-qa.4 — Player Chronicle Entity Surfaces

Local QA verification on top of `1.8.0-qa.3`. Not published or tagged.

## Scope

Audit the places where a player may open a canonical person, place, session, quest or other entity in Tome. The shared Chronicle integration already existed; this QA patch adds regression coverage rather than new Chronicle behavior.

| Surface | Target identity |
| --- | --- |
| Actor profile | Actor UUID |
| World profile | Canonical entity UUID from its profile |
| Session | Session JournalEntry UUID |
| Quest | Quest JournalEntry UUID |
| Generic entity context | Canonical entity UUID |

## Verified behavior

- Each player-facing entity view mounts Chronicle against that entity's canonical UUID.
- An entity view contains only private or explicitly shared notes linked to that UUID. A note linked to a different session stays out of the person profile.
- Creating a note from an entity view preselects that entity; links still resolve to the live visible Foundry document.
- **Known to Me** on an entity view is scoped to that same UUID and remains a record of note links, not a claim about campaign truth.
- GM renders do not mount player Chronicle panels on any of these surfaces. GM-private Campaign Memory/Notebook remains separate.
- Existing permission projection, encryption, explicit sharing and Chronicle exclusion from Campaign Index are unchanged.

## Verification

- `tests/qa18-chronicle-browser.mjs` passes in Microsoft Edge. It compiles the real Tome template and exercises all five target surfaces, entity filtering, Known to Me scoping, default link selection and the GM boundary.
- Full Node regression: **618 passed, 0 failed**.
- Manifest/workflow validation and syntax checks are run with `tests/validate.mjs`.
- The previously completed live QA confirmed My Chronicle / Player Signals sharing in Foundry. A separate visual check of every entity detail type remains useful when convenient; this patch does not claim a live Foundry run across all five.

## Changed areas

- `tests/qa18-chronicle-browser.mjs`: template matrix and focused target-surface browser assertions.
- `CHANGELOG.md`, `README.md`, and `module.json`: qa.4 build metadata.

No player Chronicle storage format, runtime behavior, campaign facts or permissions were changed.
