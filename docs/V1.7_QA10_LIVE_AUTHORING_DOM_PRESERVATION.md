# v1.7.0-qa.10 — Live Authoring DOM Preservation

**Baseline:** v1.7.0-qa.9  
**Foundry baseline:** V13.351  
**Scope:** preserve the exact active Session/Quest authoring DOM through autosave-driven document revision changes.

## Root cause

The remaining caret/focus loss was not a full Tome rerender.

`authoring-foundation.js` rebuilds Session/Quest page shells whenever a JournalEntryPage revision changes:

```text
autosave
→ JournalEntryPage.update()
→ page modifiedTime changes
→ atAfRenderPages sees a new stamp
→ existing .at-authoring-pages is removed
→ active contenteditable node disappears
→ caret/focus/scroll are lost
```

World did not show the bug because `atAfRenderPages()` explicitly skips World; its editor bridge owns the same DOM for the entire editing session.

## Fix

### Authoring Foundation

While the existing Session/Quest page shell contains a live editor:

- do not remove the shell
- do not rebuild the shell
- ignore autosave-only stamp changes for presentation
- mark a deferred structural refresh
- preserve the exact contenteditable node and caret

After the user deliberately exits editing, the deferred authoring refresh is allowed to run.

### Alpha6 Page Navigator

The page navigator also uses Journal page revision metadata as a rebuild signature.

While a live editor exists in the detail view:

- do not rebuild the navigator
- wait for editing to end
- refresh once afterward

## QA A — Session Chronicle

1. Open a Session Chronicle.
2. Enter edit mode.
3. Type continuously for at least 30 seconds.
4. Pause repeatedly long enough for several autosaves.
5. Continue typing after every save without clicking the editor again.

Expected:

- autosave occurs
- content persists
- same contenteditable DOM remains attached
- caret stays active
- focus stays active
- scroll position does not jump
- user can continue typing immediately

Then deliberately click outside.

Expected:

- edit session closes normally
- deferred UI refresh may run once
- latest text remains saved

## QA B — Quest Overview

Repeat the same test in Quest Overview.

Expected: identical behavior.
