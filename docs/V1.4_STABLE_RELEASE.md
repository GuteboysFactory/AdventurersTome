# Adventurer's Tome v1.4.0 — Tome GM Dock Stable Release

**Verified runtime baseline:** Foundry VTT V13.351  
**Architecture policy:** v14-first, v13-compatible; V14 runtime verification remains separate  
**Core policy:** system-independent; external integrations are optional capabilities.

## Stable milestone

v1.4.0 completes the Tome GM Dock milestone.

The release adds a compact GM command surface without creating a second campaign data model and without making any specific game system a Tome dependency.

## Shipped scope

- standalone GM-only Tome Dock
- optional `gbf-gm-dock-host` provider integration
- capability-driven Host v1 compatibility
- richer Host v2+ inline provider UX
- current canonical Foundry/Tome context
- UUID-backed pin/unpin
- contextual Private Vault for canonical Foundry documents
- inline/standalone Quick Capture
- explicit canonical Quick Capture target preservation
- Reveal Queue access
- Next Session / GM Dashboard access
- recent Tome navigation
- persistent Open Tome action in compatible rich hosts
- stale/deleted context recovery
- reload and lifecycle hardening
- multi-client/privacy hardening
- generic host replacement/re-registration hardening
- deterministic v1.4 runtime release gate

## System-independence guarantee

Reference systems are integration examples only.

Tome Core does not require a specific Realm Guard, Genesys or other system release. Host integration is negotiated through the generic `gbf-gm-dock-host` capability contract, and Tome retains full standalone functionality when no compatible host exists.

## Canonical-source preservation

The v1.3 Foundry Document-backed architecture remains authoritative.

Stable promotion requires:

- convergence `healthy === true`
- convergence `structuralHealthy === true`
- takeover misses = 0

The old v1.3 `qaComplete` signal is session-local runtime evidence and is not required to be recreated after every reload.
