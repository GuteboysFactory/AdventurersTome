Adventurer's Tome 2.0.0 — Integration API

Tome 2.0 gives other Foundry modules a documented connection point for system-independent campaign integrations. It builds on the existing Adapter API without requiring a particular game system.

External integration lifecycle

- A versioned Integration API reports compatibility and announces when Tome's core and Adapter API are ready.
- Active modules register under their own module IDs. Adapter IDs are namespaced, and exact-registration receipts keep cleanup from removing another provider's replacement.
- Existing Adapter API v1 registrations, matching, capability execution and optional reference adapters remain compatible.

Reviewed additions to known information

- Integrations can prepare a plain-text addition to an existing world Actor or JournalEntry's known information.
- The current user reviews the proposed addition in a native Foundry dialog before saving. Existing content is retained, and HTML/plain-text storage formats are respected.
- Native Tome visibility and semantic GM/OWNER permissions apply. Changed content, storage or permissions invalidate stale proposals. Tickets are short-lived and scoped to the integration and reviewing user.

Explicit private-note authorization

- A GM may approve one integration to read that GM's contextual private notes for one selected Actor or JournalEntry.
- Each permission permits one read, expires after 60 seconds, supports revocation and grants no write access. Other GMs' notes, other entries and private facts are excluded from the returned snapshot.
- Denying or closing the dialog does not read the private vault. Private data and tokens are not included in integration discovery or lifecycle events.

Developer documentation and optional fixture

- Public contracts and local QA instructions are included in docs/INTEGRATION_API.md, docs/INTEGRATION_SUBMISSIONS.md and docs/INTEGRATION_PRIVATE_NOTES.md.
- An optional example module is included under examples/tome-example-integration. It is not installed or enabled automatically, and makes no campaign writes or private reads on startup.

Scope and compatibility

The integration workflow is local to the current Foundry client. It does not provide a remote GM inbox, HTTP service, distributed transaction mechanism or universal RPG-system conversion. Enabled Foundry modules share a trusted JavaScript client; the authorization workflow is not a security sandbox against malicious modules or a restriction on downstream processing once a GM supplies data.

The existing 1.9 migration toolkit and interface improvements remain included. No campaign reimport is required for this update. Runtime baseline remains Foundry VTT 13.351; direct V14 verification is separate from the retained compatibility metadata.

After updating, restart Foundry and hard-refresh clients. The optional example module is only needed for developer/testing use.
