# qa.42 — Local Swedish and English narrative language foundation

This patch stays on qa.42. It adds narrative language rules, independent of Foundry's UI language, any game system, campaign names, users, and installation paths. No translator, download, network service, external program or shared-index engine is required. It does not translate or rewrite source text.

## Architecture

- `scripts/language-packs/en.js` and `sv.js` are local declarative vocabulary files. They contain grammatical boundary/noise words, entity titles and suffixes, attached role/document/place patterns, and relationship predicates with negation, uncertainty and temporal guards.
- `scripts/campaign-language-foundation.js` validates and freezes pack data, compiles/caches regular expressions, and exposes `narrativeLanguage` plus an audit. It has no document scanning, identity authority, write authority, or scheduled background work.
- `campaign-new-entity-discovery.js` uses both packs for candidate grammar, classification and attributed briefings. Uncertain identity fragments still require Review. A documentary classification does not itself grant permission to create an identity.
- `campaign-relationship-evidence.js` obtains predicate patterns from the packs and applies predicate-local language guards. Clause boundaries recognize both languages for mixed text. Canonical endpoints, permissions, source spans, evidence history, reverse links and GM decisions remain in the existing shared engine. Evidence provenance includes language and pack version. Established English evidence IDs are preserved.
- `module.json` loads both packs and their engine before consumers. Module version and public manifest/download URLs are unchanged.

The built-in providers cover the existing 19 canonical relationship types, with conservative explicit patterns. This is a rule-based foundation, not unrestricted language understanding: an unsupported expression or ambiguous referent must not become a hard fact. The packs can be extended with tested vocabulary without embedding campaign/system exceptions in the identity engine. Existing specialized English compound-information handling remains supported.

## Identity safeguard

`campaign-confirmed-entity-creation.js` now assesses the current document name when a candidate UUID resolves, rather than preferring a persisted display label. A stale Oren label attached to Toren Vale's UUID cannot manufacture a name match. Fresh identity projections from Discovery adapters can still supply legitimate source names that differ from a Foundry display name; stale Review labels do not receive that authority. Explicit UUID/source decisions remain authoritative; valid personal fragments remain Review-only. The new regression reproduces the stale-label failure and tests both safe rejection and explicit-choice handling.

## Automated validation

The language tests compare 24 English/Swedish formulations each, covering all 19 relationship types plus denied/ended/former/never-joined membership and uncertain/rumoured employment. They check source spans and language provenance, unchanged source text, stable IDs after reanalysis, accented candidate boundaries and attributed profession, mixed clauses, ambiguous namesakes and private endpoints. The shared test world loads exactly the shipped language files before consumers. Existing startup/adapter tests also verify that the new identity-name safeguard retains adapter source-name support without cloning the full registry.

Seven language-foundation tests also cover generic title rejection, name recognition without invented personal knowledge, composed/decomposed Unicode source coordinates, and ambiguous normalized-name collisions. Final validation: all eleven suites PASS, **414/414 tests**, including startup and Review performance regressions. Syntax PASS for 90 ES modules and one vendor script. Manifest/workflow URL checks and `git diff --check` PASS. No Foundry live-QA result is claimed; the local test ZIP is for that next step.

Old independent Gunther objects or conflicting historical GM choices are not automatically merged or erased. The erroneous old Orren object likewise requires a deliberate GM correction; language vocabulary does not establish identity.
