# Adventurer’s Tome 2.1.1

Private Vault now has its own workspace in **Campaign Tools → Private Vault**.
Write rich-text GM notes, search and filter them, pin important notes, create
and rename categories, attach private images and open a quiet token preview.
Actor and explicitly linked source views use the same authoritative notes.

## Private notes, images and deliberate sharing

- Private Vault records and uploaded images are encrypted. Older GM private
  records are retained and migrated after the encrypted copy is verified.
- Remember on this device avoids repeated passphrase entry in a trusted browser.
  Keep a recovery copy of the Vault passphrase; it is separate from Foundry sign-in.
- Images load on request. PNG/JPEG/WebP input is prepared to at most 1600 pixels
  on the longest side and 2 MB. Token hover does not fetch images automatically.
- Send only selected text or the chosen image to public chat or named recipients.
  Tome whispers encrypt the selection before chat storage and transmission, with
  encryption/decryption in dedicated workers. Recipients explicitly open them.
- Personal Vault export includes images and categories. These local export files
  contain decrypted private data and must be stored privately. Portable image
  backup supports 32 images; use a full world backup for larger Vaults.

## Session and Quest import

Trusted Players and Assistant GMs can import Session and Quest documents when
their Foundry role permits Journal creation. New sources are private to the
importer and GMs. Other GM tools remain restricted.

GM-only sections and reminders are preserved independently of who imports the
document. They can wait in the receiving GM's encrypted **GM Inbox** until that
GM reviews and accepts them into Private Vault. A prepared inbox receives while
the GM is offline. Trusted users cannot reroute protected GM sections into the
Chronicle or silently skip them. Missing keys or unavailable recipients stop
the operation without discarding private sections.

Document checksums support browsers without `crypto.subtle.digest`, correcting
the import error seen on HTTP hosts. Early adapter registration also tolerates
an unavailable module registry instead of calling `Reflect.get(undefined)`.

## Upgrade and important limits

Update the existing **adventurers-tome** module, restart Foundry and refresh
clients. Back up the world and previous module first. Do not enable TestAI in
parallel. Existing campaign sources do not need importing again.

**Private Vault requires HTTPS or localhost.** HTTP document-import compatibility
does not make Vault unlocking available on an insecure remote origin. Each
receiving GM must open their Vault once securely to prepare GM Inbox.

**Encrypted whisper history is device-bound.** A new browser profile or clearing
site data can make older encrypted whispers unreadable; cross-device whisper-key
recovery is not included. Retain the receiving browser profile. Vault passphrase
recovery is a separate mechanism. Other ordinary clients receive ciphertext,
but this does not defend against malicious same-origin code or compromised
HTTP delivery. This work has not received an independent cryptographic audit.

Older Tome versions cannot read the new encrypted Vault records. For a full
rollback restore both the previous module and its corresponding world backup.
This release cannot retract information already sent before encryption setup.

Validated with **49 targeted tests and 484 existing production tests**, native

approval and subsequent user testing. Foundry V14 is not directly verified.
