# Adventurer's Tome v1.4.0-qa.2 — Unified GM Dock Host QA

**Foundry target:** V13.351  
**Stable baseline:** v1.3.0  
**Previous QA:** v1.4.0-qa.1  
**QA build:** v1.4.0-qa.2  
**Companion Realm Guard build:** v1.9.0-qa.7

## Goal

Verify that Adventurer's Tome behaves as a **GM Dock provider** when a compatible GuteboysFactory Dock Host exists, while retaining its own compact Dock as a standalone fallback.

The expected user experience is one GM Dock, not one Dock per product.

## A. Realm Guard + Tome

- [ ] Enable Realm Guard / Torchbearer v1.9.0-qa.7 and Adventurer's Tome v1.4.0-qa.2.
- [ ] GM sees only the Realm Guard GM Dock.
- [ ] No separate Tome Dock remains visible.
- [ ] Realm Guard Dock contains an Adventurer's Tome provider button.
- [ ] Clicking the Tome provider opens a compact integrated Tome menu.
- [ ] Existing Realm Guard Dock tools still work unchanged.
- [ ] Realm Guard Dock drag/reset/persistence still works.

## B. Tome integrated menu

- [ ] Current context is displayed correctly.
- [ ] Open Current Context navigates to the canonical Tome entry when available.
- [ ] Pin Context survives navigation and reload.
- [ ] Unpin restores normal context resolution.
- [ ] Private Vault opens the existing UUID-backed record.
- [ ] Private Vault badge/count is correct.
- [ ] Quick Capture opens the existing Tome Quick Capture workflow.
- [ ] Reveal Queue badge is correct and opens the existing queue.
- [ ] Next Session opens the existing Tome GM Dashboard/session-prep workflow.
- [ ] Recent Tome entries resolve current names and canonical sources.
- [ ] Open Adventurer's Tome opens the normal full Tome workspace.

## C. Standalone fallback

Test in a world/system without a compatible Dock Host.

- [ ] Tome creates its own compact GM Dock.
- [ ] Context, Vault, Quick Capture, Reveal Queue, Next Session and Recents still work.
- [ ] Position remains per-user and reload-safe.
- [ ] No assumption about Realm Guard exists in Tome Core.

## D. Host lifecycle / privacy

- [ ] Player clients see neither Realm Guard GM Dock nor Tome GM provider.
- [ ] Tome private data is not exposed through host menu labels/details.
- [ ] Enabling both products creates no recurring render loop or console spam.
- [ ] Host/provider refresh after document rename is stable.
- [ ] Deleting a pinned/missing source falls back safely.
- [ ] Existing v1.3 canonical-source behavior remains intact.

## E. Architectural acceptance

- [ ] Realm Guard owns only the Dock host/presentation contract.
- [ ] Tome owns its campaign actions and data.
- [ ] Realm Guard does not copy Tome campaign data.
- [ ] Tome does not import Realm Guard rule state into its Core.
- [ ] No new parallel canonical model is introduced.
- [ ] The contract can support future providers without hard-coding Tome into Realm Guard.
