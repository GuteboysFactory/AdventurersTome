## Goal

Begin actual campaign-text discovery without weakening the qa.1 identity contract.

## Implemented

- scans readable Sessions and Quests
- scans readable text Journal Pages
- strips Foundry secret content for non-GMs
- detects explicit Foundry document refs
- detects exact visible entity names in prose
- feeds all findings through the qa.1 conservative resolver
- suppresses explicit refs whose target is absent from the current viewer-scoped Discovery snapshot
- produces a disposable runtime snapshot
- performs no Campaign Link writes

Contract: `docs/SESSION_QUEST_SEMANTIC_MENTION_DISCOVERY_CONTRACT.md`

## QA 1 — Discovery audit

Run:

```js
const d = game.modules.get("adventurers-tome").api.campaignMentionDiscovery;
d.audit();
```

Expected:

- `healthy: true`
- `readOnly: true`
- `textScanning: true`
- `writesPerformed: false`
- `autoPersistence: false`
- sourceScope = Session + Quest

## QA 2 — Full viewer-scoped scan

Run:

```js
const snap = await d.scan({ rescanDiscovery: true });
snap.summary;
```

Expected:

- Sessions/Quests counted
- readable text pages counted
- zero or more mentions
- no exception
- no recurring console loop
- no Journal or Campaign Link mutation

Then inspect a few rows:

```js
snap.mentions.slice(0, 10);
```

Expected:

- source Journal/Page UUID
- source name/page name
- mention text
- mentionType = `explicit-link` or `prose-name`
- resolver outcome attached

## QA 3 — Explicit canonical ref

In a disposable Session/Quest text page, add a normal Foundry inline link to a visible Actor/Item/Journal/Scene.

Rescan.

Expected:

- mentionType = `explicit-link`
- decision = `resolved-canonical`
- autoLinkEligible = true
- writesPerformed remains false

## QA 4 — Plain prose name

Write a visible Actor's exact name as ordinary prose with no Foundry link.

Rescan.

Expected:

- mentionType = `prose-name`
- decision = `review` when unique by type
- autoLinkEligible = false
- reason remains display-name-only unless stronger evidence exists

## QA 5 — Same-name prose ambiguity

Use two visible same-type entities with the same display name and mention that name in prose.

Expected:

- decision = `ambiguous`
- selectedTarget = null
- requiresReview = true
- autoLinkEligible = false

## QA 6 — Privacy

As a real Player:

- secret HTML is excluded
- unreadable target entities are absent from derived candidates
- an explicit ref to an unreadable target does not appear as a derived mention
- no hidden target name/UUID leaks through summary rows
