# qa.43 — Global view continuity hotfix

The earlier continuity code matched nodes using all CSS classes and data attributes and restored only during the app render callback. Tome's explorer and authoring components also mount after render hooks. Their runtime classes/guards made saved nodes unmatchable, and delayed replacement could discard an already-restored scroll position or open details.

The shared continuity helper now uses stable node attributes and the base class. It retains pending state across consecutive background renders and briefly observes delayed child replacement for up to 600 ms after each restore. Navigation cancels pending restoration. Pointer, wheel, touch, keyboard and input events immediately relinquish control to the user. Observers/listeners/timers are cleaned up after settlement or cancellation.

The fix is called by the main Tome application for all routes. No Session, Review, campaign, name or game-system exception is used. Campaign data, analysis rules and identity decisions are unchanged.

Validation: 77/77 targeted tests passed across continuity, decision history, Review performance, private facts and qa.43 role/name regressions. A separate headless Edge/Playwright test exercised real DOM layout, runtime enhancer attributes, a component inserted 90 ms after initial render, and user scroll cancellation. Scroll restored to 520 with details open; subsequent user position 160 and closed details remained intact. Live Foundry verification is still required.
