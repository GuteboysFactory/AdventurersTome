# Campaign index and background page analysis — local QA build

The index is a derived, GM-only service under Campaign Tools → Index. It reuses
unchanged page analysis and routes automatic mention discovery, new-entity
discovery and deterministic linking through one coalesced source queue. Existing
language rules are unchanged. Canonical identity, source choices, suppression,
Undo and Foundry document writes remain in the existing authoritative APIs.

## Storage and invalidation

- IndexedDB is scoped to the Foundry world ID and current GM user ID on this
  browser/origin. Other browsers/GM accounts build their own index.
- Page entries include the language/index revision, exact source text and the
  relevant known-name/authority inputs. SHA-256 keys are used on secure origins;
  exact input keys preserve correctness on LAN HTTP without SubtleCrypto.
- The derived page cache is bounded to 256 entries and approximately 16 MiB.
  Eviction only causes reanalysis. Revision changes invalidate analysis, while
  retaining historical identity markers.
- Source changes, new/deleted pages, document changes, ownership changes,
  learning/settings changes and identity changes enqueue a check. Same-source
  rapid changes are coalesced. GM-only access is checked on use, not just load.
- Unchanged sources skip matching/sync once settled. A changed identity catalogue
  or GM policy reruns matching; pure page analysis is reused when its inputs match.
- Saved mention-ledger changes invalidate source signatures, including an
  externally cleared ledger. Index results never replace canonical documents.
- Browser storage failure is shown in Index and falls back to memory-only reuse.
  This is not a distributed shared index or a backup/export of Foundry documents.

## Background execution

The module worker loads the same shipped language packs, NLP provider and page
analyser as the main module. It receives plain authorized data, not Foundry
document instances, private-vault APIs or canonical write methods. There is one
worker; remaining identity resolution yields between work units on the main
thread. The first build still consumes CPU and may take time. `async` alone is
not presented as isolation, and zero impact on Foundry is not guaranteed.

Worker failure stops the job visibly rather than silently accepting partial
analysis. Retry is available with Check changes. On browsers without Worker,
the UI explicitly reports compatibility mode with pauses between pages.

Only the active GM runs automatic persistence. Explicit existing Review actions
remain available through their normal APIs. Source changes and intervening GM
decisions invalidate an in-flight queue result before ledger commit. A stale job
is queued again. Completed sources are checkpointed so interruption is recoverable.

## Lifecycle and history

- Archive/Reactivate uses the existing canonical matching pause/resume policy.
  It does not delete, clone, rename or silently merge documents, nor remove
  established links. It retains the same identity UUID and existing Undo policy.
- Removing a Foundry document leaves a historical marker with its last known
  name/type and source references seen by this index. A deleted NPC is a historical
  contact card, not a newly created Contact identity. Original Actor data is not
  restored by this service.
- Deleted source/page text is removed from the page cache. The existing mention
  ledger retains historical evidence, while deleted sources leave live snapshots.
- A deleted identity with the same name prevents automatic replacement creation;
  the GM must deliberately link or create. Restoring the original document UUID
  reactivates the existing marker. A new UUID remains a different identity.
- Forget index marker removes only the local historical marker. It does not
  erase Foundry documents, the GM's decisions, or the authoritative mention ledger.
- Clearing browser storage loses this browser's derived cache and historical
  markers. Keep Foundry/world backups for actual NPC restoration and durable
  campaign-history preservation across devices.

## UI

Index shows current source, source progress, page cache hits/misses, recent
sources, storage/worker errors, searchable active/archived/deleted identities and
their last known source references. Pause takes effect after the current source;
Continue resumes. Rebuild clears derived analysis, retaining identity history.
It does not change language interpretation or resolve ambiguous identities.

## Validation

Regression bank covers existing language, source authority, ambiguity, Undo,
privacy and rendering behavior. Index tests cover cache invalidation, immutable
results, settled-source reuse, active-GM/role gates, source edits mid-job,
intervening GM decisions, deletion, pause/resume and LAN HTTP fallback.
The real Edge test verifies worker/main analysis equivalence, event-loop progress
while the worker runs, and persisted IndexedDB reuse after reload.

Live Foundry startup timing must still be measured on the user's world. Compare
an initial build with a second unchanged reload and verify source edits, deletion,
archive/reactivation and existing Review behavior before considering publication.
