# 1.9.0-qa.4.4 — TAF import with one approval

This fixes the qa.4.3 workflow: its initial ZIP preview still displayed hundreds of exceptions until a separate group-conversion button was used. That activation step is removed.

## Normal flow

Gear → Import & Export → Import → select the existing ZIP → Preview Import → review the concise proposal → Approve proposal & Import.

Reading a TAF ZIP for Realm Guard now prepares the conversion proposal immediately. It performs no document, account or setting writes. The displayed ready/exception counts already include withheld dependencies; they describe the copies the import can actually create, not an unconverted intermediate queue.

The visible proposal describes these defaults before approval:

- Authoritative source Character/NPC categories are retained. PC/NPC source folders supply proposals; remaining unclassified Actors are proposed as NPCs. The GM can change any group or the fallback before importing. This is an approved conversion proposal, not an assertion that folder names prove character identity.
- Compatible core fields and readable source-reference information use the existing qa.4.3 converter. NPC compendium entries remain separate compendium copies.
- Scene tokens are proposed to use converted base Actors; source-specific overrides remain archived. The GM can disable this policy for individual Scene review.
- The exporting GM maps to the current GM. Saved mappings are retained. Uniquely named existing Player accounts can be proposed; otherwise new Player accounts are proposed for source players. Other source GMs default to Keep private. The proposal explicitly counts new Player accounts. No account is created until Import is approved, and retries reuse already-created migration accounts.

Account mapping and group options are collapsed but available. Changing a group, fallback or Scene policy updates the preview automatically; there is no Apply Group Conversion prerequisite. Deliberate per-document overrides and exclusions are retained. Remaining exceptions are compact expandable rows; they do not display all source attribute controls by default. Missing documents are not invented or silently linked to namesakes.

The same private Vault, Chronicle isolation, source preservation, copy-only import, saved-copy resume and relationship-review workflow from qa.4.3 remain. No publishing or stable-channel change.

## Check

Use the same TAF ZIP in a clean test world. The proposal must appear on the first preview, before any group controls are used. Check the proposed role/account summary, make only needed corrections, then approve once. With the supplied 1,031-document package and the displayed defaults, the local simulation imports 1,023 documents and leaves 8 missing-reference/dependency exceptions. It preserves 186 compendium Actors, restores one GM Notes record privately, reports no unresolved references among copied data, and creates no duplicate copies on retry. A live Foundry confirmation is still required.
