# QA.4.12 — Profile Manage links stability

The GM profile link manager was added only by delayed render hooks. A newly painted profile initially had no manager, so adding it moved all following Relations cards. Duplicate mount hooks also removed and recreated the details/picker even when link data was unchanged.

Profiles now mount the controls in the existing pre-paint lifecycle. Repeated mounts reuse the live details and select, changing options only when the available targets actually change. Open state, pending selection and focus survive. Existing canonical unlink handlers remain delegated; stale unlink buttons are reconciled without removing the original source navigation button. Non-GM cleanup removes GM controls and preserves canonical navigation. Session and Quest mounting timing remains unchanged.

Native Edge coverage renders the real profile template/styles and link module with nine contact cards. Scenarios include GM/player with/without Entity Context, 40 successive geometry samples, repeated update/render hooks, unchanged DOM identity, focused pending choice, changed option labels, full-render continuity, link removal/readdition, and GM access loss. These UI operations perform no document writes. Related relationship/context/continuity unit tests are also run.

Install the complete local module ZIP, restart Foundry and reload the client. Existing imported characters and relationships need no reimport. Stable remains 1.8.0; no publication.
