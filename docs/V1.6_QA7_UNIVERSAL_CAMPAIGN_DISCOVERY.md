# Adventurer's Tome v1.6.0-qa.7 — Universal Campaign Discovery Foundation

**Stable baseline:** v1.5.0  
**Previous verified USL gates:** qa.1–qa.5 PASS  
**qa.6:** API surface PASS; write execution live-QA remains pending  
**Verified Foundry baseline:** V13.351

## Goal

Start the system-independent campaign discovery layer that can inspect an existing Foundry world and expose a normalized, permission-safe graph without creating duplicate Tome data.

Realm Guard M8 Social Network is the first advanced reference adapter, not a Core dependency.

## New public API

`game.modules.get("adventurers-tome").api.discovery`

Contract:

`adventurers-tome-universal-campaign-discovery` v1

Public methods:

- `scan(options?)`
- `snapshot()`
- `get(keyOrUuid)`
- `relationshipsFor(keyOrUuid)`
- `unresolved()`
- `audit()`

All qa.7 discovery is read-only.

## Core discovery sources

Generic Tome Core discovers:

- Actors
- Items
- JournalEntries
- JournalEntryPages
- Scenes
- Folders
- visible Compendium index entries

The Universal Document Registry remains canonical for live World documents.

Folder hierarchy is preserved as structural `contains` relationships and as `foundry.folderPath` metadata.

## Adapter capability

Adapter API v1 gains additive capability:

`entityDiscovery`

An adapter may return generic:

- entities
- relationships
- provenance
- source visibility
- system metadata

Core does not know any reference-system storage model.

## Generic entity shape

Representative shape:

    {
      key,
      kind,
      name,
      canonicalUuid,
      state,
      authority,
      visibility,
      provenance,
      foundry,
      attributes,
      system
    }

Initial states:

- `resolved` — canonical live World document exists
- `compendium` — known reference entry in a visible Compendium
- `unresolved-reference` — adapter supplied a UUID Tome cannot currently resolve
- `unresolved` — semantic entity has no canonical UUID yet

## Generic relationship shape

Representative shape:

    {
      key,
      kind: "relationship",
      from: { key, canonicalUuid },
      to: { key, canonicalUuid },
      role,
      status,
      origin,
      authority,
      visibility,
      provenance,
      attributes,
      system
    }

Core does not prescribe the source system's role/status/origin enums. Adapters normalize them into portable strings while retaining source metadata under `system`.

## Canonical merge rule

When an adapter entity supplies a `canonicalUuid` that already exists in World/Compendium discovery:

- do not create a duplicate entity
- merge adapter provenance and semantic attributes into the canonical discovered entity
- canonical UUID identity wins

Adapter-only entities without a resolved canonical UUID remain unresolved candidates.

## Realm Guard reference adapter

The Realm Guard adapter consumes the system-owned public runtime API:

`game.realmGuard.core.m8.social.snapshot(actor)`

It maps M8 Social Network:

- PersonRecord → generic `person` entity
- Relationship → generic relationship edge
- `actorUuid` → canonical UUID when linked
- profession / people / location → generic attributes
- role / status / origin / history → normalized relationship metadata
- M8 gameplay authority remains preserved as source metadata

Tome Core never calls `game.realmGuard` directly.

## Privacy boundary

Discovery must not increase permission.

For World documents, Tome only discovers documents the current user can OBSERVE.

Adapter discovery is invoked only for readable source documents.

Compendium discovery is limited to packs visible to the current user.

No GM Private Vault data is part of this layer.

## Automatic scan

qa.7 schedules a read-only discovery scan:

- at Foundry ready
- after Universal Document Registry rebuilds

The scan may also be invoked manually.

No create/import/write action is performed by discovery.
