# v1.7.0-qa.20 — Canonical Convergence & Campaign Links

**Baseline:** v1.7.0-qa.19  
**Foundry baseline:** V13.351  
**Scope:** converge explicitly created/linked Campaign Intelligence entities into persistent Session/Quest Campaign Links after canonical identity is verified.

## Goal

Complete the next controlled graph step:

```text
GM Confirm / Link Existing
→ canonical target UUID
→ persistent Session/Quest Campaign Link
→ reciprocal campaign reference
→ future Discovery sees canonical identity
```

All writes still require explicit GM action.

## Persistent link behavior

### Actor / Character / NPC target

The Session / Quest stores:

- canonical Actor UUID in `campaignEntityLinksV1.actorUuids`
- compatibility Actor id in `flags.adventurers-tome.links.actors`

The Actor receives a reciprocal Session or Quest id in Tome's existing `links` structure.

### Journal-backed World target

The Session / Quest stores:

- canonical target UUID in `campaignEntityLinksV1.entityUuids`
- compatibility World id in `flags.adventurers-tome.links.world`

The World Journal receives a reciprocal Session or Quest id in Tome's existing `links` structure.

This keeps existing Tome presentation compatible while adding canonical UUID-backed identity.

## Create & Link

qa.19 creation now continues one step further:

```text
Confirmed candidate
→ Create & Link
→ create via existing Quick Create/native provider
→ require canonical UUID
→ persist Campaign Link to current Session / Quest
→ record campaignLinked=true in learning
→ refresh Discovery
```

If entity creation succeeds but Campaign Link persistence fails, the created entity is not silently deleted. The UI warns the GM and returns the link error for review.

## Link Existing

`Link Existing` now does both:

1. stores the explicit campaign-learning identity mapping
2. persists the real Session/Quest Campaign Link to the selected canonical target

No automatic linking occurs from model confidence alone.

## Convergence verification API

```js
const c = game.modules
  .get("adventurers-tome")
  .api.campaignEntityCreation;

await c.verify({
  text:"Ravenmoor Valley",
  sourceUuid:"JournalEntry...."
});
```

Expected result after successful Create & Link:

```js
{
  targetResolves: true,
  canonicalVisible: true,
  campaignLinked: true,
  converged: true
}
```

## Primary QA

Use a candidate already created in qa.19 or create one new candidate in the current QA Session.

### Test A — Created World entity

1. Confirm a Location/Faction/Item/Lore candidate.
2. Click **Create & Link**.
3. Complete normal Tome creation.
4. Refresh/open the Session.

Expected:

- created entity exists in its canonical World folder
- it is no longer Possible New
- it appears as an existing campaign identity
- Session World Links include it
- created World profile sees the Session in Campaign Links
- learning record has `campaignLinked=true`

### Test B — Created Actor/NPC

1. Confirm a Character/NPC candidate.
2. Create through normal Quick NPC/native provider.
3. Reopen the Session.

Expected:

- Actor UUID is canonical
- Session Character links include the Actor
- Actor profile sees the Session
- Campaign Intelligence no longer treats the exact name as new

### Test C — Link Existing

Use a candidate alias/variant and select a visible existing target.

Expected:

- learning stores candidate -> target UUID
- Session/Quest gets a persistent Campaign Link to target
- target receives reciprocal Session/Quest reference
- no new entity is created

## Safety

qa.20 MUST NOT:

- create or link from model confidence alone
- write a Campaign Link without explicit GM action
- fabricate a target UUID
- silently create duplicates
- delete a successfully created entity if link convergence later fails
- weaken Foundry permissions

## PASS gate

qa.20 passes when explicit Create & Link / Link Existing actions persist canonical Session/Quest Campaign Links, reciprocal references are visible through existing Tome surfaces, and `verify(...).converged` returns true for a successfully linked target.
