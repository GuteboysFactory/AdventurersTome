# Adventurer's Tome v1.6.0-qa.1 — Universal Semantic Layer Foundation

**Stable baseline:** v1.5.0
**Verified Foundry baseline:** V13.351
**Architecture:** `docs/UNIVERSAL_SEMANTIC_LAYER_ARCHITECTURE.md`

## Goal

Start USL with a deliberately small, read-only vertical slice. This build does not implement write-back, creation, World Auto-Build or broad schema crawling.

It establishes a public semantic API, Semantic Catalog v1, permission gating before resolution, adapter-backed semantic reads, normalized provenance/authority/visibility metadata, safe generic Foundry identity fallback, and the first identity/relationships/traits vertical slice.

## Public API

`game.modules.get("adventurers-tome")?.api?.semantic`

Expected methods: `catalog()`, `getCatalogEntry(id)`, `resolve(source, semantic, options?)`, `resolveMany(source, semantics, options?)`, `inspect(source, options?)`, `audit()`.

Contract: `adventurers-tome-universal-semantic-layer`, version `1`, catalog version `1`.

## Semantic Catalog v1

Initial semantics: `identity`, `identity.name`, `identity.type`, `identity.ancestry`, `identity.class`, `identity.background`, `identity.biography`, `relationships`, `traits`.

Aliases exist for discovery/design purposes but never create authoritative truth by themselves.

## Adapter capability

The v1 Adapter API gains the additive `semanticRead` capability.

Adapter semantic results must explicitly provide `visibility`. Results without visibility are rejected by USL.

## Normalized fact

Resolved facts carry: semantic, status, authority, confidence, provider, sourceUuid, sourcePath, visibility, writable, data.

Locked rule: **No semantic fact without provenance, authority and visibility.**

## Privacy model

Resolution begins with a permission gate. Non-GM users must be able to observe the source before semantic resolution occurs.

Visibility rules: `public`, `player-visible`, and `source` still require observable source access; `owner-only` requires OWNER; `gm-only` is GM only. Unknown or empty visibility is rejected.

Players receive `unavailable` rather than hidden semantic facts.

## Generic fallback

qa.1 is intentionally conservative. Only `identity`, `identity.name`, and `identity.type` resolve generically from Foundry. Relationships, traits, ancestry, class, background and biography require an explicit semantic provider.

    ({
      identity:await s.resolve(actor,"identity"),

Expected: resolved, authority `foundry`, provider `tome-generic-foundry`, visibility `source`, correct Actor UUID.

## QA D — conservative unavailable fallback

Without a semantic adapter, `await s.resolve(actor,"relationships")` and `await s.resolve(actor,"traits")` must return unavailable and must not guess `actor.system` data.

## QA E — semantic adapter

Register:

    const a = game.modules.get("adventurers-tome").api.adapters;
    a.register({
      id:"qa-semantic", apiVersion:1, documentTypes:["Actor"], capabilities:["semanticRead"],
      semanticRead:({semantic}) => {
        if (semantic === "relationships") return {semantic, authority:"system", visibility:"source", sourcePath:"system.relationships", data:[{name:"QA Ally",type:"ally"}]};
        if (semantic === "traits") return {semantic, authority:"system", visibility:"gm-only", sourcePath:"system.traits", data:["QA Secret Trait"]};
        return null;
      }
    });

As GM, both semantics should resolve through provider `qa-semantic` with sourcePath and visibility preserved.

## QA F — player visibility

On a real player client with the same test adapter and an observable Actor: source-visible relationships may resolve; gm-only traits must be unavailable. Against an Actor the player cannot observe, all semantic results must be unavailable.

## QA G — explicit visibility required

Register a semantic result without `visibility`. USL must ignore it and return unavailable.

## QA H — inspect

`await s.inspect(actor)` must list only semantics resolvable for the current user, contain no raw data payload, and omit gm-only semantics for players.

## QA I — regression

Verify GM Dock release gate, Universal Document convergence, takeover misses 0, and Adapter API audit in a clean session.

## PASS criteria

qa.1 passes when the semantic API is present, generic identity resolves without schema guessing, adapter-backed relationships/traits preserve provenance/authority/visibility, player permission and gm-only filtering prevent disclosure, and v1.5/v1.4/v1.3 regressions remain green.
