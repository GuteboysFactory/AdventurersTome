# Adventurer's Tome v1.2.0-qa.9 — Source Parity hardening gate

Baseline: Foundry V13.351  
Stable baseline: v1.1.15  
Verified foundation: v1.2.0-qa.2 Source Parity I + qa.5 Private Vault Browser

## Purpose

qa.9 is the late v1.2 hardening build. It does not change the canonical architecture. It verifies the already established UUID-backed Actor/Journal/Tome model under rename, move, delete, reload, permissions and multi-client use, while removing the Foundry V13 deprecated global TextEditor access and tightening World profile body typography.

## A — TextEditor compatibility

1. Open Tome.
2. Open/edit Journal-backed World, Quest or Session text.
3. Save and finish editing.
4. Repeat after reload.
5. Check console.

PASS: no Adventurer's Tome warning saying the global `TextEditor` namespace is deprecated. Journal enrichment/editing still works.

## B — Known Information typography

1. Open NPC, Item and one other World entry containing Known Information.
2. Verify Known Information body text is normal reference/body copy, approximately 15 px.
3. Verify the Known Information heading remains unchanged.
4. Enter inline edit and finish editing.

PASS: body copy does not jump back to oversized display text before, during or after inline authoring.

## C — Rename / move identity

Using an Actor-backed World NPC with Private Vault notes:

1. Rename Actor in Foundry.
2. Verify Tome updates.
3. Move Actor to another Actor folder.
4. Move helper Journal to another Journal folder.
5. Reload.

PASS: same UUID relationship remains; Tome, Actor and Private Vault still resolve to the same logical source.

## D — Missing source / no name relink

1. Delete a linked Actor.
2. Verify Tome keeps the entry and missing-source state.
3. Create another Actor with the old name.
4. Reload.

PASS: the old Tome entry does not silently relink by name.

## E — Live refresh without navigation reset

1. Open an Actor-backed NPC in Tome.
2. Change Actor name/image from its Foundry sheet while Tome stays open.
3. Change a Journal-backed Known Information page from Foundry while Tome stays open.

PASS: relevant open content refreshes, Tome remains on the same logical entry, and no repeated render loop occurs.

## F — Multi-client / permissions

With GM + Player connected:

1. GM edits public Actor/Journal content.
2. Player verifies allowed public changes appear normally.
3. GM edits Private Vault notes.
4. Player checks the same source.

PASS: public parity converges; Private Vault controls/content never appear for Player.

If available, repeat authoring regression with Section Editor / Entry Editor roles.
