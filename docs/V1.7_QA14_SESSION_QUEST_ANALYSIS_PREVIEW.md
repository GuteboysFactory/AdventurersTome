# v1.7.0-qa.14 — Session / Quest Analysis Preview

**Baseline:** v1.7.0-qa.13  
**Foundry baseline:** V13.351  
**Scope:** present Campaign Intelligence directly inside Session / Quest detail views as a GM-only, read-only analysis surface.

## Goal

Move Campaign Intelligence out of the console and into Tome without enabling writes.

For the currently open Session / Quest, show:

- known mentions detected in the text
- possible new entities detected by qa.12/qa.13
- entity type
- confidence
- mention count
- explicit read-only status

No Confirm / Ignore / Create actions exist in qa.14.

## UI placement

### Session

The panel mounts in the selected Session detail after normal campaign-link sections and before the Chronicle excerpt / Open Full Session controls.

### Quest

The panel mounts in Quest Detail before the existing Quest Record / Campaign Links grid.

## Known mentions

Known mentions come only from `campaignMentionDiscovery.mentionsForSource(uuid)`.

The preview collapses repeated representations by canonical target where possible and shows the direct source-text detection result rather than expanding the broader campaign relation graph.

## Possible new entities

Possible new entities come only from:

```js
campaignNewEntityDiscovery.candidatesForSource(uuid)
```

This preserves qa.13 precision and type classification.

## GM-only / read-only contract

The preview:

- is shown only to GM
- does not create Actors / Journals / Items
- does not write Campaign Links
- does not mutate Session / Quest text
- exposes no Confirm / Ignore / Create actions
- defers mounting/refresh while live authoring is active

## Public API

```js
const p = game.modules
  .get("adventurers-tome")
  .api.campaignAnalysisPreview;
```

Available:

```js
p.snapshotForSource(uuid);
p.refresh();
p.audit();
```
