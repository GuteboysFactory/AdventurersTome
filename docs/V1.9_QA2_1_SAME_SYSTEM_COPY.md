# 1.9.0-qa.2.1 — Realm Guard → Realm Guard

This is a local hotfix to the qa.2 phase. It does not start qa.3 or change the stable 1.8.0 channel.

The user's recording showed an older qa.2 layout listing every ready Journal and a version-compatibility review per Actor. Several local builds had reused the same qa.2 version. This hotfix has a distinct version and a visible **BUILD 1.9.0-qa.2.1** header.

Same-system copies keep source Actor/Item type and system data. A version-label difference is a single overview notice, not a review decision per document. Before creating copies, the current target system's native data models validate Actor and embedded/world Item data on isolated clones. Invalid data or unsupported types remain exceptions. Cross-system conversion still uses its own adapter.

Original-source metadata (`_stats`, `flags.core.sourceId`, and earlier `migrationV1` archives) remains available in the raw source archive but is not treated as a live dependency on old-world documents. Actual Contact/Actor and document links remain dependencies and are remapped by identity, not name.

The same system's flags stay on its copies; unrelated module flags stay archived. Same-system Scene token overrides are preserved, including base Item/effect ID remapping. Realm Guard inventory container references are remapped to copied bag IDs. Cross-system token overrides remain advisory/review data and are not interpreted as target mechanics.

## Live check

1. Replace the installed module with this versioned ZIP, restart/reload Foundry and use Ctrl+F5.
2. Confirm **BUILD 1.9.0-qa.2.1** at the top of Migration Toolkit.
3. In an empty Realm Guard destination, read the existing exported package. No new export is needed solely for this fix.
4. The overview should show counts and real exceptions. Ready Characters/NPCs/Items/Journals should not have individual approval cards. The taf type selector should not appear.
5. Move ready and reviewed copies once. Check Character/NPC types, a linked Contact, a bag with contents, and any scene token override. Copies remain GM-only until user/ownership migration in qa.3.

Automated tests simulate Realm Guard → Realm Guard with differing QA versions and native validation callbacks; browser creation is mocked, not a live Foundry server test.

Implementation reference: [Foundry 13 DataModel validation](https://foundryvtt.com/api/v13/classes/foundry.abstract.DataModel.html#validate).
