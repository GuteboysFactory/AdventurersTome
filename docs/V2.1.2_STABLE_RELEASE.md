# Adventurer’s Tome 2.1.2

This release brings the QA.1–QA.8 campaign improvements to the stable channel.

## Group and player-facing campaign information

Checking **Group member** automatically creates reciprocal **Party Member**
relationships and shares the public Tome profiles with the group's players.
A group player has an assigned group character or Owner permission on one.
Tome grants native **Limited**, preserving existing Observer/Owner permissions;
this does not grant full access to another player's character sheet. Public
Bio, facts and relationships are readable; GM-only facts and Vault notes stay
private. An active GM client performs synchronization. Leaving Group removes
managed relationships and automatic access, preserving manually authored
history and independently granted permissions.

PCs stay in Group and Session Characters, outside World/NPC lists. Incorrect
version-1 automatic PC cards are archived privately rather than deleted. The
original Actors, page text, private notes and session links remain intact.

Confirmed NPC links in shared Sessions create limited **name/portrait** World
cards. Full NPC sheets, biographies and statistics are not shared automatically.
GM **Release player information…** explicitly publishes additional description.
Hiding/unlinking the source revokes automatically managed card access.

**Show to players** now grants the Foundry permissions needed for the entry.
Imported Sessions and shared Quests become player-visible after private parts
are safely separated. Personal Quests remain restricted to their recipients.
Trusted Player imports require an authenticated active GM for the sharing step;
a pending private import can be retried without discarding protected content.

## Faster campaign work

- Campaign Tools → **NPCs, Contacts & Items**: search, exact type/subtype filters,
  bulk native ownership changes and Undo.
- **Quick Search**: search world/compendium content, insert references, open
  documents and use supported GM item/token placement actions.
- Sessions retain the session list beside the reader. Campaign Explorer can
  collapse independently in Sessions and Quests, leaving an expand icon.
- My Chronicle's note dialog has a larger searchable linked-entry picker and
  scrolls on smaller screens; Chronicle remains in its own tab.
- Quiet **Q/S** launcher badges indicate unread accessible Quests and Sessions.
  Private reminders support time, Scene, snooze and completion. GM reminders
  include an optional configurable New session prompt.
- GM canvas context menu: **Place existing NPC or PC…**. Players can remove their
  own assigned token through token controls, retaining the original Actor.

## Private Vault without an extra password

New GM Vaults use **account access**, opening without a separate passphrase.
Notes and images are stored in the GM's own Foundry user settings. Other
ordinary players and GMs do not read that account store through Tome, but
**server-file administrators can read account-mode data**. It is not encryption
against the server administrator or protection against malicious same-origin
modules.

Existing encrypted Vaults keep their original encryption until their GM
explicitly chooses **Vault access → account access**. If the old Vault is
unlocked, saved notes and image bytes can be copied into account access. The
original encrypted archive is retained and can be reopened separately. With a
forgotten passphrase, account access starts a separate store; it cannot recover
the still-encrypted content. Preserve your old passphrase or remembered device
key if you need that archive.

Encrypted Vault operation now supports remote HTTP origins using bundled local
crypto workers. This removes the HTTPS/localhost-only unlock restriction; it
does not protect HTTP delivery from network tampering. Selected-content text
and image whispers retain encrypted delivery. Historical whisper keys remain
device-bound: keep the receiving browser profile/site data. Chronicle encryption
and Vault encryption are separate features.

## Upgrade

Back up the world and previous module, update the existing **adventurers-tome**
module through the stable manifest, restart Foundry and refresh each client
with **Ctrl+F5**. Log in as GM with Tome enabled first to run synchronization and
safe PC-card archiving. Do not enable TestAI alongside Tome. Existing campaign
sources do not need to be imported again. Rollback requires the corresponding
world backup as well as the previous module.

Validated with **566 production tests**, **52 Vault tests** and targeted
multi-client Foundry VTT **13.351 / RealmGuard 1.14.0-qa.4** checks. Foundry V14
and other systems have not been directly verified. The shipped runtime matches
the locally tested QA.8 payload apart from the stable manifest/version metadata.
