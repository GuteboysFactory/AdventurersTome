# v1.7.0-qa.4 — Projection-aware Identity Resolution

**Baseline:** v1.7.0-qa.3  
**Foundry baseline:** V13.351  
**Scope:** Campaign Mention identity resolution only

## Live QA finding

Session/Quest mention discovery correctly found plain prose `Aldari`, but the resolver returned `ambiguous` because Campaign Discovery exposed both:

- the canonical Foundry Actor `Aldari`
- a Tome-generated World Journal Contact named `Aldari`

Live inspection confirmed that the Journal is an active semantic Contact projection whose:

```text
semanticProjection.linkedUuid
```

is exactly the canonical Actor UUID.

These are two representations of one campaign identity, not two independent identities.

## Fix

The Campaign Mention resolver is now projection-aware for active Tome Contact projections.

A Journal representation is collapsed onto its linked canonical target only when all of the following are true:

1. the entity is a World JournalEntry
2. it carries `flags.adventurers-tome.semanticProjection`
3. `projection.kind === "contact"`
4. the projection is active
5. `projection.linkedUuid` is present
6. that linked target is visible in the current viewer-scoped Campaign Discovery snapshot

The linked canonical entity becomes the resolver representative.

## Safety boundaries

This does **not** weaken the same-name rule.

Two genuinely separate Actors named the same thing remain separate candidates and still resolve as:

```text
ambiguous
same-name-is-not-same-identity
```

A projection with a missing, hidden, inactive or unresolved linked target is not collapsed.

Name-only evidence still does not auto-link. Projection collapse removes duplicate representations; it does not turn a prose name into deterministic identity evidence.

## QA A — Aldari projection collapse

With the known Aldari Actor + active semantic Contact projection, run:

```js
const api = game.modules.get("adventurers-tome").api.campaignMentions;

api.resolve(api.createCandidate({
  text: "Aldari",
  kindHint: "unknown"
}));
```

Expected:

- decision = `review`
- selectedTarget = null
- candidates length = 1
- candidate target canonicalUuid = Aldari Actor UUID
- candidate reasons include `projection-linked-identity`
- autoLinkEligible = false
- requiresReview = true
- reason = `display-name-only`

Most importantly: no `ambiguous` result caused solely by Actor + its Contact projection.

## QA B — Discovery path

Create a disposable Session/Quest page containing plain prose `Aldari` and rescan Semantic Mention Discovery.

Expected prose row:

- mentionType = `prose-name`
- text = `Aldari`
- decision = `review`
- exactly one canonical candidate
- no duplicate Journal Contact identity

Explicit Foundry UUID link remains:

- decision = `resolved-canonical`
- autoLinkEligible = true

## QA C — Real duplicate identities remain ambiguous

Create two temporary same-name Actors and resolve their name.

Expected:

- decision = `ambiguous`
- selectedTarget = null
- requiresReview = true
- autoLinkEligible = false
- reason = `same-name-is-not-same-identity`

## QA D — Audit

```js
game.modules.get("adventurers-tome").api.campaignMentions.audit()
```

- `projectionCollapseRequiresActiveContact: true`
