# Adventurer's Tome v1.2.0 — Foundry Source Parity I + Contextual Private Vault

Release date: 2026-09-15

## Milestone status

**v1.2.0 is QA-approved for stable release.**

The milestone establishes reliable Foundry↔Tome identity/live parity for the Actor/Journal surfaces already central to Adventurer's Tome, while attaching private GM context to the same stable Foundry identities.

Architecture remains:

> **Foundry Document-backed, Tome-rendered.**

Canonical data rule:

> **If Foundry knows it, Tome uses it. If Tome adds it, Tome extends it.**

Platform policy established during v1.2:

> **v14-first, v13-compatible.**

Foundry V13.351 remains the verified runtime baseline for this release. The manifest permits V14 for compatibility testing, but V14 is not claimed as verified until dedicated V14 QA is completed.

---

## Shipped scope

### Foundry Source Parity I

- Stable explicit UUID identity for Actor-backed Tome World/NPC content.
- Name matching is migration/import fallback only; permanently linked content does not relink by name.
- Foundry Actor rename → Tome updates.
- Tome canonical rename → Foundry Actor updates.
- Actor source-image following plus deliberate Tome image override behavior.
- Live open-view refresh for linked Actor identity updates.
- Rename-, move-, reload- and delete-aware source lifecycle handling.
- Deleted Actor sources are marked missing instead of silently relinking.
- Creating a new Actor with the same name does not steal an old permanent link.
- Loop/reentrancy protection and multi-client convergence verified.

### Known Information parity

- Actor-backed NPC Known Information is stored on Actor extension data and live-synced between Tome and the Foundry Actor sheet.
- Continuous editing survives autosave without closing the editor or losing focus.
- Item Known Information is live-synced between Tome and Foundry Item extension data.
- PC/Group Character Information remains functionally synchronized; visual UX refinement remains non-blocking future polish.
- Actor-sheet role precedence prevents a World-backed NPC from also receiving the competing PC/Group Character Information panel.

### Contextual Private Vault

- UUID-backed v2 Private Vault storage.
- GM-only contextual notes attached to canonical Foundry identities.
- Same contextual record available from Tome and supported Foundry sheets.
- Campaign-wide Private Vault Browser with search/filtering and canonical Actor/helper-Journal deduplication.
- Vault context survives rename, folder move and reload.
- Missing-source handling remains safe.
- Player clients do not receive or expose GM-private vault content.

### World profile / authoring polish

- Accepted World profile layout with 225×225 hero image.
- Facts use the wide hero/header area.
- Known Information is the sole player-facing prose block beneath the World header.
- Simplified World actionbar with grouped player-facing actions and GM Tools menu.
- Hero image FilePicker path now uses modern namespaced Foundry APIs through a central platform boundary.

### Foundry platform boundary

- Added a central Foundry platform compatibility layer.
- New platform-sensitive work prefers modern namespaced APIs.
- No new dependence on deprecated global FilePicker APIs.
- Platform-version divergence should be isolated in the compatibility layer instead of campaign/domain code.
