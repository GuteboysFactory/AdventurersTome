# Adventurer's Tome v1.2.0-qa.5 — Private Vault Browser + Contextual Backlinks QA

## Baseline

- Stable baseline: `v1.1.15`
- Verified parity baseline: `v1.2.0-qa.2`
- Private Vault Dialog/header polish: `v1.2.0-qa.3` / `qa.4`
- Build under test: `v1.2.0-qa.5`
- Foundry baseline: `13.351`

## Scope

qa.5 adds a GM-only campaign-wide Private Vault Browser without changing the verified UUID-backed storage model.

The browser:

- groups alias records around the canonical Foundry source;
- lists all private contextual notes by source;
- supports search and source-type filters;
- supports Pinned-only and Open-only filtering;
- derives contextual relationships/backlinks from existing Tome link flags;
- opens linked Foundry sources from the browser;
- remains read-only as a browser; editing continues through the already verified contextual/Actor Private Vault workflow.

No new canonical campaign relationship model is introduced.

## Gate A — Browser access

1. Open Tome as GM.
2. Verify the new archive/browser icon appears in the GM top actions.
3. Hover it and verify the tooltip identifies Private Vault Browser and shows sensible counts when notes exist.
4. Click it.
5. Verify a non-modal `Private Vault Browser` opens.
6. Verify existing Tome navigation remains usable while the browser is open.

PASS: browser opens without console errors and does not disturb Tome navigation.

## Gate B — Campaign-wide note listing

Prepare private notes on at least three different contexts, preferably:

- one Actor-backed World NPC;
- one Session or Quest;
- one additional World/Rule entry.

Open the browser and verify:

1. all sources with notes appear;
2. note title/body/type/status are correct;
3. pinned state is visible;
4. resolved notes are visually distinguishable;
5. Actor-backed NPC notes are not duplicated as separate Actor + helper Journal browser cards.

PASS: one logical source card per canonical private context.

## Gate C — Search and filters

1. Search for a unique word contained only in one private note.
2. Verify only the matching source remains.
3. Search for a source name.
4. Verify the source is found.
5. Search for a trigger phrase.
6. Verify it is found.
7. Test source filters: Actor, Session, Quest, World, Rule and Other as applicable.
8. Test `Pinned only`.
9. Test `Open only`.
10. Combine search + type + pinned/open filters.

PASS: filtering is immediate, deterministic and does not modify stored notes.

## Gate D — Contextual links/backlinks

Use at least one source that already has Tome links to another campaign object.

Verify:

1. the source card shows `Related / backlinks`;
2. explicit outgoing Tome links are listed;
3. another Tome document that links back to the source is also listed;
4. Actor-backed World entries can derive relationships through their linked helper Journal;
5. clicking a relationship opens the correct underlying Foundry source;
6. rename a related Journal/Actor and reopen the browser;
7. verify the relationship still resolves by document identity rather than stale display text.

PASS: relationships are derived from existing IDs/UUID-backed sources and survive rename.

## Gate E — Missing source behavior

1. Use or create a Private Vault record whose original source becomes unavailable.
2. Open the browser.
3. Verify the record is retained rather than silently discarded.
4. Verify it is clearly marked `Source missing`.
5. Verify no automatic same-name replacement occurs.

PASS: private campaign memory is retained safely when a source disappears.

## Gate F — Privacy — BLOCKING

1. Keep a GM and normal Player client connected.
2. Create/edit a private note as GM containing obvious secret text.
3. Open/reopen Tome as Player.
4. Verify the Player has no Private Vault Browser button.
5. Verify the Player receives/renders none of the private browser contents.
6. Verify ordinary public Tome/Foundry content remains unaffected.

PASS only if browser access and data remain GM-only.

## Gate G — Regression

Verify qa.4 behavior remains intact:

- compact Actor-sheet lock remains in the approved upper-right header position;
- Actor-sheet Private Vault opens with DialogV2;
- contextual Tome Private Vault still opens/saves;
- Actor-backed Tome/Actor private note identity still matches;
- Actor <-> Tome name parity still works;
- source-follow / Tome image override remains correct;
- missing Actor handling remains correct;
- no deprecated legacy Dialog warning returns;
- no recurring console errors.
