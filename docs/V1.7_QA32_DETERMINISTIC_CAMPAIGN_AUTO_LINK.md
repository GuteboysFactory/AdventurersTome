# v1.7.0-qa.32 — Deterministic Campaign Auto-Link

**Baseline:** v1.7.0-qa.31  
**Foundry baseline:** V13.351

## Goal

Tome should behave like an assistant: if a Session or Quest mention already resolves to exactly one existing canonical campaign identity, Tome should create the Campaign Link automatically instead of asking the GM to perform a redundant Link Existing step.

The safety boundary is identity certainty, not a raw confidence percentage.

## Auto-Link rule

A detected Session/Quest mention is eligible only when:

1. the target already exists in the active world
2. the mention has an exact existing-name match
3. Campaign Identity Reconciliation collapses all projections to exactly one canonical identity
4. no unrelated same-name identity remains
5. the target authority is a supported Foundry document:
   - Actor
   - Item
   - JournalEntry
6. the GM has not explicitly suppressed that source/target auto-link by unlinking it

Then Tome writes a normal canonical Campaign Link through:

```js
game.modules.get("adventurers-tome").api.campaignEntityLinks.linkCanonical(...)
```

No separate parallel graph is introduced.

## Link + Mention coexist

Auto-linking does not delete Mention evidence.

For Pale Wardens:

```text
Session 1
WORLD LINKS: 1
Pale Wardens

Pale Wardens
Campaign Links
Session 1

Mentioned In
Session 1
Prose mention · Linked + Mentioned
```

The Link records the canonical campaign relationship.

The Mention records where and why Tome knows about it.

## Ambiguity lock

Example:

```text
Gunther
Actor A
Actor B
```

If both unrelated identities match the same mention:

- auto-link is forbidden
- no target UUID is selected arbitrarily
- Mention evidence remains Ambiguous
- GM review remains available

## No auto-create

If a detected name has no existing canonical identity:

- Tome does not create a new Actor/Item/Journal
- Tome does not guess a target
- existing Possible New / GM Review behavior remains authoritative

## Item authority support

qa.32 extends Campaign Entity Links to accept canonical Foundry Item UUIDs.

This is required because qa.29 backend parity may present a real Foundry Item through a managed Tome World Journal projection.

Canonical authority remains:

```text
Item.<id>
```

Tome presentation maps that authority back to the managed World projection when rendering World Links.

## GM unlink suppression

A deterministic auto-link should not fight the GM.

If a GM manually unlinks a relationship that was created by Deterministic Auto-Link:

- Tome records a source/target suppression
- future scans do not immediately recreate the link
- a later explicit manual re-link clears that suppression

## Provenance

Auto-link provenance is retained on the source Session/Quest under:

```text
flags.adventurers-tome.campaignAutoLinkEvidenceV1
```

The record includes:

- target UUID
- target name
- mention text
- source Page UUID
- decision reason
- projection reconciliation state
- link timestamp

## Runtime API

```js
const api = game.modules.get("adventurers-tome").api.campaignDeterministicAutoLink;

api.audit();
api.resolveIdentity({ text:"Pale Wardens", sourceUuid:"JournalEntry.<session>" });
await api.scan({ reason:"manual-qa", rescan:true });
```

## Clean QA fixture

Session text:

```text
Arne, Baran and Citronimus travelled through Ravenmoor Valley after receiving aid from the Pale Wardens.
Gunther warned them that the Ember Seal was still missing.
```

Existing campaign identities:

- Pale Wardens — one Faction
- Ravenmoor Valley — one Location
- Ember Seal — one Item
- Baran — one Actor
- Gunther — two unrelated Actors

Expected after reload/scan:

```text
Pale Wardens     AUTO-LINK
Ravenmoor Valley AUTO-LINK
Ember Seal       AUTO-LINK
Baran            AUTO-LINK
Gunther           AMBIGUOUS / NO AUTO-LINK
```

The exact number of links depends on which names Semantic Mention Discovery actually emits. Auto-Link never bypasses the mention-detection gate.

## PASS gate

qa.32 passes when:

1. uniquely resolved existing mentions create canonical Campaign Links automatically
2. Session/Quest counters update without GM Link Existing
3. reciprocal World/Actor surfaces show the relationship
4. Mentioned In remains and shows Linked + Mentioned
5. two unrelated Gunther identities remain unlinked
6. no new campaign entity is automatically created
7. manual unlink of an auto-link prevents immediate re-link
8. canonical Item-backed World entries can participate without replacing Item UUID authority

## Release workflow hardening

The release workflow is also restricted so the `release/READY` push trigger can publish only from `main`.

Feature branches may still be prepared and reviewed, but they must not create release tags before merge.
