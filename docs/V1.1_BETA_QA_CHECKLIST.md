# Adventurer's Tome v1.1 Beta QA Checklist

This checklist is the release gate for v1.1 beta/RC builds. The goal is regression testing, not feature expansion.

## 1. GM baseline

- Open Tome and verify Home, World, Quests and Sessions render normally.
- World catalog keeps the approved rich card presentation.
- Campaign Explorer remains persistent while selecting folders, Show all, expand/collapse and scrolling.
- Create a subfolder in Explorer.
- Rename the subfolder.
- Drag an entry into and out of the subfolder.
- Drag a non-root folder by its grip.
- Verify World / Quests / Sessions root folders cannot be renamed, deleted or moved.
- Verify non-empty folder deletion is blocked.
- Verify empty folder deletion succeeds.
- Create a World entry in a canonical World category and verify category inheritance.
- Rename the entry from Tome entry management.
- Open the entry in Tome and open its Foundry source.
- Delete only a disposable test entry and confirm the permanent-delete guard appears.

## 2. Journal Page authoring

- Open an entry with multiple Journal Pages.
- Verify Journal Pages navigator count, labels, type icons and Primary marker.
- Jump between rendered pages from the navigator.
- Open Page Manager.
- Create Text, Image, Video and PDF pages as applicable.
- Rename a page and verify autosave.
- Reorder pages with arrows and drag/drop.
- Duplicate a disposable page.
- Move a disposable page to another Journal.
- Change player access on a page.
- Delete a disposable non-primary page.
- Verify the primary page remains protected.
- Use the Page Manager jump action back to Tome.

## 3. Inline authoring / save state

- Edit title, summary and body where Tome exposes inline editing.
- Verify Editing -> Saving -> Saved state behaves normally.
- Reload and verify the Journal-backed content persists.
- Verify blank Text pages remain directly writable in Tome.
- Verify World summary does not duplicate after repeated edits/reloads.

## 4. Section Editor

With a non-GM user assigned as a Section Editor for one section:

- Verify a Tome Editor indicator is visible.
- Create a folder inside the delegated section.
- Create an entry inside the delegated section.
- Rename an allowed folder.
- Move an allowed folder within the same section.
- Move an entry within the same section.
- Edit entry content and Journal Pages.
- Verify section root protections still apply.
- Verify the user cannot manage structure in a section they were not delegated.
- Verify GM Notes/private GM workspace remain unavailable.

## 5. Entry Editor

With a non-GM user assigned only as Entry Editor for one entry:

- Verify the assigned entry can be edited.
- Verify its editable Journal Pages can be authored through Tome.
- Verify section-level folder tools are unavailable.
- Verify creating arbitrary section entries/folders is unavailable.
- Verify permanent entry deletion is unavailable.
- Verify other non-owned entries remain read-only according to normal Foundry access.
- Verify GM Notes/private GM workspace remain unavailable.

## 6. Normal Player

With a player who has no Editor role:

- Verify no folder-management, entry-management or authoring controls are shown.
- Verify only content permitted by Foundry/Tome access is visible.
- Verify hidden/private Journal Pages do not appear.
- Verify GM Notes/private GM workspace never appears.
- Verify navigation, Explorer filtering and readable page navigation still work.

## 7. Multi-source / existing campaign data

- Verify more than one Adventurer's Tome-style source root can appear without collapsing into one assumed root.
- Verify custom World folders preserve existing category semantics unless moved into a canonical category folder.
- Verify existing campaign Journals are not duplicated or automatically re-created.
- Verify Foundry Journal/folder data remains the source of truth after Tome operations.

## 8. Packaging / release gate

CI must pass all of the following before a beta/RC release is accepted:

- `module.json` parses and has matching release URLs.
- Every manifest-listed ES module, stylesheet and language file exists.
- Every manifest-listed JavaScript module passes `node --check`.
- Language JSON files parse successfully.
- Manifest arrays contain no duplicate file references.
- Retired alpha Explorer/tree/workspace prototypes are absent.
- Built ZIP contains all manifest-listed runtime files and required project files.
- Built ZIP excludes `.git`, `.github`, `release`, `dist` and retired prototype files.
- ZIP integrity test passes.

## Release decision

A beta/RC build is accepted only when the release workflow is green and the manual role matrix above has no blocker or data-loss regression. Cosmetic issues may be logged separately; authoring, permissions, persistence, Explorer stability and destructive-operation guards are release blockers.
