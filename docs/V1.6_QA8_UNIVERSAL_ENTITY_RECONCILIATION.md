# Adventurer's Tome v1.6.0-qa.8 — Universal Entity Reconciliation

**Stable baseline:** v1.5.0  
**qa.7:** Universal Campaign Discovery PASS  
**Verified Foundry baseline:** V13.351

## Goal

Classify unresolved discovery entities against existing World and Compendium candidates without auto-linking or creating anything.

qa.8 answers:

> "What might this unresolved entity already be?"

It does not answer:

> "Change the campaign to make it so."

## Public API

`game.modules.get("adventurers-tome").api.reconciliation`

Contract:

`adventurers-tome-universal-entity-reconciliation` v1

Methods:

- `analyze(options?)`
- `snapshot()`
- `resultFor(keyOrUuid)`
- `audit()`

Flags:

- `readOnly: true`
- `autoLink: false`

## Classifications

- `exact`
- `high-confidence`
- `possible`
- `ambiguous`
- `no-match`

## Safety rules

- canonical UUID equality is the only true exact match
- name equality alone never auto-links
- name-only candidates remain possible
- high-confidence requires exact normalized name plus corroborating evidence
- close competing candidates become ambiguous
- no Foundry/Tome mutation is performed
- no candidate is written back to the unresolved source
- World candidates sort ahead of Compendium candidates only as a tie-break preference, not as authority

## Candidate evidence

qa.8 may currently use:

- normalized exact name
- strong name similarity
- profession
- culture/people
- location
- Foundry folder/location context
- canonical UUID when already supplied

This is deliberately conservative.

## QA C — inspect real unresolved results

    snap.results.map(x => ({
      name: x.entity.name,
      classification: x.classification,
      confidence: x.confidence,
      selected: x.selectedCandidate?.name ?? null,
      candidates: x.candidates.map(c => ({
        name:c.name,
        scope:c.scope,
        score:c.score,
        reasons:c.reasons.map(r => r.type)
      }))
    }))

Expected:

- unresolved Realm Guard people receive transparent candidate evidence
- exact-name-only matches remain possible unless corroborated
- duplicate/close matches become ambiguous
- no-match remains no-match

## QA D — name-only must not auto-link

Create or use an unresolved person whose name exactly matches an existing Actor but has no corroborating attributes.

Expected:

- classification = possible or ambiguous
- selectedCandidate = null
- autoLinked = false

## QA E — corroborated high-confidence

Use an unresolved entity where name + location/profession/culture corroborate one unique World candidate.

Expected:

- classification = high-confidence
- selectedCandidate is exposed as a proposal
- no canonical link is changed
- no source data is mutated

## QA F — ambiguous candidates

Create/use two plausible candidates with close evidence.

Expected:

- classification = ambiguous
- selectedCandidate = null
- multiple candidates returned
- no mutation

## QA G — World vs Compendium

Where the same name exists in World and Compendium:

- both may appear as candidates
- World has tie-break preference
- Compendium never becomes live campaign authority automatically

## QA H — player permission isolation

Run `analyze({rescan:true})` as a real player.

Expected:

- only candidates present in that player's discovery snapshot are considered
- hidden World documents cannot appear as candidates
- hidden unresolved entities cannot appear
- no GM-only information leaks through candidate reasons/counts

## QA I — lifecycle refresh

After discovery changes because of create/rename/move/delete:

- reconciliation refresh follows the new discovery snapshot
- stale candidates disappear
- new candidates may appear
- no persisted duplicate reconciliation state remains

## PASS criteria

qa.8 passes when Tome can classify unresolved entities against existing campaign/reference data conservatively and transparently, without mutating, auto-linking, or creating anything, while preserving user permissions and canonical UUID authority.


## Semantic-only correction

qa.9 refines the model discovered during qa.8 live testing:

- a system Contact without a Foundry Actor is not automatically unresolved
- such an entity is `semantic-only`
- it remains reconcilable against existing World/Compendium candidates
- name-only matches remain advisory
- no Foundry NPC creation is implied

This correction preserves qa.8's reconciliation safety rules while making the campaign model more accurate.
