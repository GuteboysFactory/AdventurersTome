# QA.4.15 — Player Signals and the resting window

Player Signals defaults to expandable sections for players who actually shared notes with the GM. Headers show player name, signal count and latest share. All · latest first provides a chronological feed. Searching across notes and player names opens matching groups; clearing search restores manually opened groups. Refresh retains the selected view/search/open groups on the current host. Personal Chronicles remain separate and are never requested by the GM Signals renderer.

The main window X minimizes Tome into a bottom dock. Click the Tome dock button or normal launcher to restore. The existing DOM retains pending text, scroll, selected tab and ordinary window size/position. The dock's separate X closes Tome completely. The animation respects reduced-motion preferences. Background render requests are deferred while parked. Clean surfaces refresh on restore; pending drafts remain intact. Explicit navigation to another Tome target still works. Viewport changes constrain the restored rectangle to the screen.

Check mouse and keyboard minimize/restore, several rapid clicks, a typed unsaved note, scrolling, background updates while parked, smaller/larger viewports, complete close and reopen. The dock does not write campaign documents or reset window-size preferences. No new export/import is needed.
