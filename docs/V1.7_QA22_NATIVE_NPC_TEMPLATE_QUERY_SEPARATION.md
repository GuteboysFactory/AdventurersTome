# v1.7.0-qa.22 — Native NPC Template Query Separation

**Baseline:** v1.7.0-qa.21  
**Foundry baseline:** V13.351  
**Scope:** separate the canonical Actor name from the native Quick NPC template search query.

## Live QA finding

qa.21 verified the native creation completion handshake:

```text
Create & Link
→ native Quick NPC Library
→ GM creates Actor
→ onCreated(actor)
→ canonical Actor UUID
→ Campaign Learning
→ Campaign Link
```

A remaining integration UX defect was observed: Campaign Intelligence passed the candidate name (for example `Lady Mereth`) as both the future Actor name and the template search query. Realm Guard therefore opened its Quick NPC Library filtered by that proper name and returned zero template matches until the GM manually pressed Clear.

## Hotfix behavior

Campaign Intelligence now delegates NPC creation with:

```text
Actor name:     Lady Mereth
Template query: <empty>
```

The native library opens unfiltered while preserving the confirmed candidate name as the created Actor name.

## Implementation boundary

- Campaign Intelligence passes an explicit empty `initialQuery` for Character/NPC creation.
- Universal Folder Quick Create now distinguishes an explicitly supplied empty query from an absent query.
- If `initialQuery` is absent, existing callers still fall back to `initialName || name`.
- If `initialQuery` is explicitly empty, native Quick NPC receives an empty search and shows its full template library.
- qa.21 completion-aware waiting remains unchanged.
- Canonical UUID authority remains unchanged.
- No automatic template choice is introduced.
- No confidence-driven write is introduced.

## Primary QA

1. Confirm a Character/NPC candidate such as `Lady Mereth`.
2. Click **Create & Link**.
3. Choose **Character / NPC**.
4. Continue to native creation.

Expected:

- Quick NPC Library opens with all templates available rather than `0 / 443`.
- search field is empty
- candidate name remains the Actor name to be created
- choosing any template creates an Actor named after the candidate
- qa.21 completion callback continues into canonical UUID + Campaign Link convergence
- no manual Clear workaround is needed

## Regression

- Normal Quick NPC use that intentionally supplies a query still filters as before.
- Callers that omit `initialQuery` still inherit the existing name/query fallback.
- Contact/Location/Faction/Item/Lore Create & Link remains unchanged.
- Link Existing remains unchanged.
- all graph writes remain GM-explicit.

## PASS gate

qa.22 passes when Character/NPC Create & Link opens the native Quick NPC Library unfiltered, preserves the candidate as Actor name, creates successfully, and converges through the verified qa.21/qa.20 canonical link chain without a manual Clear step.
