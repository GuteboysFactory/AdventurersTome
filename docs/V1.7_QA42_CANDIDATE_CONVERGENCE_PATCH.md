# qa.42 — Candidate extraction and canonical convergence cleanup

Local test patch on the existing qa.42 branch, based on 3285f2d. No version or publication metadata changes. Language packs and a shared index engine are deferred.

## Root causes and changes

- `campaign-new-entity-discovery.js`: grammatical singletons were incompletely filtered. Leading context words now also participate in singleton filtering; rejected rows remain in diagnostics. Former/retired/local profession modifiers are accepted only in attached person appositions. A following named captain is not evidence that the preceding speaker has that profession. This allows the existing conservative source-name consolidation to keep Orren Hale and his later first-name mentions together. Documentary suffixes and explicitly titled documents provide Item evidence.
- `campaign-confirmed-entity-creation.js`, `assessExistingMatch` / `possibleDuplicates`: whole personal-name fragments are eligible Review choices, never automatic aliases. Existing short-name identities also block automatic creation of a parallel full name. Proven projections are grouped by authority UUID and retain their strongest match. Exact and registered-alias evidence ranks above personal fragments and place prefixes. `automaticType` / `resolveCandidates` recognize attached document-title evidence.
- `adventurers-tome.js`, `campaignDecisionCandidateMeta` / `campaignAnalysisView`: the Contact card's Linked person label now requires identity reconciliation evidence instead of an actor-name fallback. Review ranks identity evidence before contextual scores. Actor/Contact projections with proven links show one canonical choice; independent namesakes remain separate choices.

No campaign-specific names were added to production rules. No existing world identity is renamed, deleted, or merged by this patch. An already-created erroneous short-name identity requires GM review rather than an unsafe automatic repair.

## Regression coverage

`tests/qa42-candidate-convergence.test.mjs` adds 14 tests, including the Session 5 fixture, generic profession/name and document examples, fragment ambiguity, existing short-name protection, proven versus independent Actor/Contact identities, Review defaults and ranking, and reanalysis/reload without parallel identities.

Memory deliberately preserves CREATED as the provenance of an identity originally created from the same source. On reanalysis, the tests require the same target UUID and `single-canonical-identity` resolution reason, with exactly one document; CREATED does not mean a new document was created again.

Validation: all ten regression suites PASS, 406/406 tests. Manifest/workflow URL checks PASS; syntax checks PASS for 87 ES modules and one vendor script. `git diff --check` PASS. Foundry live QA remains to be performed with the local ZIP.
