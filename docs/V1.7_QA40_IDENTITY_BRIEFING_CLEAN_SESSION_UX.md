# v1.7.0-qa.40 — Identity Briefing & Clean Session UX

**Baseline:** v1.7.0-qa.39  
**Foundry baseline:** V13.351

## Goal

Every discovered identity reaches LINKED, CREATED or REVIEW. Make identity briefings readable immediately and retain clean Session/Quest information pages.

## Product rule

> **The decision card must show enough identity context immediately to decide in seconds.**

**More info** is secondary detail, not required reading for routine decisions.

## Identity briefing

Each guided candidate now tries to show a compact, direct briefing using existing Foundry/Tome data.

Possible briefing rows include:

- Role / type
- Occupation
- Faction / group
- Location
- Relations
- Contact entries / linked person
- Previously seen
- profile summary

For World Contacts the briefing explicitly shows the linked Actor when one exists.

If Tome cannot find useful campaign profile data, the card says:

> **No useful campaign profile information recorded yet.**

This is preferred over opaque technical metadata such as internal IDs.

## More info

**More info** remains available for deeper inspection:

- additional Facts
- additional Relations
- previous Campaign Memory mentions

## Session / Quest cleanup

The visible **Tome noticed** blocks are removed from Session and Quest detail views.

No evidence is deleted.

The information remains available through:

- GM Review indicator
- Campaign Tools → Analysis
- Campaign Tools → Memory

Session and Quest remain information-first pages.

## Safety locks

qa.40 does not change:

- canonical UUID authority
- qa.38 decision write behavior
- qa.39 source-focused Analysis
- recommendation thresholds
- source-scoped defer behavior
- Campaign Memory history
- player privacy

The former no-auto-create policy is explicitly replaced for clear Contacts, Locations, Factions and Items. Unknown types, weak identities, possible duplicates and failed writes go to REVIEW. Lore and system-native Actor creation remain manual.

## Discovery → Resolve → LINKED / CREATED / REVIEW

The existing candidate scanner remains read-only. Existing names, short names and weak candidates now reach resolution rather than being filtered out. Unique personal aliases are grouped; a place prefix such as Blackbridge is never silently treated as Blackbridge Watch. The lowercase militia suffix is recognized.

Resolution lives in the existing confirmed-creation API and runs during the existing Campaign Memory sync. It uses canonical identity reconciliation and source-scoped identity authority. Exact safe identities link through Campaign Entity Links. Clear new identities delegate to the existing Quick Create World authoring path without opening a modal. Clear people become system-agnostic Contact journals, not system-native Actors.

Automatic creation requires detection confidence ≥ 0.82, a type margin ≥ 0.20, and strong attached role/title or entity-type vocabulary. Shared name tokens and near spellings are only duplicate-review signals; they never establish canonical identity. Creation runs only on the active GM client, with serialized resolution on each client. New journals and their source facts are GM-private.

Each result, its reason, candidate alternatives and source briefing persist as additive fields in the existing Memory ledger. Existing evidence and historical records are retained. Memory displays the final outcome badge. Review candidates share the existing source-focused Analysis queue and GM review counter. Explicit GM dismissal and unlink suppression remain respected and traceable.

Briefing keeps source wording, including negation and suspicion. Role, faction, location and relationship excerpts are shown directly; short same-subject pronoun continuations can retain subsequent evidence. These excerpts do not create canonical relationship edges. Existing Contact profile facts are prioritized by role, faction, location and relations; previous mentions are no longer truncated by the old six-row briefing cap.

Analysis offers existing-identity selection, explicit creation with a selected type, or existing source-scoped deferral. Manual creation still requires confirmation and uses the existing dialog.

An explicit identity choice is saved for that source, including differently spelled mentions. It does not become a global alias. Undo restores the previous source choice or removes the new choice, while retaining the existing link undo behavior.

## Known limitations

- Detection remains a bounded proper-name/English vocabulary heuristic, not general language understanding. New professions, unnamed people or unusual lowercase names may require REVIEW or manual entry; the outcome guarantee applies to discovered candidates.
- Briefings use attributed source excerpts, which can be longer than curated profile facts. They do not infer authoritative affiliations or relationship edges.
- Shared name tokens intentionally favor review and may flag genuinely different entities. This can include Blackbridge versus Blackbridge Watch.
- Person auto-creation uses Contact journals. Native Actor/NPC sheet creation remains manual through existing providers.
- Tests simulate Foundry APIs; no live Foundry visual QA has been performed in this task.

## qa.40 follow-up — Gunther canonical identity fix

Baseline: `23d07047f354bb70e024c564ab07cfab6f7a0807`. No version bump.

### Root cause and reproduction

The resolver already reconciled Actor-backed NPC/Contact projections, but Session/Quest consumed legacy `links.world` and `links.actors` separately. `getTomeLinks` also read canonical entity and Actor references without reconciling their identity. The Campaign Entity Links boundary accepted a projection Journal UUID as a World target instead of its Actor authority. A source could therefore display the same proven person once in People, places & lore and once in Characters, even when resolution correctly found the Actor. The original 16 tests mocked the link writer and did not exercise this mixed-track presentation.

The new regression first failed on the old implementation: four existing Character Actors, each with an Actor-backed NPC presentation and persisted mixed World/Actor links, appeared in both tracks. It now passes with all four mentions deliberately classified as NPC and with the real Campaign Entity Links functions enabled.

### Exact changed files and functions in this follow-up

| File | Functions / change |
| --- | --- |
| `scripts/adventurers-tome.js` | `getTomeLinks`: use existing canonical identity authority to represent visible Actor-backed person projections once in the Actor track. Both Session and Quest use this shared reader. Keep readable Contact presentation when a player cannot observe its Actor. |
| `scripts/campaign-entity-links.js` | New `atCelAuthorityUuid`; `atCelCanonical`, `atCelLegacy`, `atCelLinkCanonical`, `atCelHasCanonicalLink`: normalize proven projection references into canonical authority before reads, link/unlink writes and membership checks. Writes retain unrelated links and journal data. |
| `scripts/campaign-confirmed-entity-creation.js` | `resolveCandidates`: canonicalize a selected/source-chosen projection UUID before deciding LINKED and storing its target. |
| `tests/qa40-identity.test.mjs` | More realistic mock document updates, real link API harness, six new regressions: mixed Character/NPC presentation; projection link/unlink persistence; same-name unproven identity review and safe source choice; renamed stable projections; private Actor/public Contact; clear militia Faction creation. |
| `docs/V1.7_QA40_IDENTITY_BRIEFING_CLEAN_SESSION_UX.md` | This follow-up report, validation result, canonical decision rule and focused Foundry QA. |

### Canonical decision rule

Reuse the existing identity reconciliation API and source-scoped resolver. Stable Actor UUIDs, managed backend source UUIDs, semantic Contact linked UUIDs and explicit profile Actor IDs establish authority. A source's proven canonical/inline selection or an explicit GM source choice can select among namesakes. A unique reconciled existing identity is resolved before discovery classification. Classification only guides creation after no safe existing identity has been found and duplicate review has passed.

The follow-up introduces no global name merge. Generic relationship links are not evidence that two documents are the same person. Independent documents with the same name and no authoritative projection relationship remain separate and go to REVIEW when unresolved. Proven projections stay stored as presentations of the Actor; no campaign journal is deleted or merged. Their mention remains represented by that Actor rather than silently discarded.

## qa.40 follow-up — NPC presentation is separate from canonical Actor identity

Per's follow-up screenshot shows Gunther as an Adventurer under Characters. The prior canonical identity fix correctly prevented two identities, but Session and Quest still treated every linked Foundry Actor as a party Character, and actorView defaults to the label Adventurer. An Actor is a storage document, not proof of party membership.

Session and Quest now share campaignNarrativeLinks. Characters contains explicit Tome Group members, using the existing groupMember flag and legacy groupActors fallback; an explicit false flag overrides the legacy list. This is independent of game-system Actor types, names and discovery classification. Linked non-members appear under People, places & lore. A readable Journal projection with a proven matching canonical Actor UUID is reused; otherwise an NPC card opens the existing Actor sheet. No new identity or Journal is created, no links or documents are deleted, and canonical resolution remains unchanged. Full canonical person/world lists are displayed rather than cut off at the former 10/12-card limits.
