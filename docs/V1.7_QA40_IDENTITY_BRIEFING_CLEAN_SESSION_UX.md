# v1.7.0-qa.40 — Identity Briefing & Clean Session UX

**Baseline:** v1.7.0-qa.39  
**Foundry baseline:** V13.351

## Goal

Make candidate decisions fast enough for live GM use and remove redundant Tome-noticed clutter from Session/Quest information pages.

## Product rule

> **The decision card must show enough identity context immediately to decide in seconds.**

**More info** is secondary detail, not required reading for routine decisions.

## Identity briefing

Each guided candidate now tries to show a compact, direct briefing using existing Foundry/Tome data.

Possible briefing rows include:

- Role / type
- Occupation
- Faction / group
- Location
- Relations
- Contact entries / linked person
- Previously seen
- profile summary

For World Contacts the briefing explicitly shows the linked Actor when one exists.

If Tome cannot find useful campaign profile data, the card says:

> **No useful campaign profile information recorded yet.**

This is preferred over opaque technical metadata such as internal IDs.

## More info

**More info** remains available for deeper inspection:

- additional Facts
- additional Relations
- previous Campaign Memory mentions

## Session / Quest cleanup

The visible **Tome noticed** blocks are removed from Session and Quest detail views.

No evidence is deleted.

The information remains available through:

- GM Review indicator
- Campaign Tools → Analysis
- Campaign Tools → Memory

Session and Quest remain information-first pages.

## Safety locks

qa.40 does not change:

- canonical UUID authority
- qa.38 decision write behavior
- qa.39 source-focused Analysis
- recommendation thresholds
- no-auto-create policy
- source-scoped defer behavior
- Campaign Memory history
- player privacy

## QA

### A — Two-Gunther fixture

Open the ambiguous Gunther decision.

Expected:

- each candidate shows useful identity context directly when such data exists
- Actor candidate can show role/type, faction/location facts, relations and previous mentions
- Contact candidate identifies itself as Contact and shows its linked Actor when available
- candidate with insufficient metadata clearly says no useful campaign profile information is recorded
- no internal ID is required to distinguish normal candidates

### B — Fast decision readability

Expected:

- GM can compare candidates without opening **More info**
- **This is the one** remains obvious
- ★ recommendation remains visible when present
- context match remains visible

### C — More info

Expected:

- More info expands secondary Facts / Relations / previous mentions
- missing sections are omitted cleanly
- expanding does not write data

### D — Session cleanup

Expected:

- GM Review tile remains
- Tome noticed block is absent
- canonical Quest / World / Character links remain
- Chronicle information remains unchanged

### E — Quest cleanup

Expected:

- GM Review tile remains
- Tome noticed block is absent
- canonical Campaign Links remain unchanged

### F — Data preservation

Expected:

- Campaign Memory still contains Mention evidence removed from the Session/Quest presentation
- Analysis still contains pending decisions
- Memory search still finds historical/active evidence

### G — Player privacy

Expected:

- no GM Review indicator for players
- no decision briefing/candidate metadata leaks
- normal player Session/Quest information remains unaffected

## PASS gate

1. candidate identity context is readable without opening More info
2. Contact/NPC duplicates are meaningfully distinguishable when data exists
3. low-data candidates say so clearly
4. Session/Quest no longer show Tome noticed
5. Campaign Memory evidence remains intact
6. qa.39 source-focused review still works
7. qa.38 guided decisions still work
