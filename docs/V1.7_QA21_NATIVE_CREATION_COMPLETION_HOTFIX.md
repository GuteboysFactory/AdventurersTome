# v1.7.0-qa.21 — Native Creation Completion / Canonical UUID Hotfix

**Baseline:** v1.7.0-qa.20  
**Foundry baseline:** V13.351  
**Scope:** fix the native Quick NPC completion handshake used by Campaign Intelligence Create & Link.

## Live QA finding

qa.20 verified canonical convergence for Journal-backed World entities, but exposed a native Character/NPC integration defect:

```text
Create & Link
→ native Realm Guard Quick NPC Library opens
→ Tome treats the opened library Dialog as the creation result
→ no Actor UUID exists yet
→ canonical UUID resolution fails
```

Observed error:

```text
Creation completed but Tome could not resolve the resulting canonical UUID.
```

The native provider itself already supports an `onCreated(actor)` callback. The missing behavior was on the Tome side: Campaign Intelligence needed a completion-aware delegation contract rather than treating provider UI-open as mutation completion.

## Hotfix behavior

For Campaign Intelligence Character/NPC creation only:

```text
explicit GM Confirm
→ Create & Link
→ open native Quick NPC Library
→ wait while GM selects/creates an NPC
→ native provider calls onCreated(actor)
→ normalize canonical Actor UUID
→ record Campaign Learning identity
→ persist Session/Quest Campaign Link
→ write reciprocal Session/Quest reference
→ refresh Discovery
```

Closing/cancelling the native library before creation resolves as cancellation and must not create Campaign Learning or Campaign Links.

Ordinary Quick NPC use outside this completion-aware path keeps its existing behavior.

## Implementation boundary

- `quickNpc.open({ awaitCreation:true })` waits for a native provider completion callback.
- Universal Folder Quick Create forwards the completion-aware option only when explicitly requested.
- Campaign Confirmed Entity Creation requests completion-aware behavior for Create & Link.
- Native provider open by itself is not treated as a created document.
- Canonical UUID remains the authority.
- No polling for Actor names is introduced.
- No display-name inference is introduced.
- No confidence-driven write is introduced.

## Primary QA

### Test A — Character/NPC Create & Link

1. Open a Session/Quest with a confirmed Character/NPC candidate.
2. Click **Create & Link**.
3. Realm Guard Quick NPC Library opens.
4. Select/create an NPC.
5. Reopen or refresh the Session/Quest.

Expected:

- no premature canonical UUID error when the library opens
- selected NPC Actor is created normally
- Campaign Learning stores its canonical Actor UUID
- Session/Quest Character Links include the Actor
- Actor profile sees the reciprocal Session/Quest Campaign Link
- exact candidate is no longer Possible New

### Test B — verification

Run:

```js
const c = game.modules.get("adventurers-tome").api.campaignEntityCreation;
await c.verify({ text:"<candidate>", sourceUuid:"<session-or-quest-uuid>" });
```

Expected:

```js
{
  targetResolves: true,
  canonicalVisible: true,
  campaignLinked: true,
  converged: true
}
```

### Test C — Cancel safety

1. Confirm a fresh Character/NPC candidate.
2. Click **Create & Link**.
3. Close the native Quick NPC Library without creating anything.

Expected:

- no Actor created
- no canonical target recorded
- no Campaign Link written
- no reciprocal reference written
- no false success message

### Regression

- Journal-backed World Create & Link remains working.
- Link Existing remains working.
- normal Quick NPC Library opening outside Campaign Intelligence remains unchanged.
- all graph writes remain GM-explicit.
