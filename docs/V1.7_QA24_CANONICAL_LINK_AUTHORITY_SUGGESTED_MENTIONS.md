# v1.7.0-qa.24 — Canonical Link Authority & Suggested Mentions

**Baseline:** v1.7.0-qa.23  
**Foundry baseline:** V13.351  
**Scope:** separate authoritative Campaign Links from heuristic text mentions in Session and Quest detail views.

## Problem

Before qa.24, Session/Quest detail views merged two different concepts into the same visible link lists:

```text
explicit / canonical Campaign Links
+
text-based inferred matches
=
World Links / Character Links / Quest Links
```

That made heuristic matches look authoritative and could surface people or world entries that were only mentioned in text, including ambiguous duplicate display names.

## Authority model

qa.24 makes the distinction explicit:

### Campaign Links

The authoritative lists and counters now contain only links backed by Tome link storage:

- legacy explicit Tome link IDs
- canonical Actor UUIDs from `campaignEntityLinksV1.actorUuids`
- canonical Journal UUIDs from `campaignEntityLinksV1.entityUuids`
- reciprocal explicit Session/Quest references where applicable

No free-text inference is promoted into these lists.

### Tome noticed

Text-derived matches are rendered separately as advisory suggestions:

- Quest name mentioned in Session text
- World entry name mentioned in source text
- exact Actor name mention
- unique first-name mention
- character title mention
- alias / nickname mention
- inferred Session reference from Quest text

These suggestions are read-only in qa.24 and do not write Campaign Links.

## Ambiguity

If multiple canonical documents share the same normalized display name, the suggestion is marked **Ambiguous** rather than presented as a single authoritative identity.

No automatic reconciliation is performed.

## Session QA

1. Open a Session with known explicit/canonical links.
2. Confirm the top counters match only real Campaign Links.
3. Confirm **People, places & lore** contains only explicit/canonical World links.
4. Confirm **Characters** contains only explicit/canonical Actor links.
5. Confirm prose-only matches appear under **Tome noticed** instead.
6. Confirm a prose-only mention does not increase the canonical counters.

## Quest QA

1. Open a Quest with canonical Session/World/Character links.
2. Confirm Campaign Links shows only explicit/canonical links.
3. Confirm text-only matches appear under **Tome noticed**.
4. Confirm First seen / Last linked derive from explicit Session relationships, not arbitrary text mentions.

## Duplicate QA

Create or use two visible documents with the same display name and mention that name in source text.

Expected:

- suggestion is marked **Ambiguous**
- duplicate candidates are not silently collapsed into a canonical link
- canonical Campaign Link counters remain unchanged

## Safety / regression

- no auto-linking
- no auto-creation
- no confidence-driven writes
- GM-explicit graph-write boundary remains unchanged
- qa.20–qa.23 Create & Link / Link Existing behavior remains unchanged
- system-agnostic startup behavior remains unchanged
- Genesys GM Dock host integration is explicitly out of scope

## PASS gate

qa.24 passes when authoritative Session/Quest link lists and counters contain only explicit/canonical relationships, while heuristic text matches are visible only as clearly labeled read-only suggestions with ambiguity surfaced rather than hidden.
