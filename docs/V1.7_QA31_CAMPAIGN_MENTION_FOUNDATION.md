# v1.7.0-qa.31 — Campaign Mention Foundation

**Baseline:** v1.7.0-qa.30  
**Foundry baseline:** V13.351  
**Scope:** introduce the first persistent Campaign Memory / Mention evidence layer without automatic Campaign Link writes.

## Product intent

Tome is moving from a passive archive toward a proactive campaign assistant.

qa.31 establishes a durable distinction between:

- **Linked** — authoritative canonical Campaign Link
- **Mentioned** — persistent evidence that an entity appeared in a source
- **Suggested / Unresolved / Ambiguous** — detected evidence that is not yet safe to treat as canonical

A Mention does **not** imply a Campaign Link.

A Mention may remain after a Link is created because it preserves historical provenance.

## Storage model

qa.31 adds:

`scripts/campaign-mention-evidence.js`

API:

```js
game.modules.get("adventurers-tome").api.campaignMentionEvidence
```

The first persistence layer is intentionally:

- GM-only
- user-scoped
- derived from Session / Quest source documents
- rebuildable from source evidence
- not a replacement for Foundry canonical documents

This protects GM-only evidence while the later viewer-scoped/player-safe evidence storage layer is designed.

Foundry Session/Quest documents remain source of truth.

## Evidence record

A v1 Mention record can retain:

- stable evidence id
- source Journal UUID
- source Page UUID
- source kind
- source/page names
- source path
- source order / Session ordinal
- resolved canonical target UUID when available
- target name/kind
- mention text
- provenance snippet
- source offsets
- mention type
- resolution state / reason
- detection confidence
- identity confidence
- relation state
- whether a canonical Link also exists
- active / historical state
- first-seen / last-seen timestamps
- provenance metadata

## Lifecycle

Mention evidence automatically refreshes after Semantic Mention Discovery updates.

The ledger does not delete disappeared evidence.

If a previously detected mention is no longer present in the current source scan, the record becomes historical instead of being erased.

This supports future:

- First Mention
- Last Mention
- changed knowledge
- superseded evidence
- campaign-history queries

## World UI

For GM users, World profiles now include a separate:

**Mentioned In**

section.

It shows:

- source Session / Quest
- page name
- evidence snippet
- Prose Mention / Explicit Reference
- Mentioned / Mentioned · review / Linked + Mentioned
- historical state
- First Mention
- Last Mention
- total evidence count

Campaign Links remain a separate canonical section.

## Search/query foundation

The API exposes:

```js
const api = game.modules.get("adventurers-tome").api.campaignMentionEvidence;

api.snapshot();
api.query({ text:"Pale Wardens", includeHistorical:true });
api.recordsForTarget("JournalEntry.<id>", { includeHistorical:true });
api.recordsForSource("JournalEntry.<session-id>", { includeHistorical:true });
api.audit();
```

Manual refresh:

```js
await api.sync({ reason:"manual-qa", rescan:true });
```

## QA fixture

Use:

`Session 1 — QA test Session 1`

with text mentioning:

- Pale Wardens
- Ravenmoore Valley
- Ember Seal
- Baran
- Gunther

### A — persistent Mention without canonical Link

Expected for Pale Wardens before explicit linking:

```text
Campaign Links
No canonical Campaign Links yet.

Mentioned In
Session 1 — QA test Session 1
Prose mention
Mentioned / Mentioned · review
```

The Mention must exist even though:

```text
WORLD LINKS: 0
```

### B — Link and Mention coexist

After a real canonical Session -> Pale Wardens Campaign Link:

```text
Campaign Links
Sessions
Session 1 — QA test Session 1
```

and the Mention evidence remains:

```text
Mentioned In
Session 1 — QA test Session 1
Linked + Mentioned
```

No duplicate Mention record should be created merely because the Link status changed.

### C — ambiguous identity

For two unrelated canonical Gunther identities:

- Mention discovery may remain Ambiguous
- no canonical target UUID is assigned to the evidence record
- the ambiguous record must not appear as authoritative Mention history on either Gunther target

The evidence remains queryable in the GM ledger for future review tooling.

### D — historical preservation

Remove a previously detected mention from Session text and save.

After discovery/evidence refresh:

- the previous record remains
- `active === false`
- the relation becomes historical
- World Mention history marks it Historical

No source content is recreated automatically.

## Safety locks

qa.31 does **not**:

- create Campaign Links automatically
- create new campaign entities
- merge identities
- select between ambiguous candidates
- expose the GM-private ledger to players

Those behaviors remain future steps.

## Diagnostics

```js
game.modules.get("adventurers-tome").api.campaignMentionEvidence.audit()
```

```text

canonicalUuidAuthority: true

autoEntityCreation: false
```

## PASS gate

qa.31 passes when:

1. known Session/Quest mentions persist into the GM Mention ledger
2. resolved target mentions appear under World -> Mentioned In
3. Campaign Links remain independent
4. Link + Mention can coexist
5. ambiguous evidence does not attach to an arbitrary canonical target
6. removed evidence becomes historical rather than disappearing
7. reload preserves the Mention ledger
