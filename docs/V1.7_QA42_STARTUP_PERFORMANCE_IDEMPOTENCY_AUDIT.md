# qa.42 — Startup Performance & Idempotency Audit

Branch: `v1.7.0-qa.42-entity-intelligence-contextual-navigation`.
Audited baseline: `f73e7f1a96c384339e4b8047a1356a37cc2b1855`.
Version remains `1.7.0-qa.42`. Local test delivery only.

## Root causes and bounded fixes

1. **Repeated private migration reproduced.** Foundry merges object flags. The old cleanup supplied visibility/discovery but omitted legacy `notes`/`gmNotes`, leaving them on shared documents. The next load migrated the same sources again. Cleanup now explicitly deletes those fields after the private copy succeeds. A cheap eligibility check skips already-clean documents. Counters count newly copied records, rather than records revisited. Identical vault data is not rewritten.
2. **Migration retry stability.** Legacy notes without IDs/dates now receive migration-only deterministic IDs and reuse prior timestamps. `normalizeGmNote` now returns the intended reminder/open defaults on the first normalization; previously missing type/status became the string `undefined`, changing on the next normalization. Failed private writes retain the source; failed cleanup can retry without duplicating the copied notes. Existing historical duplicates are not deleted.
3. **Summary serialization-only writes reproduced.** A correct single-quoted HTML variant was considered changed solely because the browser serialized it differently. `atSsNormalizeHtml` now preserves the input if it makes no semantic repair. The ordinary two-page repair fixture already converged on the old baseline (2 then 0); repeated repair of that ordinary fixture was not reproduced. The fix specifically prevents representation-only repairs.
4. **Relationship self-invalidation reproduced under duplicate sync signals.** Identical ledger writes fired another evidence-update signal and rebuilt the Entity Intelligence graph/index. `atReSync` now compares the complete serialized ledger before writing/emitting. Real evidence changes still write and invalidate; decisions, IDs, provenance and temporal semantics remain intact.

## Measurement limits

Measurements below use actual module functions in controlled local fixtures. Vault/summary runs use a real headless Edge DOM with 18 legacy records, 50 Journal pages and Foundry-style merge/deletion semantics. Transport is in memory. Universal/graph runs use a small isolated core-script VM world (4 registry documents), persisted settings across fresh reload contexts, two deliberate relationship sync signals and one explicit convergence audit per run. They are **not Per's live Foundry timings** and do not prove an overall live startup speedup. The two fixtures have different totals and must not be added together. Nested phases overlap; do not sum their times. Timings are a single sample, subject to host load and warmup.

## Runtime profiling and privacy

`scripts/startup-performance.js` loads first. It measures elapsed client time from init through the last observed startup work, including asynchronous ready phases. A one-second quiet timer prints the GM-only profile without blocking startup; that deliberate idle second is excluded from TOTAL. Failed measured work closes its token in `finally`. Startup and later runtime phases are separate. This is a measured Tome startup window, not all Foundry world startup or pixel-render completion. `_prepareContext` also measures the initial/later Tome context work; the local fixture does not execute a real Foundry render.

Inspect in Foundry after startup and again after opening Tome:

```js
game.modules.get("adventurers-tome").api.startupPerformance.snapshot()
```

Instrumentation writes no settings, emits no document update hooks, and records only fixed phase/counter names, numeric counts and timings. Unknown caller-supplied labels become `other`. No document names, UUIDs, hidden text, private notes or secrets enter telemetry. Automatic console output is GM-only. No adapter/system-specific startup behavior was introduced.
