# qa.42 — Manual Existing Identity Link from Review

Local hotfix on `v1.7.0-qa.42-entity-intelligence-contextual-navigation`, following the clean surface baseline `be6f895c5505a9662ee18ed5f11b28e44eb60a56`. Version and publishing metadata remain qa.42. No publishing, release, PR, merge or qa.43 is part of this change.

## Root cause

The identity review footer only offered creation and deferral. Existing identity selection was confined to the resolver's recommended candidate cards. A GM who knew a different identity could not search for it. The learning module already supported explicit source-scoped UUID decisions, but no Review picker invoked that path. The older Campaign Links writer also restricted targets to Actor, Item and JournalEntry.

The picker catalog is a temporary read-only view, not a new registry or setting. It canonicalizes proven projections through `campaignIdentityReconciliation.identityFor`. Search includes display names, established aliases, folder and existing profile facts. A one-dialog catalog avoids rescanning every collection while typing. Search matches never write links or decisions. Before confirmation, the UUID resolves again against the live world.

Dialog hosting follows the official [Foundry DialogV2 render callback](https://foundryvtt.com/api/v13/types/foundry.DialogV2RenderCallback.html) and button/form callbacks. Context uses the existing `campaignDecisionCandidateMeta` Identity Briefing; no second briefing model exists.

## Canonical decisions and duplicate prevention

Confirm → fresh canonical target UUID → existing `campaignEntityLinks.linkCanonical` → existing `campaignReviewLearning.chooseForSource` → mention rescan → relationship evidence sync → Analysis render.

The decision key is the existing source UUID plus normalized mention. Target name/category are presentation metadata. Explicit GM source choice precedes automatic recommendation and name/type heuristics, including a wrong discovery type or same-name target. It persists across module reload, reanalysis, target rename and folder move. It does not become a global surname alias.

Exact source-selected mentions, full canonical names and registered aliases converge. Unregistered longer fragments that overlap the explicitly selected name stay REVIEW instead of creating another person or being silently merged. Other sources do not inherit the manual choice. Different same-name entities remain separate UUIDs. A deleted selected target is REVIEW (`gm-selected-identity-deleted`), even if another matching name exists.

Undo restores the earlier source choice or deferral and removes only a link introduced by this decision. It preserves a pre-existing link and all original target identity/profile data. Canonical backlink flags follow the existing link/unlink API. Creation is never called by the picker.

## Relationship truth and privacy

Mention evidence supplies the chosen UUID to the existing qa.41 relation endpoint index. This makes relationships, provenance and backlinks use the same endpoint. Identity confirmation does not call relationship `decide`: a possible assertion remains possible, with its own review decision.

Picker action, search/catalog, canonical selection and learning metadata are GM-only. Player calls return empty candidates/decisions or reject selection before resolving a target. Player Entity Intelligence retains its independent viewer filtering. No system names or QA campaign names are used in production resolution.

Relationships presentation, compact Entity Context, Session/Quest surfaces and profile composition are unchanged.

## Focused Foundry-QA (Per)

1. Open an unresolved identity without a recommended match. Confirm Link existing is present. Repeat with an existing recommendation.
2. Click Link existing. Search a fragment of an existing person; compare same-name results using role, folder/location and prior mentions. Confirm Cancel writes nothing.
3. Change the initial type filter, then choose All entity types. Select an existing person, organization, location, item or Scene and confirm. No new entity should appear.
4. Confirm the Review count decreases and Memory/source evidence points to the selected UUID. Check Entity Context/relationships/backlinks use the same target.
5. Reload and reanalyse. Rename the target and move its folder; reanalyse again. The original selected mention must still be linked to the same identity without duplicates.
6. Link an identity involved in a hedged relationship. Confirm the relationship stays Possible/reviewable.
7. Undo a fresh link; compare with undoing a decision where the link already existed. The identity remains, earlier source decision is restored, and only the new source link is removed.
8. In a disposable QA world, delete a selected target and reanalyse. The mention returns to REVIEW without choosing a namesake or creating a replacement.
9. Check as a player: no picker, hidden candidates/context or GM decision metadata. Verify public Entity Intelligence still obeys visibility.

Automated validation uses real core scripts, native NLP, the full existing regression suites, real Handlebars templates, and an actual headless browser with the production picker/render callback and CSS. The DialogV2 window host in the browser fixture is simulated; this does not replace Per's live Foundry verification.
