# v1.9.0-qa.2 — Reviewed target copies

Stable remains 1.8.0. This is a local QA build, not a published release.

## Included

- Original Tome Migration ZIP reader with SHA-256 payload/media checks, allowed paths, duplicate detection and schema limits.
- Target review and preview before any creation. Copies receive new world/embedded IDs, recognizable UUID links are rewritten, and original data/ownership stays archived under the GM-only copy's migrationV1 flag.
- Journals/pages, folders, scenes, playlists and RollTables. Scenes are inactive and not in navigation; playlist sounds do not start playing. Generic Foundry data is retained. Foreign module flags are archived instead of activated; existing Tome journal metadata remains on the private copy.
- Same-system Actor/Item copies require review and supported target types. System version compatibility is not automatically assumed.
- Optional taf **3.2.0** → Realm Guard adapter. GM chooses Character/NPC. `system.content` becomes biography; generic embedded/world items become Gear with description/quantity. Embedded attribute labels/keys suggest Nature, Will, Health, Resources or Circles; values are applied only when explicitly mapped. Other mechanics, Macro triggers, carry capacity and unsupported fields are archived. No free-text rules are guessed.
- Source Character/NPC/Contact/Location and other explicit Tome categories are retained as neutral metadata. They are not inferred from names or ownership. Known Actor categories are preserved automatically; a field template cannot overwrite them. Raw source relations and original ownership remain in the archive, even where a target system cannot use them.
- **Reuse approved field mappings** applies exact normalized field labels to matching source document types in this migration. Internal attribute IDs can differ. Covered fields with valid values can reuse the confirmed review; new labels/invalid values become exceptions. Actor categories remain independent. Rules are not silently applied to unrelated systems or later migrations.
- The overview shows **counts and exceptions**, not hundreds of mandatory review cards. **Move ready and reviewed copies** approves ready copies together, excluding unresolved exceptions and their unreviewed dependants. Full mappings are optional. If a source lacks Character/NPC distinctions, the GM can classify remaining unknown Actors in one batch after choosing individual exceptions.
- Repeated unsupported document types are grouped by shared adapter issue. They remain in the source package; the GM does not receive one unusable mapping form per document.
- Unsupported rows are preserved in the original package and skipped. Compendium entries import as world copies; packs are not recreated.
- Previously created copies from the same package are recognized, so exceptions can be resolved in a later pass without duplicating ready copies. Contact actorId/itemId references and stored UUID relations are remapped. Missing parties become exceptions. This is not transactional rollback or repair of references after an interrupted creation pass (qa.4).

## Test in Foundry

Use a disposable **destination world** with a backup. The source world does not need to remain open.

1. Install this QA ZIP and open Campaign Settings → Developer Tools → Migration Toolkit.
2. Select a small ZIP exported with qa.1 or qa.2 and click **Read package / Dry Run**. Confirm the destination name/system.
3. Check the overview, then **Move ready and reviewed copies**. Only exceptions need review. Check the journal text, preserved category, new UUID links, inactive scene and stopped playlist. **Show all mappings** is optional.
4. Check that the imported document is GM-only and the original document's ownership/data is in its `flags.adventurers-tome.migrationV1.sourceData` archive.
5. For a taf 3.2.0 package in Realm Guard, choose Character/NPC and click **Update mapping preview**. Confirm the biography and Gear. Choose a mechanical field for any suggested attributes, then update preview again.
6. Approve one template row, click **Reuse approved field mappings for matching documents**, and inspect another matching Actor. Confirm its own value was used, not the first Actor's value, and Character/NPC did not change. Already covered rows disappear from the exceptions list; new fields remain exceptions. For unclassified Actors, choose known Character exceptions first and use **Remaining unclassified Actors are NPCs** only if that is your intended batch classification.
7. Resolve another exception after the first pass and move it. Existing copies should not be duplicated.

Live taf/Realm Guard/Genesys reference-world tests are planned for qa.3. Automated tests use synthetic fixtures based on official taf 3.2.0 and local Realm Guard schemas; the browser harness mocks Foundry document creation and is not a live server test.
