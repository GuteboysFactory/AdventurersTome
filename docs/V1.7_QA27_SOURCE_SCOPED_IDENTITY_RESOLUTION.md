# v1.7.0-qa.27 — Source-Scoped Identity Resolution

**Baseline:** v1.7.0-qa.26  
**Foundry baseline:** V13.351  
**Scope:** resolve campaign identities using the current Session/Quest as primary evidence before broad campaign-wide candidates.

## Why qa.27 exists

qa.26 showed that Campaign Analysis could still disagree with Tome noticed because the semantic resolver searched the whole campaign index first. Same-name entities elsewhere in the world or in compendiums could therefore force Ambiguous even when the current Session already contained stronger local evidence.

Examples from QA:

- `Citronimus` was Reconciled in Tome noticed but Ambiguous in Campaign Analysis.
- `Pale Wardens` was already a canonical World Link on the Session but Campaign Analysis still showed Unresolved.
- Compendium/world duplicate names inflated ambiguity counts for some names.

## Source-scoped authority order

For each detected mention, qa.27 resolves identity in this order:

1. Canonical Campaign Links already stored on the current Session/Quest.
2. Explicit Foundry inline references on the current source/page.
3. Exact-name world candidates from the resolver set.
4. Other world candidates from the resolver set.
5. Compendium candidates only as fallback.

At every stage, Campaign Identity Reconciliation collapses Actor + Contact/World projections before ambiguity is decided.

## Rules

- Source-local canonical evidence beats unrelated same-name identities elsewhere.
- Source-local inline UUID evidence beats broad name matches.
- World documents are preferred over compendium templates.
- Same-name candidates outside source-relevant evidence do not override stronger source-local evidence.
- Multiple source-linked identities with the same mention remain Ambiguous.
- No source evidence means the result can still remain Review, Reconciled, Ambiguous or Unresolved.

## Consumers

### Campaign Analysis

Known Mentions now call the shared source-scoped resolver using:

- source Journal UUID
- source Page UUID
- exact mention text
- resolver candidates
- existing resolver decision/confidence

### Tome noticed

Suggested Mentions also consult the same source-scoped resolver so advisory presentation and Campaign Analysis share the same identity interpretation.

## QA

### A — canonical source link

Use a Session that already has a canonical Campaign Link to `Pale Wardens` and whose text mentions `Pale Wardens`.

Expected:

- Campaign Analysis must not show Unresolved.
- It should resolve as source-linked/canonical.
- Unrelated same-name entries elsewhere must not create ambiguity.

### B — reconciled Actor + Contact

For `Citronimus`, `Arne`, or `Baran` where Actor + Contact projection converge on the same Actor UUID:

Expected:

- Tome noticed and Campaign Analysis agree.
- Result is Reconciled or source-linked to one authority identity.
- No false ambiguity from the projection.

### C — true duplicate

For a name with multiple unrelated source-relevant canonical identities:

Expected:

- both views remain Ambiguous
- visible identity count reflects source-relevant identities after reconciliation

### D — compendium noise

If a world identity and one or more compendium templates share the same name:

Expected:

- active world identity wins before compendium fallback
- compendium-only candidates cannot inflate ambiguity when a unique world candidate exists

## Safety

- read-only resolution only
- no automatic Campaign Link writes
- no auto-creation
- no document merge
- no confidence-driven writes
- GM-explicit graph-write boundary remains unchanged

## PASS gate

qa.27 passes when Campaign Analysis and Tome noticed agree on the same source-scoped identity interpretation, canonical source links resolve deterministically, projection aliases reconcile correctly, and unrelated campaign/compendium duplicates no longer create false source ambiguity.
