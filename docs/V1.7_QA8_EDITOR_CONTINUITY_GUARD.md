# v1.7.0-qa.8 — Editor Continuity Guard

**Baseline:** v1.7.0-qa.7  
**Foundry baseline:** V13.351  
**Scope:** preserve active Tome authoring through autosave and background discovery refreshes

## Problem

Session Chronicle and Quest Overview autosave correctly, but a saved JournalEntryPage can trigger:

```text
JournalEntryPage.update
→ Universal Document Registry rebuild
→ Campaign Discovery update
→ Tome background main render
→ active contenteditable DOM replaced
→ caret/focus lost
```

Autosave must save content without ending the user's editing session.

## Fix

- Authoring Foundation now tracks live Tome editors through a shared `_atRichEditingCount`.
- Autosave still writes normally.
- Registry, Discovery, Mention Discovery and other background work remain active.
- Generic Tome background renders are deferred while a live editor exists.
- Deferred renders coalesce into one pending refresh.
- The pending refresh runs only after editing has genuinely ended and the save lock is settled.
- Existing richer editor paths that already use `_atRichEditingCount` remain compatible.
- A DOM-state fallback also detects supported live editor surfaces.

## Expected behavior

While continuously typing:

```text
Editing…
Saving…
Saved
```

may repeat any number of times.

The user must retain:

- caret
- focus
- edit mode
- scroll position
- ability to continue typing immediately

Autosave must never itself terminate authoring.

## QA A — Session Chronicle

1. Open a Session with Chronicle.
2. Click Chronicle to edit.
3. Type continuously for at least 20–30 seconds.
4. Pause long enough for several autosaves, then continue typing without clicking again.

Expected:

- multiple saves occur
- caret stays in Chronicle
- Chronicle remains contenteditable
- no view jump
- no forced exit from edit mode
- text persists

Then deliberately click outside the editor.

Expected:

- final pending save completes
- edit mode ends
- one deferred Tome refresh may occur
- saved Chronicle text remains intact

## QA B — Quest Overview

Repeat the same test in a Quest Overview.

Expected: identical behavior.

## QA C — Campaign Intelligence remains live

During Session/Quest authoring, autosave may still trigger Registry/Discovery/Mention work in the background.

Expected:

- no disabled discovery pipeline
- no Campaign Link persistence introduced
- after ending edit mode, the refreshed Tome can reflect the newest derived campaign data

## PASS gate

qa.8 passes when Session Chronicle and Quest Overview both survive repeated autosaves without losing caret/focus/edit mode, and a normal UI refresh resumes after the user deliberately exits editing.
