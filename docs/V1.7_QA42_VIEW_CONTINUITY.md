# qa.42 — View continuity and attributed professions

Local test patch, no version bump or publication.

The shared Tome application's render lifecycle preserves DOM state when its navigation identity is unchanged. It captures after template preparation, immediately before replacement, so scrolling or typing during asynchronous work is included. It restores nested vertical/horizontal scroll, open details, dirty text/select/checkbox fields, focus and caret after event listeners and responsive styling are installed. Visible landmarks compensate for changes in content height above the viewport. Actual navigation, changed document/source scope and entering/leaving profile editing do not inherit another view's state. This is client-only, transient state; it does not write campaign data or run discovery.

A resolved Review decision reserves its former card height with a noninteractive confirmation. Existing completed slots persist on same-view refreshes. Undo restores the real card; navigation/reopening removes temporary slots. Cards removed by unrelated updates do not falsely receive decision confirmations. This avoids placing a different decision button at the old click position.

Source-derived role briefing now requires punctuation/capitalization evidence of an attached profession. A reporting person in “According to X, Captain Y …” does not inherit Y's profession. Equivalent Swedish attribution and a legitimate former-scout apposition are covered.

## Boundaries

This patch does not merge independent Actor/Contact documents by name, rename old Orren fragments, rewrite old saved briefing fields or discard conflicting historical GM decisions. Confirm the correct identity explicitly. The existing canonical identity reconciliation still collapses proven Actor/Contact projections and preserves independent namesakes for review. Existing erroneous document fields require deliberate correction; fresh analysis uses the corrected attribution rule.

This lifecycle applies to the main Tome application across its views. Foundry's external document sheets and separate dialogs retain their own lifecycle. Deleted controls cannot retain focus. A shorter document can clamp scroll to its available extent. Images loaded after rendering and live Foundry layout need user QA; browser geometry is modeled in the automated tests, not a live Foundry session.
