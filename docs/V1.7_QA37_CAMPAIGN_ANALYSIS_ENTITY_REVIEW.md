# v1.7.0-qa.37 — Campaign Analysis & Entity Review

**Baseline:** v1.7.0-qa.36  
**Foundry baseline:** V13.351

## Goal

Add a dedicated GM-only Campaign Tools → Analysis surface that turns Campaign Memory into a practical review queue without changing canonical authority or making autonomous campaign decisions.

## Locked UX rule

> **Memory tells the GM what Tome has recorded. Analysis tells the GM what actually needs attention.**

Analysis is a triage and navigation surface only. It does not auto-create entities, choose between ambiguous identities, or silently modify Campaign Links.

## New Campaign Tools section

Campaign Tools now exposes:

- Overview
- Memory
- **Analysis**
- Assistant

Analysis is also present in contextual Campaign Tools navigation on Next Session Dashboard, Quick Capture, Reveal Queue and Post-Session Assistant.

## Entity Review Queue

The queue is built from active Campaign Mention evidence and prioritizes:

1. Ambiguous identities
2. Unresolved identities
3. Mentioned · review candidates

Repeated evidence for the same active identity/state is grouped into one review row with:

- entity / mention name
- entity kind
- relation state
- latest evidence snippet
- total evidence count
- source count
- latest source
- Target navigation when a resolved target exists
- authoritative Source navigation

## Tome noticed

Ordinary active Mentioned evidence that is not a canonical Link is collected separately under **Tome noticed**.

These rows are informational by default. They do not imply a required GM decision.

## Safety / authority locks

qa.37 does not change:

- Foundry Document backend/source of truth
- canonical UUID identity authority
- deterministic auto-link rules
- ambiguity rules
- auto-create policy
- unlink suppression behavior
- Mention evidence history/lifecycle
- player permissions/privacy
- Campaign Tools Assistant behavior

Analysis is GM-only and read-only.

## QA

### A — Navigation

Open Campaign Tools.

Expected:
- tabs are Overview / Memory / Analysis / Assistant
- Analysis opens cleanly
- Campaign Tools remains highlighted
- contextual GM workflow nav includes Analysis

### B — Fixture counts

Using the existing Campaign Memory fixture:

Expected:
- Gunther appears in Analysis as Ambiguous
- deterministic linked entities such as Pale Wardens / Ravenmoor Valley / Ember Seal / Baran do not appear in the decision queue merely because they have evidence
- ordinary non-linked Mentioned evidence may appear under Tome noticed
- top counters match the visible grouped rows

### C — Review queue

Expected:
- Ambiguous rows are ordered before Unresolved
- Unresolved rows are ordered before Review candidates
- repeated evidence for the same identity/state is grouped
- evidence/source counts are visible
- latest source context is visible

### D — Navigation actions

For a row with a resolved target:

Expected:
- Target opens the canonical Tome/Foundry entity

For any review row:

Expected:
- Source opens the authoritative Foundry source/page
- no Link or identity decision is written by opening either action

### E — Clean state

If there are no Ambiguous / Unresolved / Review rows:

Expected:
- Analysis shows a clear “No identity decisions waiting” state
- Tome noticed remains independently visible when ordinary mentions exist

### F — Player privacy

As player:

Expected:
- Campaign Tools remains absent
- Analysis tab is absent
- Analysis counts/rows are absent
- no Campaign Memory evidence or ambiguous identity information leaks

## PASS gate

qa.37 passes when:

1. Analysis is a stable fourth Campaign Tools tab
2. entity review classification matches Campaign Memory relation semantics
3. grouped review rows navigate safely to Target/Source
4. no automatic campaign write occurs from Analysis
5. ordinary Tome noticed rows remain distinct from required review
6. player privacy remains intact
7. qa.31–qa.36 Campaign Memory and Campaign Tools behavior does not regress
