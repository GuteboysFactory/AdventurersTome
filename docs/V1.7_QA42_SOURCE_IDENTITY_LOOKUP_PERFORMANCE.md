# qa.42 source identity lookup performance

Local follow-up to Foundry startup/runtime reports on baseline 6779810.
Version and publication metadata remain 1.7.0-qa.42.

## Evidence and root cause

The supplied live profile measured 8 Memory syncs / 90,407.3 ms accumulated
elapsed time, then 12 syncs / 203,367 ms. These overlapping asynchronous
measurements must not be interpreted as wall-clock startup duration.
The embedded-item and private-vault fixes were effective in those profiles.

Source-scoped identity resolution calls `atSsiCandidateForUuid` for every
canonical/legacy/inline source link. Each lookup previously called the public
Discovery `snapshot()`, which deep-clones the entire registry, to find one UUID.
Thus every mention repeated whole-registry cloning once per linked identity.
This synchronous work runs on the browser's UI thread; deferring its start does
not prevent it from blocking Foundry once it runs.

The existing Discovery `get(uuid)` returns a clone of just the requested entity.
The resolver now uses that API, preserving the existing snapshot-only fallback
for compatible providers and the live-document fallback for absent entries.
No persistent cache, identity policy, viewer scope, scheduler or data format
changes were introduced. Missing candidates and same-name collisions retain
their prior resolution/review behavior.

## Local reproduction

Identical synthetic workload: 1,419 unrelated Discovery entities with attributes

The included entity count is synthetic, not copied campaign content.

## Changed code

- `campaign-source-scoped-identity.js`: `atSsiDiscoveryEntity` uses Discovery
  `get`; `resolveMention` measures `source-identity-resolution`.
- `campaign-mention-evidence.js`: measures the awaited candidate resolver as
  `candidate-resolution`, without changing its options or outcomes.
- `startup-performance.js`: permits those two content-free measurement phases.
- `qa42-startup-performance.test.mjs`: four regressions for repeated lookups,
  same-name ambiguity/projection reconciliation, fresh rename/removal behavior,
  and snapshot-only compatibility.

No scan/job is disabled, no candidate is silently dropped, and no actor,
Journal, settings, or installed Foundry module has been edited by this task.
