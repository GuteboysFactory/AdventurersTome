# qa.43 — GM matching preferences and compact completed decisions

## GM workflow

In an expanded Review candidate, open **Matching preferences**:

- **Use as campaign default** stores an explicit name-to-identity preference for this campaign.
- **Pause automatic matching** excludes the identity from automatic candidate matching. The document, facts and existing links remain. **Link existing** still lists it for an explicit source choice.

The dialog reports how many distinct sessions already chose the identity for this name. Repeated choices recommend a default; they never set it automatically.

The Analysis heading has a separate **Matching preferences** button for removing a default or resuming a paused identity even after the original Review card disappears. Preferences persist in the existing GM-only world learning setting. Both setting and removing preferences enter the recent Undo history.

## Authority and reversibility

An explicit session choice takes precedence over a campaign default, including a manually chosen paused identity. Existing source-specific canonical/inline references retain priority. Unlink suppression is preserved. A default whose document is missing remains unresolved instead of silently choosing another namesake. Pausing every candidate does not create another identity.

Changing or undoing a preference does not erase established session links. Undo protects against a later conflicting preference. Namesakes are not merged and no document is deleted or retyped.

## Review layout

Resolved Review cards disappear from the queue without a full-height placeholder or local Undo button. The top-level Undo/history remains. Global scroll anchoring, retained open details, delayed-render restoration and navigation behavior are retained. When a list becomes shorter, browser scroll limits still apply.
