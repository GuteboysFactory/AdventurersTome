# Adventurer's Tome v1.6.0-qa.3 — Semantic Catalog Expansion & Character Intelligence

**Stable baseline:** v1.5.0  
**Previous USL gates:** v1.6.0-qa.1 PASS, v1.6.0-qa.2 PASS  
**Verified Foundry baseline:** V13.351

## Goal

Expand the read-only Universal Semantic Layer from identity / relationships / traits into a richer character-intelligence model while preserving the same permission, provenance and authority rules.

This package remains **read-only**.

## Semantic Catalog v3

New semantics:

- `drives`
- `beliefs`
- `goals`
- `instincts`
- `skills`
- `wises`
- `talents`
- `conditions`

Resolution policy:

- drives / beliefs / goals / instincts = `single`
- skills / wises / talents / conditions = `merge`

Existing identity, relationships and traits behavior remains unchanged.

## Realm Guard reference mapping

The existing optional `realm-guard-semantic-reference` adapter gains:

- `drives` ← belief / goal / instinct
- `beliefs` ← `system.belief`
- `goals` ← `system.goal`
- `instincts` ← `system.instinct`
- `skills` ← embedded `Item[type=role]`
- `wises` ← embedded `Item[type=wise]`
- `talents` ← embedded `Item[type=talent]`
- `conditions` ← embedded `Item[type=condition]`

Realm Guard-specific source paths remain isolated to the reference adapter.

## Privacy scope

Character Notes remain intentionally excluded.

qa.3 does not map `system.notes` because the product-level visibility semantics for personal/private/GM notes are not yet locked. No semantic expansion is allowed to weaken the existing GM secrecy boundary.

- 8 entries
- catalogVersion = 3
- single/merge policies as documented

Use a populated Realm Guard Actor:

    const actor = game.actors.getName("Dev Testsson")
      ?? game.actors.contents.find(a => ["character","npc"].includes(a.type));

    await s.resolveMany(actor, [
      "drives",
      "beliefs",
      "goals",
      "instincts",
      "skills",
      "wises",
      "talents",
      "conditions"

Expected populated semantics resolve through:

- provider containing `realm-guard-semantic-reference`
- authority = `system`
- visibility = `source`

Empty source categories may remain unavailable.

## QA C — skills shape

`skills.data` should be an array of embedded role Items containing at least:

- id
- uuid
- name
- rating
- trained
- versus
- learning.pass/fail state
- sourcePath

No skill data is inferred from rendered sheet HTML.
