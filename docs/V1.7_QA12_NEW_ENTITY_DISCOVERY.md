# v1.7.0-qa.12 — Unknown / New Entity Discovery

**Baseline:** v1.7.0-qa.11  
**Foundry baseline:** V13.351  
**Scope:** read-only discovery of likely campaign entities mentioned in Session / Quest prose that do not yet resolve to a known canonical campaign identity.

## Goal

Extend Campaign Intelligence beyond known-name matching:

```text
Session / Quest prose
→ known mention discovery
→ known identity filter
→ proper-name candidate extraction
→ contextual type classification
→ read-only possible new entity candidates
```

No entity is created and no Campaign Link is written in qa.12.

## Confidence model

Three distinct questions remain separate:

1. **Detection confidence** — is this text likely an entity mention?
2. **Entity type confidence** — what kind of entity does context suggest?
3. **Identity confidence** — does an existing canonical campaign entity match?

A new-entity candidate has identity status:

```text
no-existing-canonical-match
```

and remains non-persistent.

## Candidate extraction

The scanner:

- reads viewer-visible Session and Quest Journal text pages
- strips non-visible secrets for non-GMs
- ignores Foundry inline reference markup as raw prose
- extracts proper-name shaped runs
- filters known canonical names already present in Universal Campaign Discovery
- filters obvious single-token aliases of known multi-token identities
- suppresses common sentence-start / function-word noise
- groups repeated occurrences on the same source page
- treats repetition as detection evidence only

## Contextual type classification

qa.12 provides read-only likely types:

- `character`
- `location`
- `faction`
- `item`
- `lore`
- `unknown`

Signals include title words, type-like suffixes and nearby prose context.

Examples:

```text
Brother Hadrin       → Character/NPC
Captain Varek        → Character/NPC
Ironroot Ford        → Location
Blackmere Pass       → Location
Hollowwatch Ruins    → Location
Ashen Hand           → Faction
Moon-Key             → Item
Red Star Oath        → Lore
```

These are classifications, not creation instructions.

## Public API

```js
const api = game.modules
  .get("adventurers-tome")
  .api.campaignNewEntityDiscovery;
```

Available:

```js
await api.scan({ rescanDiscovery:true, rescanMentions:true });
api.snapshot();
api.candidatesForSource(uuid);
api.audit();
```

## Primary QA — Session 7

Use:

**Session QA — The Broken Road to Hollowwatch**

The current test Chronicle deliberately contains both known campaign identities and entities that do not yet exist.

After install/reload:

```js
const n = game.modules
  .get("adventurers-tome")
  .api.campaignNewEntityDiscovery;

await n.scan({
  rescanDiscovery:true,
  rescanMentions:true
});

const s = n.snapshot();

s.summary
```

Then isolate the Session:

```js
const session = game.journal.contents.find(j =>
  j.name.includes("Broken Road to Hollowwatch")
);

n.candidatesForSource(session.uuid).map(c => ({
  text:c.text,
  count:c.mentionCount,
  detection:c.detection,
  type:c.classification.kind,
  typeConfidence:c.classification.confidence,
  disposition:c.disposition,
  identity:c.identity.status
}));
```

## Audit

```js
n.audit()
```

Expected:

- `healthy = true`
- `readOnly = true`
- `writesPerformed = false`
- `autoPersistence = false`
- `confidenceModel = "detection-type-and-identity-separated"`
- `noEntityCreation = true`
- `noCampaignLinkWrites = true`

## Safety / lock

qa.12 MUST NOT:

- create Actors
- create Journal entries
- create Items
- create Locations/Factions/Lore
- modify existing campaign entities
- write Campaign Links
- infer hidden GM-only evidence for players

## PASS gate

qa.12 passes when viewer-visible Session/Quest prose produces useful read-only new-entity candidates, known canonical identities are filtered out, and no campaign data writes occur.
