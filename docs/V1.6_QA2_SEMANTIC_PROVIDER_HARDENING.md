# Adventurer's Tome v1.6.0-qa.2 — Semantic Provider Hardening & Realm Guard Reference Mapping

**Stable baseline:** v1.5.0  
**Previous USL gate:** v1.6.0-qa.1 PASS  
**Verified Foundry baseline:** V13.351

## Goal

Harden provider resolution and move from synthetic QA-only semantic reads to the first real reference mapping.

This package remains **read-only**.

It adds:

- Semantic Catalog v2 resolution policies
- single-provider and merge-provider behavior
- multi-provider provenance aggregation
- first real Realm Guard / Torchbearer semantic reference adapter
- system data mapping for ancestry, rank/class-like role, background, biography, relationships and traits

Tome Core still does not hard-code Realm Guard paths. All Realm Guard-specific knowledge remains in the optional reference adapter.

## Catalog v2 resolution policy

Each semantic declares a resolution mode.

Current policy:

- identity and identity.* → `single`
- relationships → `merge`
- traits → `merge`

Single semantics take the highest-priority compatible provider.

Merge semantics combine compatible visible providers after permission/visibility filtering.

## Realm Guard reference mapping

The optional reference adapter id is:

`realm-guard-semantic-reference`

It declares:

- systemId: `realm-guard`
- documentTypes: `Actor`
- sourceTypes: `character`, `npc`
- capability: `semanticRead`

Mappings:

- `identity.ancestry` ← `system.ancestry`
- `identity.class` ← `system.rank`
- `identity.background` ← concept / homeland / lineage / insignia
- `identity.biography` ← `system.biography`
- `relationships` ← parents / seniorArtisan / mentor / friend / enemy
- `traits` ← embedded Item documents with `type === "trait"`

Notes are intentionally not mapped in qa.2 because their player/GM privacy semantics are not yet locked.

## QA B — real Actor resolution

Use a Realm Guard Actor with populated character data:

    const s = game.modules.get("adventurers-tome").api.semantic;
    const actor = game.actors.contents.find(a => ["character","npc"].includes(a.type));

    await s.resolveMany(actor, [
      "identity.ancestry",
      "identity.class",
      "identity.background",
      "identity.biography",
      "relationships",
      "traits"
    ])

Expected populated fields resolve with:

- provider containing realm-guard-semantic-reference
- authority = system
- visibility = source
- sourceUuid = Actor UUID
- accurate sourcePath

Unavailable/empty source fields may remain unavailable.
