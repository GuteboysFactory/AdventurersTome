# Adventurer's Tome v1.6.0-qa.12 — Relationship Identity & Authority Convergence

**Baseline:** v1.6.0-qa.11  
**Verified Foundry baseline:** V13.351

## Goal

Remove duplicate contextual relationship presentation without introducing unsafe name-based identity.

qa.12 keeps source data intact and converges only the Tome read model / presentation.

## Locked principles

1. **Canonical identity beats display name.**
2. **Name alone never merges people.**
3. **One stable target identity renders as one person/contact card.**
4. **Multiple relationship roles remain preserved as facets.**
5. **Current structured semantic data is the preferred live presentation authority.**
6. **Manual / imported / legacy-compatible information may remain as supporting evidence or notes rather than a second person card.**
7. **Semantic-only Contacts remain legitimate entities and do not require Actor materialization.**
8. **Generated Contact projections are Relations data first, not fuzzy Campaign Links.**

## Identity order

Contextual relation targets resolve in this order:

1. canonical Foundry Actor UUID
2. stable semantic key
3. stable discovery entity key
4. relationship key as a final non-name fallback

Display name is never used as the merge key.

This means:

- two different people named Gunther stay separate unless stronger identity proves otherwise
- two semantic relationship records that both resolve to the same Actor can converge into one rendered person
- a manual Tome relation and a semantic relation to the same Actor can converge safely

## Relationship facet convergence

When several relationship records point at the same stable target identity:

- the target renders once
- distinct roles are aggregated, for example `Parent · Friend`
- distinct notes/status/origin details remain visible
- GM-only detail keeps its lock marker
- canonical Actor navigation wins over Contact navigation
- Contact navigation wins over non-clickable fallback
- semantic/current navigation metadata wins when available
- Tome manual notes are preserved

No source relationship records are deleted or rewritten.

## Legacy / old-world behavior

qa.12 does not perform destructive legacy migration.

The intended authority model is:

```text
legacy / imported / manual evidence
              ↓
        normalized current model
              ↓
         Tome converged view
```

If a system adapter already exposes a normalized current relationship graph, Tome consumes that graph and does not independently promote raw legacy fields into parallel live identities.

Legacy handling remains adapter/migration responsibility; Tome Core remains system-agnostic.

## Campaign Links correction

Automatic Semantic Contact projections are Tome relationship presentation.

They must not enter Character → Campaign Links → World only because fuzzy text matching finds the character name.

For generated semantic Contacts:

- explicit Tome Actor ↔ World link → allowed in Campaign Links
- text/name inference only → suppressed

Ordinary non-projection World Journals retain the existing inference behavior.

## Permission boundary

- hidden Actor targets are not rendered
- unreadable Contact Journals are not navigable
- GM-only Tome relation facets remain available only in GM context
- convergence must not broaden source permissions
- player-facing Discovery remains permission-filtered before this consumer receives it

## System independence

Core convergence uses only generic Tome/Foundry concepts:

- Actor UUID
- semantic key
- entity key
- relationship key
- Discovery
- Contact Projection
- Tome relation extension data

No Realm Guard-specific field or API branch is added to Tome Core.

## QA A — duplicate Actor target

Use a character where:

- a manual Tome relation points to Actor A
- a semantic relationship also resolves to Actor A
- the roles differ

Expected:

- Actor A appears once
- both role facets are visible
- notes/details from both sources remain visible
- clicking opens Actor A

## QA B — same semantic target, multiple roles

Create or use two semantic relationship edges pointing to the same canonical Actor.

Expected:

- one person card
- both roles preserved
- no duplicate card

## QA C — same display name, different identities

Use two Contacts/Actors with identical names but different stable identities.

Expected:

- two separate cards
- no name-only merge

## QA D — semantic-only Contact

Use a relationship target with no Actor.

Expected:

- one Contact card
- Contact navigation works if projection is readable
- no Actor is auto-created

## QA E — Contact Campaign Links suppression

Open a character whose generated Contact projection text contains the character name.

Expected:

- Contact appears under Relations
- Contact does not appear under Campaign Links → World from fuzzy inference alone

Then explicitly link the Contact Journal to the Actor in Tome.

Expected:

- Contact may now appear under Campaign Links → World

## QA F — ordinary World inference regression

Use a normal, non-projection World Journal mentioning the character.

Expected:

- existing Campaign Links inference still works

- convergence does not expose private source evidence
