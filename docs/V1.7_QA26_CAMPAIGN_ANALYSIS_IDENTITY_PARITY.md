# v1.7.0-qa.26 — Campaign Analysis Identity Parity

**Baseline:** v1.7.0-qa.25  
**Foundry baseline:** V13.351  
**Scope:** make Campaign Analysis apply the same identity reconciliation semantics as Tome noticed before it presents Existing/Ambiguous/Reconciled state.

## QA25 finding

qa.25 successfully reconciled Actor + Contact projections inside **Tome noticed**, but Campaign Analysis could still inherit a pre-reconciliation `ambiguous` decision from Semantic Mention Discovery.

Example observed in QA:

```text
Tome noticed:
Citronimus
Character / Contact
RECONCILED

Campaign Analysis:
Citronimus
Character / NPC
AMBIGUOUS
```

The difference came from Campaign Analysis consuming only the selected/first resolver target and the resolver's already-computed decision.

## qa.26 behavior

Campaign Analysis now:

1. collects every visible resolver candidate for a known mention,
2. sends those candidate identities through Campaign Identity Reconciliation,
3. collapses Actor + managed Contact/World projections that converge on one Actor UUID,
4. preserves Ambiguous only when multiple unrelated canonical identities remain,
5. derives its visible state from the reconciled result.

No underlying Foundry documents or Campaign Links are changed.

## Expected examples

### Projection convergence

```text
Citronimus
Actor UUID X
├─ Actor
└─ Contact projection linked to Actor UUID X

Tome noticed      → Reconciled
Campaign Analysis → Reconciled
```

### True ambiguity

```text
Gunther
├─ canonical identity A
├─ canonical identity B
└─ canonical identity C

Tome noticed      → Ambiguous
Campaign Analysis → Ambiguous · 3 identities
```
