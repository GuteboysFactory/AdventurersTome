# qa.42 startup recovery after Review hotfix

Scope: existing qa.42 branch, no publishing/version change, PR, merge or release.

## Evidence and cause

Per's live Foundry 13.351 profile shows `tome-ready` 26743.5 ms and `private-vault` 26738.2 ms: 81 documents visited, 16 note records scanned, zero new migrated records, 16 cleanup writes, and no vault write. This locates the dominant delay in legacy-access cleanup, not narrative scanning. The screenshot alone does not prove the exact Foundry setter internals or that the same fields survive successive reloads.

The prior cleanup passed deletion keys inside an object to `setFlag`. The migration fixture assumed this applied deletion directly. A persisted-state regression now models preprocessing which consumes deletion keys before the document/database update, leaving the original database keys behind. The old path repeats cleanup; explicit flattened document deletion updates remove them and survive simulated reload. This is a tested compatibility fix for that failure mode; live reload confirmation remains required.

The Review hotfix also introduced unconditional full-sync replay. Reproduction with the exact d137a665 scripts and seven simultaneous signals produces seven relationship extractions and seven Memory syncs. Updated code produces one of each. Wall-clock values in the synthetic VM were affected by other verification processes, so no live speedup or timing guarantee is inferred from them.

## Changes

- `scripts/adventurers-tome.js`, `migrateLegacyPrivateData`: persist access deletion keys directly using flattened `document.update` fields, retain unrelated public access data, verify fields are actually removed, report failure while retaining the private copy. Private copy is still persisted before any cleanup; already-copied notes do not cause another vault write.
- `scripts/campaign-mention-evidence.js`, `atMeSync`: coalesce simultaneous full syncs using their in-flight promise; source-scoped requests retain ordered fresh execution.
- `scripts/campaign-relationship-evidence.js`, `atReSync`: share ongoing full sync work; source-scoped Review refresh still waits and executes separately.
- `tests/helpers/startup-world.mjs`: explicit document-update deletion model.
- `tests/qa42-startup-performance.test.mjs`: seven added regressions: persisted setter compatibility, already-copied cleanup, ineffective deletion/retry, concurrent full Memory/relationship dedupe, scoped refresh freshness.

No startup scanning was simply delayed with a timeout. Legitimate scheduled external updates, manual subsequent full syncs, authoritative Review persistence, duplicate-click protection, Undo and viewer privacy retain their existing behavior. No private payloads were added to profiling.
