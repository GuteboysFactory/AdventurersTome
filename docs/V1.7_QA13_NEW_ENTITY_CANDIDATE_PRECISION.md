## Precision rules

qa.13 adds two conservative filters.

### 1. Leading context trimming

Leading context/preposition words are trimmed before candidate evaluation.

Examples:

```text
On the ...
During the ...
After the ...
At the ...
Behind Citronimus
```

become either empty/non-candidates or reduce to the meaningful following name. If that remaining name is already canonical, normal known-identity filtering removes it.

### 2. One-off unknown singleton suppression

A candidate is moved to a diagnostic suppressed bucket when all are true:

- one token
- mentioned only once on the page
- type classification remains `unknown`
- type confidence is below 0.45

This targets sentence-start noise such as:

```text
Witnesses
Rather
Fighting
```

It does not suppress a single-token candidate that has meaningful character/location/faction/item/lore evidence.

## Public API addition

```js
api.suppressedForSource(uuid)
```

returns precision-suppressed candidates for QA/debugging.

## Primary QA

After install/reload:

```js
const n = game.modules
  .get("adventurers-tome")
  .api.campaignNewEntityDiscovery;

await n.scan({
  rescanDiscovery:true,
  rescanMentions:true
});

const session = game.journal.contents.find(j =>
  j.name.includes("Broken Road to Hollowwatch")
);

n.candidatesForSource(session.uuid).map(c => ({
  text:c.text,
  count:c.mentionCount,
  detection:c.detection.score,
  type:c.classification.kind,
  typeConfidence:c.classification.confidence,
  disposition:c.disposition
}));
```

Expected important candidates remain:

- Sister Elira
- Captain Varek
- Ironroot Ford
- Blackmere Pass
- Hollowwatch Ruins
- Ashen Hand
- Moon-Key
- Red Star Oath

Expected obvious noise no longer appears in normal candidates:
