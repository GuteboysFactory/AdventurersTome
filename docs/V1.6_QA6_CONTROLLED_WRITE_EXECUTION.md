# Adventurer's Tome v1.6.0-qa.6 — Controlled Semantic Write Execution

**Stable baseline:** v1.5.0  
**Previous USL gates:** qa.1–qa.5 PASS  
**Verified Foundry baseline:** V13.351

## Goal

Introduce the first real semantic mutations on top of the already verified privacy-safe dry-run write contract.

qa.6 adds controlled execution only. It does **not** add document creation.

## Public API

New method:

`semantic.executeWrite(source, plan, options?)`

Execution requires a valid `dryRun:true`, `allowed:true` plan produced by `semantic.planWrite()`.

The original plan is never trusted blindly.

## Revalidation before mutation

Immediately before mutation, execution re-runs `planWrite()` using the original plan's `currentValue` as `expectedCurrentValue`.

Execution is rejected when:

- permission changed
- canonical current value changed
- provider changed
- canonical target path changed
- source UUID changed
- operation changed
- the plan already contains a conflict
- the semantic no longer has an executable provider

This is the multi-client/stale-plan safety boundary.

## Adapter API

New additive capability:

`semanticWriteApply`

New targeted adapter helper:

`adapters.executeAdapter(adapterId, capability, payload)`

Targeted execution prevents a mutation request from being broadcast to every matching write adapter.

## Realm Guard controlled writes

The reference adapter can execute the same canonical system paths already verified by `semanticWritePlan`:

- `identity.ancestry` → `system.ancestry`
- `identity.class` → `system.rank`
- `identity.biography` → `system.biography`
- `beliefs` → `system.belief`
- `goals` → `system.goal`
- `instincts` → `system.instinct`
- `notes.private` → `system.notes`

Initial live QA should use `goals` and `notes.private` as the primary system-owned probes.

## Tome-owned controlled write

`notes.public` can execute against the canonical public-information path selected by qa.5.

For Tome Character Information Actors this is:

`flags.adventurers-tome.profile.biography`

The existing Character Information sync hooks remain responsible for normal UI refresh/convergence.

## GM Vault intentionally remains plan-only

`notes.gm` is **not executed in qa.6**.

Its storage model is user-scoped Contextual Private Vault data rather than a Foundry Document field. Controlled Vault mutation will be enabled only after the standard document write path is verified.

A qa.6 attempt to execute a valid `notes.gm` plan must return a safe non-applied result.

## Loop prevention

Semantic writes pass Foundry update options:

- `adventurersTomeSemanticWrite:true`
- `adventurersTomeSemantic:<semantic>`

No write execution recursively calls itself. Existing sync hooks may observe the canonical update and refresh their normal surfaces.

## Audit trail

USL audit now includes session-local `recentWrites` (maximum 20).

Audit entries contain only:

- timestamp
- semantic
- status
- reason
- provider
- target UUID
- target path
- user id

They never include current values, proposed values, GM note content, private note content, or semantic payloads.

## QA B — controlled goal write

Create a plan:

    const actor = game.actors.getName("Dev Testsson");
    const original = actor.system.goal;
    const plan = await s.planWrite(actor, "goals", "QA Execute Goal");

Execute:

    const result = await s.executeWrite(actor, plan);

Expected:

- applied = true
- status = applied
- provider = realm-guard-semantic-reference
- targetPath = system.goal
- Actor system.goal becomes QA Execute Goal
- semantic.resolve(actor, "goals") returns the new value

Then restore through the same semantic flow by planning/executing the original value.

## QA C — stale plan conflict

Create a valid plan, then change the canonical goal through normal Foundry editing before execution.

Execute the stale plan.

Expected:

- applied = false
- status = rejected
- reason = conflict
- conflict = true
- stale proposed value does not overwrite the newer canonical value

## QA D — source/target tamper guard

Clone a valid plan and alter targetUuid or targetPath.

Expected:

- mismatched targetUuid throws before mutation
- changed path/provider/operation fails fresh-plan target comparison
- no mutation
