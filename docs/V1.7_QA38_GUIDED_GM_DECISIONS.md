# v1.7.0-qa.38 — Guided GM Decisions

**Baseline:** v1.7.0-qa.37  
**Foundry baseline:** V13.351

## Goal

Turn Campaign Tools → Analysis from a passive diagnostic list into a fast GM decision inbox.

The intended interaction is:

> **Tome detects → Tome explains → Tome recommends when evidence supports it → GM confirms / defers → done.**

The GM should not need to research routine identity questions manually.

## Product rule

> **Tome does the analysis work. The GM keeps campaign authority.**

No decision is applied without an explicit GM click.

## Overview — Decision Monitor

Campaign Tools → Overview now includes a compact **Decision Monitor**.

It shows:

- Ambiguous count
- Unresolved count
- Review count
- Tome noticed count
- the next pending GM question
- source context
- **Confirm recommendation** directly from Overview when Tome has a sufficiently strong recommendation
- **Review** to open full Analysis

When no decisions are waiting, Overview shows a clear all-clear state.

## Analysis — Guided Decision Cards

Technical review rows are replaced by guided decision cards.

Each card answers:

1. **What did Tome detect?**
2. **What does Tome need the GM to decide?**
3. **What existing choices are available?**
4. **Does Tome have a recommendation?**

### Ambiguous

Question style:

> **Which existing identity does “X” mean here?**

The card shows up to four existing canonical candidates.

The GM can:

- choose one identity → creates the canonical Campaign Link for this Session/Quest source
- **Keep unresolved** → dismisses the question for this source without creating a Link

### Unresolved

Question style:

> **What is “X” referring to?**

If safe existing candidates are available they are offered.

If none are available:

- Tome says there is no safe match
- GM can open the source
- GM can **Keep unresolved**

qa.38 does **not** add automatic or one-click entity creation.

### Review

Question style:

> **Should “X” become a canonical Campaign Link?**

The GM can:

- choose an existing identity
- **Keep as Mention only**

## Recommendations

Candidate ranking reuses existing Campaign Mention resolver scores and source context.

Tome may add additional local-context support from the candidate's existing campaign profile, such as:

- title / subtitle
- campaign facts
- World profile metadata
- folder/type metadata

A candidate is marked **★ Tome recommends** only when the current evidence produces a sufficiently clear lead.

No recommendation is shown when candidates remain effectively tied.

## Candidate identity clarity

Where available the decision card shows:

- Actor / Item image
- name
- profile title / subtitle / facts
- kind / folder metadata
- relevant evidence reason

This is specifically intended to make duplicate display names such as two different **Gunther** identities distinguishable without opening several sheets.

## Persistence / authority

Choosing a candidate:

- writes through the existing **Campaign Entity Links** API
- Foundry canonical UUID remains authority
- the source Session/Quest gains the explicit Campaign Link
- Campaign Mention Evidence is rescanned
- the review queue should shrink when the ambiguity is resolved

Choosing **Keep unresolved** or **Keep as Mention only**:

- uses existing source-scoped Campaign Review Learning ignore state
- suppresses that question for that source
- does not globally merge identities
- does not delete Campaign Memory history

## Undo

The most recent guided decision in the current Tome session exposes **Undo**.

Undo:

- removes a Campaign Link only if qa.38 created that Link and it did not already exist
- clears the source-scoped defer decision when applicable
- rescans Campaign Mention Evidence

## Safety locks

qa.38 does not change:

- Foundry Document backend/source of truth
- canonical UUID identity authority
- deterministic auto-link rules
- ambiguity rules
- auto-create policy
- player permissions/privacy
- historical Mention evidence
- GM unlink suppression policy

A recommendation is never an automatic decision.

## QA

### A — Overview monitor

Open **Campaign Tools → Overview**.

Expected:

- Decision Monitor is present
- Ambiguous / Unresolved / Review / Tome noticed counts match Analysis
- next pending question is visible
- **Review** opens Analysis
- when a safe recommendation exists, **Confirm ★ [candidate]** is shown
- when no recommendation exists, Overview does not invent one

### B — Gunther ambiguous fixture

Using the existing two-Gunther fixture:

Expected:

- Gunther appears as an explicit question:
  - **Which existing identity does “Gunther” mean here?**
- both canonical Gunther identities are presented when resolver candidates are available
- candidates have useful distinguishing metadata/images where Foundry data permits
- if neither candidate has a clear evidence lead, no ★ recommendation is shown
- Source still opens the authoritative source context

### C — Choose identity

Choose one Gunther candidate.

Expected:

- the source Session/Quest receives a canonical Campaign Link to that exact UUID
- no new Actor/World entity is created
- Campaign Mention Evidence rescans
- the resolved question disappears from the pending decision queue when source-scoped resolution is now deterministic
- linked identity remains visible through normal Campaign Link / Mention presentation

### D — Keep unresolved

For an ambiguous/unresolved row click **Keep unresolved**.

Expected:

- no Campaign Link is created
- question disappears for this source
- same display name is not globally merged
- Campaign Memory history remains intact

### E — Mention only

For a review row click **Keep as Mention only**.

Expected:

- no Campaign Link is created
- question disappears for this source
- Mention evidence remains separate from canonical Links

### F — Recommendation

For a case with a clearly higher candidate score/context match:

Expected:

- one candidate receives **★ Tome recommends**
- reason is visible
- Overview may show one-click confirmation
- recommendation is not auto-applied

For tied candidates:

Expected:
- no recommendation badge
- GM must choose deliberately

### G — Undo

After one decision:

Expected:

- green **Decision saved** strip appears
- Undo reverses only the decision just made
- pre-existing Campaign Links are not removed
- evidence rescans and the question may return

### H — Player privacy

As player:

Expected:

- Campaign Tools remains absent
- Decision Monitor absent
- Analysis decision cards absent
- candidate metadata / GM context absent
- no Campaign Memory evidence leaks

## PASS gate

qa.38 passes when:

1. Overview provides an accurate campaign decision monitor
2. Analysis states the actual GM question rather than only technical status
3. existing candidate choices are understandable and quick to select
4. recommendations are conservative and never automatic
5. choose / defer actions persist through existing authority layers
6. decisions make the pending queue shrink instead of endlessly accumulating
7. Undo is safe
8. player privacy remains intact
9. qa.31–qa.37 Campaign Memory / Analysis behavior does not regress
