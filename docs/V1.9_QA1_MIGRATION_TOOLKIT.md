# 1.9.0-qa.1 — Migration Core + Generic Foundry Content

Local QA build following stable 1.8.0. Not a stable release.

## Entry point

GM: Campaign Settings → Developer Tools → Tome Migration Toolkit → Open Migration Toolkit.

The toolkit opens a separate workspace. Opening or starting Foundry does not scan the campaign. All migration work requires an explicit GM action; no automatic indexing, target writes, source updates, upload or import is performed by this build.

## Implemented

- Read-only selection and analysis of world Journals/pages, Scenes/embedded content, Playlists/sounds, RollTables/results, Folders and optional Actors/Items.
- Explicit Compendium selection; document data, pack metadata and pack folders are preserved. System/module packages are recorded as dependencies, not installed/copied as executable modules.
- Deterministic source-world/UUID migration identities, including embedded documents. Target UUIDs remain null until target import.
- Known references are inventoried and checked against the selected identities. Missing/unselected targets are reported as unresolved. Arbitrary module-specific references/automation are preserved as raw data and need later adapter review.
- Scene geometry, tokens, lights, walls, ambient sounds, tiles and journal markers remain in original source data. Actor delta/rules data is preserved without conversion.
- Actors/Items are marked Unmapped; unsupported pack document types are preserved and reported. Unknown fields and module flags are never silently removed.
- Downloadable ZIP containing `manifest.json`, `campaign.json`, optional `assets/` files, asset mappings and SHA-256 checksums. ZIP entries use stored encoding; this prioritizes compatibility over archive compression.
- References-only mode performs no media downloads. Include-media mode reads browser-accessible resources and preserves unavailable resources as references with an error report. External assets require browser CORS support; wildcard paths/streaming links may remain references. Each file is capped at 64 MiB; total included media at 512 MiB. Large campaigns should use references or narrower selections.
- Analysis and file work yield between batches and support cancellation. Compendium `getDocuments()` loads only explicitly selected packs and can still take time for a very large pack.
- Export re-analyzes selected source content and refuses a stale reviewed snapshot. The package payload is rebuilt from the verified current source, not caller-mutated cached data.

## Privacy and limits

This is a private GM migration archive, not a player-safe export. Original document ownership user IDs are preserved in source data but are not automatically valid in the destination world. Target user mapping and conservative visibility restoration belong to target import/review.

Player Chronicle journal documents are explicitly excluded, including legacy private Chronicle documents. User settings, inbox deliveries, credentials and user-private Chronicle storage are not exported. Campaign Memory/index stores and private GM user vaults are not collected yet. Owner-aware Chronicle and campaign-state migration are the combined qa.3 milestone. Tome flags already attached to selected Foundry documents remain preserved as opaque source data.

No rules conversion, target import, automatic dependency installation, media upload or source-world mutation occurs in qa.1. The existing Tome Importer does not import migration ZIPs.

## Planned source-system coverage

Per's campaign uses **Text-Based Actors (`taf`) 3.2.0**. It is approved as an additional planned source adapter, alongside the existing reference systems. The adapter belongs in qa.2, with `taf` 3.2.0 → Realm Guard verification in qa.3 using representative source Actors/NPCs. Preserve original text, embedded Items, custom attributes and unknown fields; free-text rules values require GM review. The shared neutral package allows this source to serve multiple target systems. qa.1 currently preserves raw `taf` Actor data as Unmapped; no `taf` → Realm Guard conversion is implemented yet. See the [roadmap](../ROADMAP.md) for the approved scope.

## Automated verification

`node --test tests/qa19-migration.test.mjs` covers source preservation, unknown fields, permissions, embedded identities, selected compendium reads, folder mapping, unresolved references, GM authorization, cancellation, stale snapshots, ZIP payload and media checksums, failed media, unsupported source data and unsafe archive paths.

Full regression: `node --test --test-concurrency=2 tests/*.test.mjs`.
Manifest and syntax: `node tests/validate.mjs`.

## Foundry manual QA

1. Open the toolkit as GM from Developer Tools. Confirm the normal Tome/Foundry view remains usable.
2. Analyze a Journal, Scene, Playlist and Folder selection; inspect counts, identities, dependencies and unresolved references. Analyze must create/change no documents.
3. Select one small compendium and repeat; verify other packs are not exported.
4. Export references-only ZIP. Inspect `manifest.json` and `campaign.json`; confirm Scene geometry and Playlist sound paths are present.
5. Export with media enabled using a small local map/audio file. Verify `assets/` files, path mappings and any missing-file report.
6. Change a selected document after Analyze, then Download. It must request another Analyze instead of exporting stale data.
7. Cancel an analysis/export. Verify no source data changed.
8. Confirm Player Chronicle private note text is absent from the package and that players cannot open the toolkit.

Automated checks do not replace live Foundry QA; the first delivery must be tested on the actual world before proceeding to qa.2.
