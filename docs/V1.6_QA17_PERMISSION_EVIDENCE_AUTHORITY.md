# Adventurer's Tome v1.6.0-qa.17 — Permission Evidence Authority

**Baseline:** v1.6.0-qa.16  
**Verified Foundry baseline:** V13.351

## Trigger

Final regression audit found one remaining Contact permission violation:

- Contact: `Gunther, Alive, Bree`
- permission policy: `semantic-source`
- source Actor readable by Dev Player
- stale `linkedUuid` no longer resolves
- `permissionSourceUuids` correctly contains only the source Actor

The viewer permission check still treated `linkedUuid` as mandatory evidence even though the active permission policy was `semantic-source`.

## Root cause

`linkedUuid` serves identity/navigation purposes and may legitimately outlive its Actor.

Permission authority is already normalized by `managedProjectionOwnership()` into `permissionSourceUuids`.

The read-side visibility check duplicated and broadened that authority by also consulting `sourceUuid` and `linkedUuid` directly.

## Fix

qa.17 makes `permissionSourceUuids` the primary permission-evidence authority.

- when `permissionSourceUuids` exists, only those UUIDs define projection permission evidence
- `linkedUuid` is not treated as an extra permission dependency
- legacy projections without `permissionSourceUuids` use a policy-aware fallback:
  - `source-and-target-intersection` → source + linked target
  - `semantic-source` → source only

This keeps identity metadata separate from permission authority.
