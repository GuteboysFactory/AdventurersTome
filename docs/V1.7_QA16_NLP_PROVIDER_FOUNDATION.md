# v1.7.0-qa.16 — NLP Provider Foundation

**Baseline:** v1.7.0-qa.15  
**Foundry baseline:** V13.351  
**Scope:** add a local advisory NLP provider layer using Compromise 14.17.0 and use it for candidate-boundary refinement.

## Why

The qa.12–qa.15 work proved the Campaign Intelligence pipeline, but also showed that hand-maintained grammar lists scale poorly.

Examples:

```text
Is Dev gonna...
TrueBlood the confidence...
Behind Citronimus...
During the battle...
```

The identity resolver is not the problem in these cases. The hard part is deciding where the candidate name begins and ends.

## Architecture

```text
Session / Quest prose
        ↓
Tome deterministic scanner
        ↓
Local NLP Provider (advisory)
        ↓
candidate boundary refinement
        ↓
known canonical / alias filtering
        ↓
Tome identity resolver
        ↓
GM review / future controlled writes
```

The NLP provider is advisory only.

It does **not** become campaign identity authority and has no write authority.

## Public API

```js
const p = game.modules
  .get("adventurers-tome")
  .api.nlpProvider;
```

Available:

```js
p.analyze(text)
p.refineBoundary(text)
p.typeHints(text)
p.audit()
```

## Candidate boundary behavior

Compromise POS tags are used conservatively to trim grammatical material from the outside of a candidate.

Examples:

```text
Is Dev
→ Dev

TrueBlood the
→ TrueBlood
```

Internal connectors remain intact:

```text
Order of the Phoenix
→ Order of the Phoenix
```

After refinement the existing Tome canonical-name / alias filter runs normally.

## Primary QA

Open the existing Session 7 test.

Run:

```js
const nlp = game.modules
  .get("adventurers-tome")
  .api.nlpProvider;

nlp.audit();
nlp.refineBoundary("Is Dev");
nlp.refineBoundary("TrueBlood the");
nlp.refineBoundary("Order of the Phoenix");
```

Expected:

- runtimeAvailable = true
- localOnly = true
- networkRequired = false
- identityAuthority = false
- writeAuthority = false
- `Is Dev` refines to `Dev`
- `TrueBlood the` refines to `TrueBlood`
- `Order of the Phoenix` is preserved

Then rescan Session 7:

```js
const n = game.modules
  .get("adventurers-tome")
  .api.campaignNewEntityDiscovery;

await n.scan({
  rescanDiscovery:true,
  rescanMentions:true
});

const session = game.journal.contents.find(j =>
  j.name.includes("Broken Road to Hollowwatch")
);

n.candidatesForSource(session.uuid).map(c => ({
  text:c.text,
  type:c.classification.kind,
  detection:c.detection.score,
  disposition:c.disposition
}));
```

Expected:

- `Is Dev` absent
- `TrueBlood the` absent
- known aliases resolve/filter normally
- qa.13's eight verified new entities remain
