# v1.7.0-qa.35 — Campaign Tools Consolidation

**Baseline:** v1.7.0-qa.34  
**Foundry baseline:** V13.351

## Goal

Lock the Campaign Tools navigation model and reduce GM header clutter without changing any campaign authority or workflow semantics.

## Locked UX principle

> **Header = global utility actions. Campaign Tools = GM campaign workflows.**

The top-right Tome header should remain reserved for small global utilities such as Manual/Help and Campaign Settings.

GM workflow surfaces belong under the GM-only **Campaign Tools** workspace.

## Campaign Tools structure

qa.35 keeps:

- **Overview**
- **Memory**

and adds:

- **Assistant**

### Overview

Overview remains the quick GM campaign-intelligence landing page.

It includes entry points to:

- Campaign Memory
- Assistant Tools

### Memory

Memory retains the verified qa.34 Campaign Memory / Evidence Search surface.

No Campaign Memory authority or filtering semantics change in qa.35.

### Assistant

Assistant becomes the consolidated launcher for existing GM workflows:

- Next Session Dashboard
- Quick Capture
- Reveal Queue
- Post-Session Assistant
- GM Notebook

These tools keep their existing implementations and actions. qa.35 changes navigation/presentation, not their underlying data model.

## Header consolidation

Removed from the top-right GM header:

- Next Session Dashboard
- Quick Capture
- Reveal Queue
- GM Notebook

Retained in the header:

- Adventurer's Tome Manual / Help
- Campaign Settings

Dedicated GM workflow pages keep Campaign Tools highlighted and provide a Campaign Tools sub-navigation strip back to:

- Overview
- Memory
- Assistant

## Privacy

Campaign Tools remains GM-only.

Expected for a non-GM user:

- no Campaign Tools top-level navigation item
- no Assistant launcher
- no Campaign Memory counts/evidence
- no GM Dashboard / Quick Capture / Reveal Queue / Post-Session / Notebook surfaces

## Authority locks

qa.35 does not change:

- Foundry as backend/source of truth
- canonical UUID authority
- Campaign Link writes
- Mention evidence semantics
- ambiguous identity handling
- deterministic auto-link rules
- auto-create policy
- player-facing permission boundaries
