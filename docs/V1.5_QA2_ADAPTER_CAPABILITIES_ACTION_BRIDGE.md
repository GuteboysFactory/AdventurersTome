# Adventurer's Tome v1.5.0-qa.2 — Adapter Capabilities & Action Bridge

**Stable baseline:** v1.4.0  
**Previous adapter gate:** v1.5.0-qa.1 PASS  
**Verified Foundry baseline:** V13.351  
**Core policy:** system-agnostic; all adapter behavior is capability-driven.

## Goal

Move from a registry-only Adapter API to typed helper surfaces and a safe adapter-to-Tome action bridge.

This package must not hard-code Realm Guard, Genesys or any other game system into Tome Core.

## New public helper surface

Preferred access:

```js
const a = game.modules.get("adventurers-tome")?.api?.adapters;
```

New convenience methods:

- `displayFields(source, payload?)`
- `mapActor(source, payload?)`
- `mapItem(source, payload?)`
- `actions(source, payload?)`
- `invokeAction(actionKey, payload?)`

Existing generic `execute(capability, payload)` remains available.

## Capability result shapes

### displayFields

Adapter may return either an array or `{ fields: [...] }`.

Supported normalized fields:

```js
{
  id,
  label,
  value,
  icon,
  group,
  order,
  visibility
}
```

Tome adds `adapterId` to normalized output.

### actorMapping / itemMapping

Convenience helpers return the first successful compatible result:

```js
{
  adapterId,
  result
}
```

No mapping is authoritative until a later consumer explicitly uses it. qa.2 only defines the bridge.

### actions

Adapter `actions()` may return an array or `{ actions: [...] }`.

Action descriptor:

```js
{
  id,
  label,
  detail,
  icon,
  group,
  order,
  gmOnly,
  disabled,
  execute
}
```

Public discovery strips the executable function and returns a safe descriptor with:

```js
{
  key: "adapter-id:action-id",
  adapterId,
  id,
  label,
  detail,
  icon,
  group,
  order,
  gmOnly,
  disabled
}
```

Execution occurs only through:

```js
await api.adapters.invokeAction(actionKey, payload)
```

## GM Dock bridge

When a GM has a valid current context:

- compatible adapter actions are discovered asynchronously
- actions appear in the standalone Tome Dock
- actions appear under **System actions** in compatible hosted-provider menus
- execution always routes back through `api.adapters.invokeAction()`
- context is re-resolved at click time
- adapter actions never become permanent Tome data
- adapter actions disappear when the adapter unregisters or no longer matches
- no action is shown to non-GM users when `gmOnly !== false`

## QA B — displayFields normalization

Register:

```js
a.register({
  id:"qa-fields",
  apiVersion:1,
  capabilities:["displayFields"],
  matches:()=>true,
  displayFields:()=>[
    { id:"rank", label:"Rank", value:3, order:20 },
    { id:"role", label:"Role", value:"Scout", order:10 }
  ]
});
```

Then:

```js
await a.displayFields(canvas?.scene ?? null)
```

Expected:

- Role sorts before Rank
- both rows include `adapterId: "qa-fields"`
- no raw executable functions leak into the result

Cleanup:

```js
a.unregister("qa-fields")
```

## QA D — action discovery

Register:

```js
a.register({
  id:"qa-actions",
  apiVersion:1,
  priority:50,
  capabilities:["actions"],
  matches:()=>true,
  actions:()=>[
    {
      id:"ping",
      label:"QA Ping",
      detail:"Action bridge test",
      icon:"fa-bell",
      order:10,
      gmOnly:true,
      execute:()=>({ ok:true, marker:"qa-action-executed" })
    }
  ]
});
```

Then:

```js
const source = canvas?.scene ?? game.scenes?.active ?? null;
const actions = await a.actions(source, { surface:"qa" });
actions
```

Expected:

- exactly one QA action
- key = `qa-actions:ping`
- label = `QA Ping`
- descriptor contains no `execute` function

## QA E — action execution

await a.invokeAction("qa-actions:ping", {
