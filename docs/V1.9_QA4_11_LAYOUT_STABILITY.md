# QA.4.11 — Layout stability

The shared render/analysis chain could be requeued by window-state saves. Library enhancers also mounted at different delays, replaced shared filter bars, rewrote identical count text and competed for legacy Create controls. This made headers and controls move after the main view appeared, and could keep DOM observers busy while idle.

The main render now prepares synchronous layout components in manifest order, then applies registry permissions, before continuing its normal listeners and view-continuity restoration. Deferred hooks remain for actual later content changes; their stable passes preserve existing nodes. Dynamic editors and authoring save locks are retained.

Window writes are skipped when the serialized position/viewport is unchanged. The index ignores known presentation settings and registered client/user settings; world rules, document edits and GM matching decisions still queue work. Analysis is not disabled.

Verification includes the real library template, styles and enhancers in Edge; World, Sessions, Quests and Rules as GM and player; 243 source entries; first-frame geometry, subsequent main refresh, unrelated application hooks and idle DOM quiescence. Unit coverage checks unchanged/changed window positions and analysis invalidation. Source documents and TAF conversion rules are untouched.

Install the complete local module ZIP, restart Foundry and reload the client. No new campaign export or import is needed. Stable channel remains 1.8.0; nothing is published.
