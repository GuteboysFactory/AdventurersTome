# Adventurer's Tome v1.6.0-qa.13 — Contact Projection Privacy Hardening

**Baseline:** v1.6.0-qa.12  
**Verified Foundry baseline:** V13.351

## Trigger

Live player QA found a permission leak:

- an unreadable linked Actor was correctly absent from Character → Relations
- the same person still appeared through World → Contacts as an automatically generated semantic Contact projection
- the Contact card exposed the person's name plus relationship/status/location metadata

This violated the privacy lock that a derived projection may never be more visible than the evidence available to the current viewer supports.

## Fix

qa.13 keeps the existing identity/convergence model and tightens only the permission boundary.

### Managed Contact ownership

For generated semantic Contacts:

- semantic-only Contact → ownership mirrors the semantic source Actor
- canonical linked Actor Contact → ownership becomes the intersection of:
  - semantic source Actor ownership
  - canonical target Actor ownership
- automatically managed projections tighten in place on refresh
- a Contact whose GM manually diverged permissions remains explicitly GM-managed and is not silently overwritten

### Viewer-scoped Contact API

`contactProjections.list()` now returns only Contact Journals observable by the current user.

This prevents downstream consumers from enumerating unreadable projected Contacts.

### Contextual Relations

Character → Relations no longer synthesizes a semantic fallback row when the corresponding Contact projection is absent from the viewer-scoped list.

For a non-canonical semantic target, the current viewer must have a readable Contact projection before the relation renders.

## Hard lock

> The existence of a hidden person or relationship is protected information.

No unreadable generated Contact should leak through:

- World → Contacts
- Character → Relations
- Contact Projection API enumeration
- fallback semantic rendering

## QA protocol

Use a linked relationship Actor such as Baran Dev.

1. GM: linked target Actor is visible and generated Contact is present.
2. Set the player to **None** on the linked target Actor while keeping the source PC readable.
3. Refresh/rescan projection as normal and reload the player client.
4. Player → Character → Relations:
   - target does not appear
   - no hidden/locked placeholder appears
5. Player → World → Contacts:
   - target does not appear
   - name/status/location/relationship details do not appear
   - Contact count does not include the hidden projection
6. GM:
   - target still appears normally
7. Same-name identity regression:
   - two separate readable Gunther Contacts with different internal identities remain two cards
8. Console/reload regression:
   - no recurring errors
   - Discovery / Contact Projection audits remain healthy

## Expected result

If all checks pass:

- **Unreadable linked Actor projection = PASS**
- **Existence leak = PASS**
- **qa.13 privacy hotfix = PASS**

Then continue the remaining qa.12/qa.13 privacy gate.
