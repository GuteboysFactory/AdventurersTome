# Adventurer's Tome v1.6.0-qa.9 — Semantic Contacts World Projection

**Stable baseline:** v1.5.0  
**qa.7:** Universal Campaign Discovery PASS  
**qa.8:** Entity Reconciliation active; semantic-only model refined during live QA  
**Verified Foundry baseline:** V13.351

## Goal

Make system-owned relationship people visible inside Tome World even when no Foundry Actor exists.

This is the first visible World Auto-Build projection.

A Contact projection is Tome-owned presentation backed by a stable semantic source. It does not become the rules/data authority.

## Core model

Semantic entity states now distinguish:

- `resolved` — canonical Foundry document exists
- `compendium` — reference candidate
- `semantic-only` — legitimate campaign entity with no required Foundry document
- `unresolved-reference` — a referenced canonical UUID cannot currently resolve
- `unresolved` — incomplete/unknown semantic entity

Realm Guard Contacts without `actorUuid` are `semantic-only`, not missing NPCs.

## Adapter representation policy

Realm Guard M8 person discovery now declares:

    representation: {
      mode: "semantic-only" | "canonical-document",
      materialization: "optional",
      preferredDocumentType: "Actor"
    }

The generic Discovery layer consumes this metadata without knowing Realm Guard internals.

## Tome World Contacts

qa.9 adds a first-class World category:

`Contacts`

A GM discovery scan can automatically project relationship people into Tome World as Journal-backed Contact entries.

The Contact Journal stores Tome presentation only.

Its semantic source remains authoritative for:

- identity key
- source relationship
- role
- relationship status/origin
- profession
- culture
- location
- optional canonical Actor link

## Stable identity

Projection identity is the stable semantic key supplied through the generic discovery contract.

The Journal has:

`flags.adventurers-tome.semanticProjection.key`

This prevents duplicate Contact Journals across syncs.

## Linked Actor upgrade

If a semantic Contact later gains a canonical Actor UUID:

- the same Tome Contact Journal remains
- its semantic projection key remains unchanged
- its World profile gains Actor source linkage
- the Contact is not recreated as a second Tome entry

## Removal policy

Automatic projection never deletes a Contact Journal.

If its semantic source disappears, the projection is marked inactive.

Destructive cleanup requires a future explicit GM workflow.

## Permissions

New Contact Journals mirror the source Actor's Foundry ownership on creation.

Managed ownership follows the source only while the GM has not manually diverged the Contact's permissions.

A manual ownership change disables automatic permission management for that Contact.

## User edits

Projection sync preserves GM-authored profile content where possible.

Generated facts are tagged as semantic projection facts and may be refreshed.

Custom facts remain.

A GM-edited summary is not overwritten after it diverges from the last generated summary.
