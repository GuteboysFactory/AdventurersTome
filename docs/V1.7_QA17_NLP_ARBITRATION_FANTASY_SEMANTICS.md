# v1.7.0-qa.17 — NLP Arbitration & Fantasy Entity Semantics

**Baseline:** v1.7.0-qa.16  
**Foundry baseline:** V13.351  
**Scope:** harden NLP boundary authority for fantasy names and improve fantasy-domain Location / Faction classification.

## Live qa.16 evidence

The test sentence:

```text
Could Sister Vaela reach Frostgate Abbey before soldiers of the Silver Choir find her?
```

produced:

- Sister Vaela → Character/NPC ✅
- Silver Choir → detected but Unknown / Review ⚠️
- Frostgate Abbey → missing ❌

Targeted inspection showed the exact Frostgate failure:

```text
Frostgate Abbey
→ Compromise tagged Frostgate as Infinitive + Verb + PresentTense
→ NLP boundary layer trimmed "Frostgate"
→ remaining candidate "Abbey"
→ one-off singleton suppression
```

This proves generic Verb tagging is too weak to authorize destructive candidate trimming in fantasy prose.

## Arbitration fix

qa.17 changes NLP boundary policy:

- generic `Verb` is no longer a leading trim authority
- trimming remains allowed for stronger grammatical classes:
  - Auxiliary
  - Copula
  - Modal
  - Preposition
  - Determiner
  - QuestionWord
  - Conjunction

Expected:

```text
Is Dev
→ Dev

Could Sister Vaela
→ Sister Vaela

Frostgate Abbey
→ Frostgate Abbey
```

The NLP provider remains advisory. Tome remains final boundary / identity authority.

Faction context has been strengthened for constructions such as:

```text

`Choir` is also accepted as a faction-like semantic suffix in fantasy campaign prose.

```
