# v1.7.0-qa.6 — Campaign Authoring 2.0: Sessions + Quests

**Baseline:** v1.7.0-qa.5  
**Foundry baseline:** V13.351  
**Scope:** GM creation UX for Sessions and Quests

## Goal

Make normal campaign authoring task-first rather than Explorer-first.

GM should be able to create:

- a new Session without first selecting a folder
- a new Quest without first selecting a folder

Explorer remains available for advanced organization and management.

## Session creation flow

From the Sessions page:

```text
+ New Session
→ Session number (auto suggested)
→ Title
→ Date
→ Create Session
```

Tome then:

1. resolves or creates `Adventurer's Tome / Sessions`
2. creates a real Foundry JournalEntry
3. stores structured session metadata
4. creates a `Chronicle` JournalEntryPage
5. opens the new Session in Tome
6. attempts to focus the Chronicle inline editor

Canonical Chronicle storage remains:

```text
JournalEntry
└─ Chronicle JournalEntryPage
   └─ text.content
```

Session metadata:

```js
flags["adventurers-tome"].session = {
  number,
  date,
  status: "draft",
  schema: 1
}
```

Existing name-based Session parsing remains compatible.

## Quest creation flow

From the Quests page:

```text
+ New Quest
→ Title
→ Status
→ Create Quest
```

Tome then:

1. resolves or creates `Adventurer's Tome / Quests`
2. creates a real Foundry JournalEntry
3. preserves the existing top-level Quest status flag
4. stores structured Quest metadata
5. creates an `Overview` JournalEntryPage
6. opens the new Quest in Tome
7. attempts to focus the Overview inline editor

Canonical Quest storage remains:

```text
JournalEntry
└─ Overview JournalEntryPage
   └─ text.content
```

## Safety / compatibility

- creation is GM-only
- no Campaign Link persistence is introduced
- no Semantic Mention behavior changes
- no existing Sessions or Quests are migrated or rewritten
- Explorer creation remains available
- existing Journal-backed authoring/autosave remains the editor authority
- existing folder organization remains valid
