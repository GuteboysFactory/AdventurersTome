# 2.1 release validation

The production gate is `node tests/validate.mjs` followed by
`node tests/production-suite.mjs`. The latter runs both the current integrated
contracts and compatible inherited tests, using a production pass-through
boundary in legacy VM fixtures. It does not mock Foundry document writes in the
native upgrade test.

Seventeen earlier suites are retained as historical scanner coverage, listed
explicitly in production-suite.mjs. Their VM world does not load a browser HTML
parser, UDPipe or the integrated interpreter. Running those fixtures directly
against 2.1 produces missing-interpreter errors and obsolete presentation/
scheduling assertions. They are not reported as passing current release tests.
The exploratory all-legacy run found 175 failed cases before the fixture import
boundary was updated; this was not treated as a successful release run.

Current replacement coverage includes:

- decisionRows/discovery adapters, proof coordinates, action/target validation;
- source choices after merged name forms, source/global learning boundaries;
- creation concurrency, current source/target/owner validation and deletion guards;
- private source corrections, permissions and role loss, failed storage;
- scheduling, worker fingerprints, bounded render reads and view cache invalidation;
- folder ownership, repeated import/move, Original/Content/Custom privacy;
- one-time TestAI world/user/client settings transfer and simultaneous-module guard.

Browser and native tests additionally run real local Swedish/English models,
document-role parsing, multi-world synthetic/holdout reports and a copied
Foundry 13.351 / RealmGuard 1.13.1 world. The release record preserves the earlier
integrated candidate measurements, plus the production identity upgrade and
World 10/20/30 tests. Finite tests do not prove perfect language understanding.

Before public release, run the production gate, real-model browser check,
pagination check, native upgrade/reload check and package integrity checks.
No original user world is used for writes. No old erroneously created entries
are silently removed; the new deletion/correction UI remains outside this release.
