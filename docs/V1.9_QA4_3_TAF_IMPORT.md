# 1.9.0-qa.4.3 — TAF group conversion and story review

Local QA build. Stable channel stays 1.8.0; nothing is published. This is Adventurer's Tome migration work, not a Realm Guard system change.

## Import the existing TAF ZIP

1. Install the full module, including root module.json; restart the Foundry server and reload the browser with Ctrl+F5.
2. Gear → Import & Export → Import. Choose the existing migration ZIP and Preview Import. No replacement source export is required.
3. Open “TAF → Realm Guard: convert groups together”. Confirm Character/NPC for the source folder groups. PC/NPC folder names and the NPC compendium label supply proposals only. Existing authoritative source categories and individual choices take precedence. Choose a fallback only if appropriate for the remaining unclassified Actors.
4. Optionally confirm that Scene tokens should use converted base Actors. This archives source-specific token deltas rather than applying foreign rules to the destination. Token appearance and source data remain preserved.
5. Apply group conversion & Update Preview. This prepares copies without creating accounts or documents. Check the small remaining exception list; do not approve missing references blindly.
6. Map each source user to an existing account, “Create new Player account”, or Keep GM-only. The exporting GM maps to the importing GM. New accounts are created as Players only when Do Import is clicked and are identified for reuse on retry. No source passwords are copied and no existing account is promoted.
7. Do Import. Copies are staged GM-only; the current owner-aware restoration applies the confirmed account map. Compendium entries remain in a separate migrated compendium.
8. Optionally click “Find relationships in imported story”. Tome reuses its bilingual relationship extractor on the imported Actor biographies and reference Notes, together with unambiguous relationship-folder context. Results enter GM review as possible relationships. Sessions/Quests are queued through the existing Campaign Index. This action creates no NPCs and confirms no narrative claims. Unknown identities in Session/Quest analysis use the existing identity review workflow.

## Information retained

- TAF 3.1.0 and 3.2.0 are supported with schema checks. Other versions/types remain exceptions.
- Original biography HTML, portrait and token appearance are preserved. Obsolete TAF token bar paths are cleared.
- Compatible health, will, nature, resources and circles fields are copied by exact known labels. Out-of-range and duplicate core fields remain readable references, never clamped or silently interpreted.
- Other attributes, skills and traits remain readable in Actor Notes and complete in the source archive. They are not automatically declared equivalent to Realm Guard mechanics.
- Freeform Sheets inventory text and additional system.attr fields remain readable. Gear retains description and quantity plus source weight/equipped/group reference text. Macro triggers/effects are archived, never executed.
- Standalone attribute/base documents become explicitly labeled zero-quantity reference Items, retaining identity for links. These are not declared active equipment or converted rules.
- Foreign automation flags stay inactive. References found only inside discarded automation do not block copying; references in the transferred Freeform text still require valid targets.
- GM Notes module text is restored to the importing GM's contextual private Vault before player visibility is restored. It is removed from document source archives that players might later access. Original module data also remains in the GM-only migration receipt and source ZIP. Private Vault and player Chronicles are never used as story-analysis text.
- Relationship proposals preserve source context, canonical identities and review history. Repeating analysis retires changed claims without duplicating evidence; ambiguity does not create a namesake or guessed endpoint.

## Verification and limits

The supplied TAF 3.1.0 package contains 1,031 documents including 186 NPC-compendium Actors. The local import simulation, after confirming group roles and the base-Actor Scene policy, copies 1,023 documents with 8 exceptions and no unresolved references among the copied documents. The remaining exceptions are two Actors with source text links to absent documents and six Scenes with an absent or withheld Actor dependency. Original package data stays unchanged; repeating the import creates zero duplicates. One GM Notes record is restored privately. These counts depend on the choices above; they are not a claim that every imported rule is mechanically equivalent.

The live Foundry import and the GM's confirmation of folder-based Character/NPC proposals still need testing. Missing source documents are not invented. Existing rollback/resume safeguards remain; this build does not overwrite the source world or publish a stable release.
