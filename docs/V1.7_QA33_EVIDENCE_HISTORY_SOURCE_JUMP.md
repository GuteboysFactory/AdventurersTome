# v1.7.0-qa.33 — Evidence History & Source Jump

**Baseline:** v1.7.0-qa.32  
**Foundry baseline:** V13.351

## Goal

Build the first practical history/navigation layer on top of Campaign Mention Evidence.

qa.33 keeps the existing authority model:

- **Campaign Links** = canonical graph relationships
- **Mentioned In** = persistent provenance/history
- **Tome noticed / Ambiguous** = unresolved advisory evidence

No new auto-create or ambiguity override is introduced.

## World profile evidence history

World profiles now present Mention evidence in two levels.

### Summary

The profile shows:

- First Mention
- Last Mention
- Total Evidence
- active/historical counts

### Recent Evidence

The five newest active mentions are shown first.

This keeps long-running campaign profiles readable without discarding old evidence.

### Older / Historical Evidence

Older active evidence and historical evidence are moved behind an expandable archive.

Historical Mention records remain visible and are not silently deleted.

## Source navigation

Every Mention row now has two distinct navigation paths:

1. click the Session / Quest source name to navigate to that source inside Tome
2. click **Source** to open the authoritative Foundry source

If a JournalEntryPage UUID is available, Source opens that exact Foundry Journal page.

If page-level provenance is unavailable, Source falls back to the parent Journal.

qa.33 therefore guarantees source-document/page provenance navigation.

Exact scroll-to-character/text-fragment positioning is not claimed yet; that remains a later refinement.

## Evidence API additions

```js
const api = game.modules.get("adventurers-tome").api.campaignMentionEvidence;
```

Query sorting now supports:

```js
api.query({ targetUuid, sort:"newest" });
api.query({ targetUuid, sort:"oldest" });
api.query({ targetUuid, sort:"first-seen" });
api.query({ targetUuid, sort:"last-seen" });
```

Target summary:

```js
api.summaryForTarget(targetUuid, { recentLimit:5 });
```

Recent target evidence:

```js
api.recentForTarget(targetUuid, 5);
```

These are foundations for the later Campaign Memory search/filter UI.

## QA fixture

Use the verified qa.32 world.

Pale Wardens should already have:

- canonical Session 1 Campaign Link
- one active Mention
- Linked + Mentioned status

### A — Summary

Open World -> Pale Wardens.

Expected:

```text
Mentioned In
First Mention: Session 1
Last Mention: Session 1
Total Evidence: 1
```

### B — Source jump

Click **Source** on the Mention row.

Expected:

- Foundry Journal sheet opens
- the Chronicle page for Session 1 opens when its Page UUID is present

### C — Tome navigation

Click the Session name in the Mention row.

Expected:

- Tome navigates to Session 1

### D — Recent / archive behavior

Create enough additional mentions to exceed five active records.

Expected:

- newest five active mentions appear under Recent Evidence
- remaining records appear under expandable older/historical evidence
- no evidence is lost

### E — Historical evidence

Remove a previously detected mention and allow evidence sync.

Expected:

- record remains historical
- it is not shown as current Recent Evidence
- it remains available in the archive

## PASS gate

qa.33 passes when:

1. First/Last/Total summary remains correct
2. newest active evidence is prioritized
3. older/historical evidence remains accessible
4. Tome source navigation still works
5. Source opens the authoritative Foundry Journal/Page
6. reload preserves evidence history
7. Link/Mention/Ambiguous semantics remain unchanged
